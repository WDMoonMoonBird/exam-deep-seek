## 2 中间件规则（★秒级边界与理由）

`server/src/middleware/auth.js`（在既有 `auth` 内、`req.user` 之前）：

1. `user.passwordChangedAt` 为 NULL ⇒ **完全不判定**（历史行/从未改密 ⇒ 行为与本批之前一致，零回归）。
2. 否则 `changedSec = floor(password_changed_at / 1000)`、`issuedSec = payload.iat`；
   **判定 = 严格小于**（`issuedSec < changedSec` ⇒ 401 + **code 1002**，文案「登录状态已失效（密码已变更），请重新登录」）。
3. ★为什么用"秒 + 严格小于"：`iat` 是 JWT 标准声明、单位**秒**且**向下取整** ⇒ 改密同一秒内签发的令牌与库值秒分量相等；
   若改成 `<=`，则「改密成功后立刻重新登录」会得到一个**当场失效**的令牌 ⇒ 用户被锁在登录页（假 401）。
   代价是**最多 1 秒**窗口内同秒签发的旧令牌仍可用——秒级精度的固有下界，窗口有界（实测：w67-1 需跨秒才能观测到旧令牌失效）。
4. 无 `iat` 的令牌无法判定 ⇒ **保守放行**（不误杀）；已用 w72-5 固化该行为（并记录 `jsonwebtoken` 的坑：
   签名时传 `{noTimestamp:true}` 会 **delete payload.iat** ⇒ 令牌根本没有 iat，正是我们不放行误杀的边界）。
