### 1.2 可直接粘贴的安全测试命令
```bash
cd server
# 0) 派生测试库 URL（不回显密码）+ 硬断言：库名必须是 exam_system_test
export DATABASE_URL="$(grep -m1 '^DATABASE_URL=' .env | cut -d= -f2- | sed 's|/exam_system|/exam_system_test|')"
node -e 'const u=new URL(process.env.DATABASE_URL); if(u.pathname!=="/exam_system_test"){console.error("⛔ REFUSE "+u.pathname);process.exit(1)} console.log("db_ok="+u.pathname)'

# 1) 静态层检查（不触库）
node scripts/check-layers.mjs

# 2) 单元 + 契约（注意：setupFiles 会 seed，因此**仍需**指向测试库）
npx jest --config test/jest.config.js --runInBand --forceExit test/unit test/contract

# 3) 集成（34 个文件；写入仅发生在测试库）
npx jest --config test/jest.config.js --runInBand --forceExit test/integration
```
- **不要**直接 `npm test`：它不注入 `DATABASE_URL`，`setup.js:4` 的 dotenv 会读到 `server/.env` 的生产库名 `exam_system` ⇒ 护栏 `setup.js:52-70` 直接 `exit(1)`（正确的 fail-closed，但会让人误以为测试坏了）。
- 需要跑 `npm test` 同款全量时：`DATABASE_URL="…/exam_system_test" npm test`。

### 1.3 只读旁证（证明测试没写生产库）
```sql
-- 跑测试前/后各执行一次，逐位比对（只读）
SELECT 'users' k, COUNT(*) c FROM exam_system.users
UNION ALL SELECT 'submissions', COUNT(*) FROM exam_system.submissions
UNION ALL SELECT 'questions', COUNT(*) FROM exam_system.questions
UNION ALL SELECT 'assignments', COUNT(*) FROM exam_system.assignments
UNION ALL SELECT 'assignment_questions', COUNT(*) FROM exam_system.assignment_questions
UNION ALL SELECT 'system_configs', COUNT(*) FROM exam_system.system_configs;
SELECT MAX(id) max_id, MAX(submitted_at) max_submitted FROM exam_system.submissions;
SELECT COUNT(*) fresh FROM exam_system.submissions WHERE created_at >= NOW() - INTERVAL 10 MINUTE; -- 若列不存在则跳过
SELECT COUNT(*) FROM information_schema.columns WHERE table_schema='exam_system' AND table_name IN ('assignment_questions','submissions');
```
- **判定**：六个计数 + `max_id/max_submitted` + 列数必须**逐位相同**；任一变化 ⇒ 立刻停止 R2 并人工核查。

### 1.4 「不得写生产库 exam_system」的可执行约束（5 条）
1. **前置断言**：任何 jest/DB 脚本前必须通过 §1.2 第 0 步（库名 === `exam_system_test`）；`setup.js:35` 白名单与 `setup.js:52-70` 护栏**不得修改/绕过**（B 的改动范围里不含 `server/test/**`）。
2. **禁跑清单（无护栏、直连 HTTP）**：`server/test/submit-500-v2.mjs`、`server/test/setup-500.mjs`、`server/test/stress-64-concurrency.mjs`——它们 `POST http://localhost:3000/api`，而当前 **:3000 有活服务**（PID 81402，连生产库）⇒ 等于通过 API 写生产数据。
3. **禁跑 Prisma 执行类命令**：`prisma migrate dev`（无 `--create-only` 时会执行 SQL）、`prisma migrate reset`（**清库**）、`prisma db push`、`prisma migrate deploy`（生产执行由用户/运维按 §2 做）；允许 `--create-only`/`migrate diff --script`/只读 `status`。
4. **禁跑 e2e**：`npm run test:e2e` 需要独占 :3000 与 :5173，二者均被用户实例占用（PID 81402/81403），且 `reuseExistingServer:false` ⇒ 必然失败/冲突；e2e 不进 R2 门禁。
5. **违规判定**：§1.3 指纹变化 或 `exam_system` 出现新表/新列 ⇒ 视为事故：停止提交、保留现场、由人工作业回滚（本流水线不写生产库）。
