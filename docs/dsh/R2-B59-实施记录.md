# R2-B59 实施记录：入口版本探测（有新版本 ⇒ 提示刷新）+ 当前版本可见

> 摘要（≤8 行）：① **方案**：版本指纹 = **入口 chunk 的构建哈希**。运行中版本取自当前文档 `script[type=module][src]` 的文件名哈希（浏览器实际加载的那份代码，可自证）；线上版本 = 拉 `index.html`（`cache: no-store`）解析同一个 script 标签 ⇒ 不同即「服务端已发新版」。
> ② 为什么不用 version.json / 构建期注入哈希：少一个部署面（不必保证新文件不被缓存/不被发布脚本漏传，而 `index.html` 天然要求不缓存）；哈希在产物生成后才确定（自引用循环），运行时可从自身 script 标签直接读到。构建期仍注入**时间戳** `__BUILD_VERSION__`（vite `define`）用于展示。
> ③ 提示**非打断式**：`message.info({ duration: 0 })` + 文案「有新版本，点击刷新」+ 点击 ⇒ `window.location.reload()`（不弹窗、不阻塞、可关闭）；在 **mount 之后**安装 ⇒ 渲染永不被网络探测阻塞。
> ④ 健壮性：请求失败/离线/HTTP 非 2xx/HTML 解析不出哈希 ⇒ **一律静默忽略**（`status: ignored`，不抛不提示）；**同一（线上）版本只提示一次**（`version-notified:<hash>`）；**去抖 60s**、**轮询 5 分钟**、切前台/恢复网络各补一次（参数见 `composables/appVersion.js`）。
> ⑤ 追加 A：`ProfileCard` 资料区新增**版本短码**（小字，`v-<yyyyMMddHHmm>-<入口哈希前 7 位>`，`pc-ver` 样式）⇒ **三端「我的信息」一并可见**；⑥ 追加 B：`client/tmp-b57-patch.mjs` 已不存在（t45 已删，本批复核为干净）。
> ⑦ 测试：`verify-frontend` 新增 ⑫a–⑫e（结构 + **可执行四态**）⇒ **checks=44 failed=0 rc=0**；变异三条各自 rc=1 且还原逐字节一致；⑧ 回归：jest w52+w61+w62+w67 全绿、check-layers 141 文件 0 违规、指纹按环境 29/28/30。

## 1. 方案对比与理由（为什么这样探测）
| 方案 | 取舍 |
|---|---|
| **入口哈希对比（本批采用）** | 探测的是"服务端真的换了入口代码"，与 B52 的 chunk 自愈、B52 记录的「保留上一版 assets」运维建议天然配套；零新依赖、零部署面 |
| 另设 `version.json` | 需保证该文件不被缓存、不被发布脚本漏传（多一个部署面）；收益与入口哈希重复 |
| 构建期把最终哈希注入 JS | 哈希在产物生成后才确定（自引用循环），需要"先构建再回写"的两段式插件；运行时本可直接读自身 script 标签 |
| 轮询 `dist/index.html` 全文 diff | 变更噪音大（注释/空白），入口哈希更精确、更便宜 |

## 2. 参数与状态机（`client/src/composables/appVersion.js`）
- `DEFAULT_CHECK_INTERVAL_MS = 300000`（5 分钟轮询）、`MIN_CHECK_GAP_MS = 60000`（60s 去抖）、`THROTTLE_KEY = version-check-at`、`version-notified:<线上哈希>`（同一版本只提示一次）。
- `checkForNewVersion({ fetchImpl, doc, storage, notify, url, now, minGapMs })` ⇒ `same` / `newer(notified)` / `newer(already_notified)` / `throttled` / `ignored(http|network|unparsable|no_fetch)`；**从不抛**（外部依赖全部可注入 ⇒ node 下可测）。
- `installVersionWatcher({ ... })`：首次 + `setInterval(5min)` + `visibilitychange`（转前台）+ `online`（恢复网络）⇒ 返回 `{ stop() }`；全程 try/catch。
- `appVersionLabel(doc = document)`：`v-<yyyyMMddHHmm>-<入口哈希前 7 位>`；非 Vite 环境（node）安全回落 `dev`（`typeof __BUILD_VERSION__ !== 'undefined'` 守卫）。

## 3. 接线
- `client/vite.config.js`：`define: { __BUILD_VERSION__: JSON.stringify(BUILD_STAMP) }`，`BUILD_STAMP = 'v-' + yyyyMMddHHmm`（本地时间，构建期计算）。
- `client/src/main.js`：`app.mount('#app')` **之后** `installVersionWatcher({ notify })`；`notify` 内 `message.info({ content: h('span', ['有新版本，', h('a', { onClick: () => window.location.reload() }, '点击刷新')]), duration: 0 })`（整段 try/catch）。
- `client/src/components/ProfileCard.vue`：资料区 `<div class="pc-f pc-ver"><dt>版本</dt><dd>{{ versionLabel }}</dd></div>`（`versionLabel = appVersionLabel()`；样式 `.pc-ver dd .pc-v { font-size: var(--fs-caption); color: var(--text-tertiary); }`）⇒ 三端「我的信息」共用 ⇒ 一并可见。

## 4. 测试与防呆（verify-frontend ⑫a–⑫e）
- ⑫a：`vite.config.js` 有 `define … __BUILD_VERSION__: JSON.stringify(BUILD_STAMP)` 且 `BUILD_STAMP` 由日期各部分拼出（含 `getMonth()+1`/`getMinutes()`）。
- ⑫b：`main.js` 安装点**晚于** `app.mount`；提示为 `message.info({` + 「点击刷新」+ `window.location.reload()` + `duration: 0`；提示处有 catch（失败静默）。
- ⑫c：`ProfileCard.vue` 含 `<dt>版本</dt>` + `{{ versionLabel }}` + `appVersionLabel()` + `pc-ver`（三端共用 ⇒ 三端可见；三端 Layout 使用 `<ProfileCard>` 由 ⑩a 另测）。
- ⑫d：探测模块**零 import**（未引入新依赖）且导出所需 API。
- ⑫e **可执行四态**（注入 fetch/doc/storage/notify 桩件、不发真实网络）：相同 ⇒ `same` 不提示；1s 内二次 ⇒ `throttled`（**去抖证据**）；不同 ⇒ `newer` 且 `notified=true`；同一线上版本再检测 ⇒ `newer` + `already_notified`（**只提示一次**）；坏 HTML / 离线 / HTTP 500 ⇒ 三项全部 `ignored`；全程 `notify` 只被调用 **1** 次。
- 变异对照（逐字节还原）：M1 去掉新版本提示 ⇒ ⑫e rc=1；M2 去掉 ProfileCard 的版本行 ⇒ ⑫c rc=1；M3 去掉 vite 的 `define` ⇒ ⑫a rc=1；三文件还原后 sha256 逐字节一致。
