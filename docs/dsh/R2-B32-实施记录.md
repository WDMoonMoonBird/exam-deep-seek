## 摘要（≤8 行）
1. **云上原始证据（队长提供）**：① summary 错 —— `{"n":10,"measurable":0,"unmeasurable":0,"submissions":[{"slug":"coverage-s01","parseError":true},{"slug":"matrix-s01",…}]}`（读的 `out/measure/*.json` 是 coverage/matrix 干扰产物）；② 剪枝回退 —— job 5 `RUN_ARCHIVED … pruned_run_root=no`（job 3/4 均 yes）且归档日志 `"jobId":null`（job 4 为 `"jobId":4`）。
2. **根因①**：`buildEvidenceSummary()` 读 `out/measure/*.json`，并且那段代码里 `it` 未定义（潜在 ReferenceError 被 catch 吞掉）⇒ 每个文件都落成 `{parseError:true}` 占位；逐份结果实际在 `out/grading-result/<slug>.json`（索引 `out/grading-results.json`）。
3. **根因②**：`finalizeRunRoot()` 调用 `archiveRun({ jobId: null, … })` ⇒ 归档日志 `jobId=null`，且剪枝护栏 `isPrunableRunRoot(runRoot, jobId)` 期待 `r2b4-job-<jobId>-*` 形状 ⇒ 传 null 时**形状失配 ⇒ 成功也不剪枝**。
4. **修法①**：summary 改为「逐份结果」口径 —— 主源 `out/grading-result/<slug>.json` → 索引 `out/grading-results.json` → 交叉 `measurable.json` → 旧布局兜底 `out/results/*.json`（仅当主源无条目，且必须 `looksLikeResult`）；**不再产出 parseError 占位**（无法解析/非结果文件只计入 `skipped_artifacts`）；条目含 slug/student/score/hits/measurable/failed/reason；汇总含 `n/measurable/unmeasurable/failed/skipped_artifacts`，schema 升为 `evidence-summary/2`。
5. **修法②**：`finalizeRunRoot({ …, jobId })` 透传 jobId ⇒ `archiveRun` 用它命名归档目录与剪枝判据；worker 调用处传 `jobId: res.jobId`；`RUN_ARCHIVED` 行新增 `jobId=<值>`，**不剪枝时必打 `prune_skipped=<原因>`**（`not_success` / `shape_guard(jobId=…)` / `rm_residual` / `rm_failed:…`），不再静默。
6. **★本机对拍（复刻云上 job 5 的 out/ 形态：4 组 coverage+s0N / matrix+s0N 干扰文件 + 1 个坏 JSON + grading-result 4 份 + grading-results.json 索引 + measurable.json）**：

   非 job 形状的 run-root ⇒ `{"pruned":false,"reason":"shape_guard(jobId=88)"}`（明确原因，不静默）
