> 旧自然语言评语/其它 JSON/坏 JSON/空 ⇒ **原样或安全降级**。⑤ 学生端未改（一行开关可开，见 §6）。⑥ 变异对照 M1–M3 全部「改回缺陷即失败」，还原逐字节一致。

## 1. 根因与证据链
- 装置侧：`grading-results.json` / `out/grading-result/<slug>.json` 的 item 形如
  `{"id":"P01","title":"web.xml 使用 jakartaee 命名空间…","max_score":1,"score":1,"status":"hit","reason":"P01(count_regex): … | 证据: src/main/webapp/WEB-INF/web.xml"}`。
- 平台侧：`dshCheckerConsumer.listMeasureResults()` 只列 `out/measure` 与 `out/results`（★`out/measure` 是**量尺投影**，items 只有分数）；
  `buildWriteback()` 从该 result 取 items ⇒ `comment` 取不到 reason ⇒ 落库为空串（与归档 `dshRunArchiver` 早就写明「`out/measure` 是干扰产物、结果源应由 grading-result 负责」一致）。

## 2. 写入侧增强（`server/src/services/dshCheckerConsumer.js`；不动判定/分数）
- 新增 `loadGradingResultIndex(runRoot)`：按优先级读 ①`out/grading-result/<slug>.json` ②`out/grading-result.json`（单份契约：items 数组 / `{results|submissions:[…]}`）
  ③`out/results/<slug>*.json`（兼容）⇒ `{bySlug, fallback, sources}`；坏文件/坏 JSON 一律跳过（不影响分数路径）。新增 `normalizeDetailDoc()`。
- `listMeasureResults()` 给每条结果挂 `grading_detail`（按 `result.submission.id` 命中，单份契约的 items 数组作兜底）；**分数与"是否写分"的来源不变**（仍是 measure/旧布局 + `decideScoreWrite()`）。
- `buildWriteback()`：`breakdown[]` 逐项按 **item id** 合并依据；`score`/`maxScore` **只取原来源 item**；新增键：
  `title`（≤80，缺则空串）、`status`（hit/miss…，缺则 null）、`comment`（`rich.comment || rich.reason || 原 item.comment || 原 item.reason`，**上限 300**）、
  并保留 `item/score/maxScore/kind`；`aiFeedback` 顶层新增 `detail_source`/`detail_items`（依据来源留痕），既有键（raw_score/score_int/score_int 口径/checker_id/canonical_sha256/max_score/aggregate）**原样保留**。

## 3. 回填脚本（`server/scripts/backfill-ai-feedback.mjs`）
```bash
# dry-run（默认，不写库）——本地/生产演练都可先跑这条
node scripts/backfill-ai-feedback.mjs --from /srv/grader/runs/21 --assignment <id> --map <slug→submissionId.json>
# 生产（**由队长授权后执行**；只更新 ai_feedback，脚本前后各读一次分数并断言零变化）
node scripts/backfill-ai-feedback.mjs --job 21 --runs-root /srv/grader/runs --assignment <id> --apply
```
- 源兼容：`out/grading-result/<slug>.json`（优先）/ `grading-results.json` / `grading-result.json` / `out/results/<slug>*.json`。
- 映射：显式 `--map`（slug→submissionId）**或** 学生姓名/账号（`users.realName`/`username`，二者都试）；未命中 ⇒ `UNMAPPED` 行，绝不猜。
- 安全：`--apply` 才写；**只 UPDATE `ai_feedback` 一列**；源总分与行 `ai_score` 不一致的行**默认跳过**（`--force-score-mismatch` 可强制）；结束断言 `SCORE_UNCHANGED=yes`（否则退出码 3）+ `IDEMPOTENT=yes`。
- 本地演练（测试库）：dry-run 零写入 → `--apply` 后 `breakdown[].comment` 含「证据: src/a.java」、title/status 落地、**ai_score/final_score 逐行不变** → 再跑一次 `changed=0` 且内容字节一致（见 §5 W61-4）。

## 4. 教师侧展示（`client/src/composables/review/parseCheckerFeedback.js` + `client/src/views/teacher/ReviewDetail.vue`）
- 解析器为**纯函数 + 模块级缓存**（复审页面禁止响应式原语 ⇒ 视图里用 `fbOf(sqId)` 直接调用，不引入 computed），三种结果：
  `{kind:'checker', rows, hits, total, scoreText, maxText, hasEvidence}` / `{kind:'text', text}` / `{kind:'empty'}`。
- 判定形状：`source === 'dsh-checker'` 且 `breakdown` 是数组；`ok` 先看 `status`（hit/pass/ok/true/met），否则按 `score >= maxScore` 推断。
- 渲染：一行汇总「AI 评分依据：本次 93 / 100 分 ｜ 40 项中 38 项达标」+ 分项行「✅/❌ · 分项名 · 得分/满分 · 判据与证据（含「证据:」时高亮）」；
  **旧自然语言评语/其它 JSON/坏 JSON/空** ⇒ 原样显示或「暂无评语」（不报错、不改写）。
