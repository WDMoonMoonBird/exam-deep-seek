# R2-B22 实施记录（装置模型端点必须是 Messages API 根 —— 修生产造尺必然 404）

## 摘要（≤10 行）
1. **现场**（队长实测，有效平台 key）：`build-and-measure` 造尺会话 1 秒即失败 —— `dsh: HTTP_404: DeepSeek Messages request failed (404)` ⇒ `ASSIGNMENT_FAIL_REASON=build-session-nonzero(rc=1,child=1)`。
2. **端点探测**（同一把 key）：`https://api.deepseek.com/chat/completions` ⇒ 200（OpenAI 风格）；`https://api.deepseek.com/anthropic/v1/messages` ⇒ **200**（装置要的 Messages 风格）；`https://api.deepseek.com/v1/messages` ⇒ **404**（装置当时拼出的路径）。
3. **根因**：装置（DSH harness）走 **Anthropic 风格 Messages API**，请求路径 = `profile.baseURL` + `/v1/messages`；而 t48 的 profile 补丁把**平台的 `deepseek_base_url`（OpenAI 风格口径 `https://api.deepseek.com`）**原样写入 ⇒ 拼出 `/v1/messages` ⇒ 404。影响面：**造尺（唯一用 LLM 的一步）在生产配置下必然失败**；此前成功 job 都走「复用」（零 LLM），故未暴露。
4. **★修法（`scripts/dsh-grader/lib.sh` 最小改动）**：新增 `messages_api_root()`，profile 的 `baseURL` 按优先级取：①`DSH_GRADER_BASE_URL`（显式覆盖）②由 `DEEPSEEK_BASE_URL` 派生（含 `/anthropic` ⇒ 原样；host = `api.deepseek.com` ⇒ 归一为 `<scheme>://<host>[:port]/anthropic`；**其他 host ⇒ 原样不动**，不猜）③都没有 ⇒ 不写 baseURL（保持既有默认，不引入新默认值）。
5. **★可观测**：`scaffold_home` 打印 `MODEL_ENDPOINT=<scheme://host/path> model=<模型>`（新增 `endpoint_label()` 只保留 scheme+host+path，剥掉 query/fragment/`user:pass@`；**绝不含 key**）；无配置时打印 `MODEL_ENDPOINT=(device-default) model=…`。
6. **不变式**：`scripts/dsh-grader/**` 合并指纹**因本轮有意变更**（仅 `lib.sh`：新增两个函数 + profile 补丁段改为派生逻辑，见 §3 逐条）；三条装置不变式（`classify_changes.py`、`scripts/dsh-checker/**`、fixture canonical）**未变**（这些文件未被触碰，selftest 全绿）。
7. **测试**：新增 `server/test/unit/w50-device-model-endpoint.test.js`（5 例）：组合矩阵逐条断言 / ★profile 落盘守卫（`DEEPSEEK_BASE_URL=https://api.deepseek.com` ⇒ 写入必须 `…/anthropic`）/ 未配置 ⇒ 不写 baseURL 且打 device-default / 显式覆盖优先 / `bash -n` + 无 key 泄漏。
8. **文档**：`docs/dsh/deploy/README.md` §7 新增第 6 条（端点必须是 Messages API 根 + 两段 curl 验活 + 平台 `deepseek_base_url` **不可直接喂装置**）；`docs/dsh/deploy/上云首次部署清单.md` §0 表新增「★模型端点」行 + 新 §0.1「模型端点验活（2 分钟）」。
9. **verify（串行，selftest 独占先行）**：`bash -n` ✓；selftest rc=0/全绿；check-layers 0 违规；unit 57 套件/731 例；contract 3/50；生产库指纹 before/after **逐位相同**。

## 4 未验证项（单列）
1. **真实模型调用未由我执行**（硬性约束：不发起真实调用）：本轮的证据是「派生逻辑 + 落盘 profile 内容 + 端点可观测」；`404 → 200` 的最终确认由队长用真实 key 跑一次 `build-and-measure`（记录 §2 的端点探测已由队长实测给出）。
2. **其他自建网关的 Messages 根**未实测：非 `api.deepseek.com` 的 host 一律原样透传（不猜）⇒ 若某网关的 Messages 根不是它给的 base（例如同样需要 `/anthropic`），需用 `DSH_GRADER_BASE_URL` 显式覆盖（已文档化）。
3. **`api.deepseek.com` 带自定义端口**未覆盖：我的归一只保留 `<scheme>://<host>[:port]/anthropic`（正则按首个 `/` 切分）⇒ 形如 `https://api.deepseek.com:8443/v1` 会得到 `https://api.deepseek.com:8443/anthropic`（合理，但未实测）。
4. **`/v1` 归一的取舍**：`https://api.deepseek.com/v1` ⇒ `/anthropic`（**丢弃** `/v1`）——依据「DeepSeek 公有云的 Messages 根是 `/anthropic`」；若未来出现需要保留 path 的形态，应改用 `DSH_GRADER_BASE_URL` 覆盖。
