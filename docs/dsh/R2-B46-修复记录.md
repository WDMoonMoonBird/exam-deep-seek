## 1. 现象与根因（组件 ↔ 路由错配）
| 项 | 值 |
|---|---|
| 用户路径 | 班级复审 → 点学生 ⇒ 路由 `review/project/:submissionId` |
| 实际组件 | `src/views/teacher/ProjectReviewNew.vue`（含「评分面板/查看提示词/重新评分/引用到教师评语/最终分数/待评分」等特征串） |
| B43 改的组件 | `src/views/teacher/ReviewDetail.vue`（路由 `review/:id`，另一条入口） |
| 结论 | 功能本身没问题，**装配错页面** ⇒ 用户看不到总评；两条入口必须一致 |

## 2. 移植点（ProjectReviewNew.vue）
- 数据来源：`getProjectReview` 返回的 `aiResult` = `JSON.parse(submissions.ai_feedback)`（服务端 `projectReviewController.js:130-134`）⇒ `aiResult.summary` 直接可读，**无需改后端**。
- 新增：`import { parseCheckerFeedback } from '../../composables/review/parseCheckerFeedback.js'`；
  `const fbView = computed(() => aiResult.value ? parseCheckerFeedback(JSON.stringify(aiResult.value)) : null)`；
  `const hasSummary = computed(() => !!(fbView.value?.kind === 'checker' && fbView.value.summary))`。
- 模板：`v-if="hasSummary"` 的 **总评卡**（`AI 总评` 标签 + `white-space:pre-wrap` 正文 + `truncated` 时「可重新生成」提示）与 **一行依据**（`fbView.basisText`）。
- 折叠：`:defaultActiveKey="hasSummary ? [] : undefined"` —— 有总评时**默认折叠**（点开才看 N 项）；无总评时不传该 prop（与改动前一致）。
- 样式：新增 `.ai-sum-card/.ai-sum-tag/.ai-sum-text/.ai-sum-note/.ai-sum-basis`（沿用 `--border-default/--bg-sunken/--fs-caption` 等既有令牌，与通用复审页视觉一致）。

## 3. 路由级防呆（verify-frontend ⑤）
- **不硬编码组件路径**：从 `src/router/index.js` 取 `path: '<route>'` 片段并在其后 600 字符内解析 `component: () => import('…')` ⇒ 得到真实组件文件；路由改名/换组件同样被覆盖。
- 判定 = 「渲染出 AI 总评」`/>\s*AI 总评\s*</` **且** 「消费同一解析器」`parseCheckerFeedback` ⇒ 判定的是**功能在**，而不是"字样出现在注释里"。
- 失败信息直接指向文件与原因，例如：`FAIL ⑤a … :: src/views/teacher/ProjectReviewNew.vue 未见渲染的「AI 总评」 ⇒ 教师打开该页看不到总评`。
