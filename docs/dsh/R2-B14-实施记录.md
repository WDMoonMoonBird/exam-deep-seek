# R2-B14 实施记录（作业锚点：入库持久化 + 复用回填 + 消费侧 materials-manifest 兜底）

## 摘要（≤10 行）
1. **现场**：复用（measure-only-reuse）run-root 里没有 `out/assignment/assignment-manifest.json` ⇒ 装置读不到（`ASSIGNMENT_FROZEN_SHA256=na`），消费侧 `map_reason=manifest_missing` ⇒ `written=0`、62 份全 `needs_rerun`（fail-closed，311 分数逐位未变）。
2. **①入库持久化**：新增表 `grading_assignment_anchors`（每 (assignment_id, checker_id) 一行，含 `frozen_sha256` / `materials_manifest_digest` / `n_submissions` / `submissions_json` / 原始 `anchor_json`）；迁移 `20261012040000_r2b14_assignment_anchors`（含 `rollback.sql`），**仅在测试库应用**。
3. **②复用回填**：worker 以 `--reuse-checker`（查询到 ready 尺子）拉起装置前，把持久化锚点写回 `<run-root>/out/assignment/assignment-manifest.json` ⇒ 装置 `frozen_intact` 预检与 `ASSIGNMENT_FROZEN_SHA256` 恢复；**无锚点（历史数据）⇒ 打 `ANCHOR_MATERIALIZED=no reason=no_persisted_anchor` 并继续**（不静默装成功）。
4. **③消费侧兜底**：`deriveSlugMapFromRunRoot` 在缺锚点时回退读装置**两种模式都会写**的 `materials/materials-manifest.json`（其 `submissions[].id` 同为「源目录名/学生名」），沿用既有 `matchSlugToSubmissions`（realName/username 对齐），`map_reason=materials_manifest`；两者皆缺 ⇒ 仍 `manifest_missing`（fail-closed，不猜）。
5. **入库两条路径都持久化**：r2b7（造尺/复用入库）与 worker 消费成功后各打 `ANCHOR_PERSISTED=yes/no`；幂等（`ON DUPLICATE KEY UPDATE`）。
6. **实测（w37，3 例）**：持久化字段齐全（`frozen_sha256` 与装置口径一致、`materials_manifest_digest`、`n_submissions`、`submissions`）；空 run-root 回填后 `frozen_sha256` **不再是 na**；无锚点 ⇒ `materialized=false reason=no_persisted_anchor`。
7. **实测（w38，2 例）**：缺锚点 + 有 materials-manifest ⇒ `map_reason=materials_manifest`、`written=2`、两条 `ai_score=64` 正确写入；两者皆缺 ⇒ `manifest_missing`、`written=0`、逐份 `needs_rerun`、`ai_score` 保持 NULL（绝不落 0 分）。
8. **BCNF**：`grading_assignment_anchors` 的唯一非平凡 FD 是 (assignment_id, checker_id) → 其余属性（该对即候选键）⇒ 满足 BCNF；与 R2-B12 的活动键方案（`grading_jobs.active_key` 生成列）互不影响。
9. **verify（串行 + selftest）**：selftest **PASS/exit 0**（装置侧本轮**零改动**）；check-layers 0 违规；unit **54 套件/715 例**；contract **3/50**；三重度 17/61/21；integration 51 套件/404 例（1 例既有 flake，见 §5）；smoke **8/8**；生产库指纹 before/after **逐位相同**。
10. 未验证项与自纠见 §6/§7。

## 2 数据模型（新增表）
```sql
CREATE TABLE `grading_assignment_anchors` (
  `id` INT NOT NULL AUTO_INCREMENT,
  `assignment_id` INT UNSIGNED NOT NULL, `checker_id` VARCHAR(80) NOT NULL,
  `frozen_sha256` VARCHAR(96) NULL, `materials_manifest_digest` VARCHAR(96) NULL,
  `n_submissions` INT NOT NULL DEFAULT 0,
  `submissions_json` JSON NOT NULL, `anchor_json` JSON NOT NULL,
  `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3), `updated_at` DATETIME(3) NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `uniq_grading_assignment_anchors_assignment_checker` (`assignment_id`, `checker_id`)
);
```
- **BCNF**：候选键 = (assignment_id, checker_id)；唯一非平凡 FD 是该对 → 其它属性 ⇒ BCNF ✓（表内无传递依赖）。
- 读写走**原始 SQL**（`INSERT … ON DUPLICATE KEY UPDATE` / `SELECT`）⇒ 不依赖 Prisma Client 的模型生成（本轮不执行任何 build/codegen）；`schema.prisma` 同步声明该模型，供未来 `prisma generate` 后按类型化 API 使用。

## 7 自纠清单
1. **Prisma 客户端未生成**：新模型 `GradingAssignmentAnchor` 在 schema 里，但本轮禁止 build/codegen ⇒ 类型化 API 不可用（测试首跑报 `Cannot read properties of undefined (reading 'deleteMany')`）。改为**原始 SQL** 读写（`ON DUPLICATE KEY UPDATE` + `SELECT`），并显式写 `created_at/updated_at`（raw SQL 不走 `@updatedAt`，否则 MySQL 报 `Field 'updated_at' doesn't have a default value`）。
2. **fake prisma 容错**：冒烟的 fake prisma 没有锚点表 API ⇒ `persistAnchor` 检测 `$executeRawUnsafe` 缺失时返回 `{persisted:false, reason:'anchor_store_unavailable'}`（不影响主流程；冒烟恢复 8/8）。
3. **迁移文件与已应用库的一致性**：`updated_at` 未带列默认值（由应用显式赋值）⇒ 迁移与代码一致；若后续希望 DB 侧兜底，可再开一条小迁移加默认值（当前不必要）。
