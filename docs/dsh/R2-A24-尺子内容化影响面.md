## 3. 风险清单（含最小复现）

① **并发同内容竞态**：`r2b7` 与 worker 造尺路径**都不在** `dsh_grading_concurrency` 闸内（闸只管 job 领取，`worker:274-281`）⇒ 同内容两入口并行会造两把。最小复现：同内容两作业 A1/A2，并行两次 `r2b7 --assignment A1|A2 --device node --device-arg scripts/stub-device.mjs`（不同 `--workdir`）⇒ 断言 `grading_rulers` 该 content_key 仅 1 行、且只有一把 `checker_id`；无 `UNIQUE(content_key)`+`building` 抢占即失败（第二把 checker 也入库）。
② **老锚点复用补建**：老锚点仅在 `checker_raw` 非空时可回填（`dshGradingAnchor.js:88-91`）；且按内容找老锚点**不能**用 content_key 的 zip-sha 去比 `grading_checkers.standard_hash`（那是装置口径 `dir_sha256(...,checker.input_contract.ignore)`，`check.py:419`/`shape_checks.py:85`）。可用判据：`grading_checkers.rubric_hash == 'sha256:'+sha256(rubric 字节)` 且对该候选 checker 用**它自己的 ignore** 复算 `dirSha256(标准包目录, ignore)` 与 `standard_hash` 相等。最小复现：`w41` 手法插一条无 raw 的历史锚点 ⇒ 必须走「不命中/重建」，不得假装命中。
③ **绑定不一致 fail-closed**：改 rubric/描述/标准包任一字节 ⇒ 新 content_key；此时同作业 (A,Q) 已有绑定且 ruler 不同 ⇒ 必须拒绝（留痕、不写分、不换尺）；同时 `worker:395` 的锚点 upsert 会把 `(A, job.checker_id)` 写成新尺 ⇒ 若 job.checker_id 被静默换成新尺，**老尺锚点字节会被覆盖**。最小复现：A1 出分 ⇒ 改 rubric ⇒ 重触发 A1 ⇒ 断言 `submissions.ai_score/checker_id/canonical_sha256/ai_feedback` 与 `grading_assignment_anchors(checker_raw)` 逐字段不变，且本次未写分。
④ **一作业多题** ⇒ 结论：**尺子按「题」定义，绑定按 (assignment,question)，运行/落分按作业**。依据：标准包路径按 questionId（`projectPaths.js:36-38`）；rubric/materials 是 question 字段（`schema.prisma:143-147`）；`submissions` 唯一键含 questionId（`:291`）⇒ 一次运行可写多题提交；export 只接受**唯一** project 题（`r2b20:123-124`）⇒ 本期实际 (作业)↔(project 题) 一一对应；但 `grading_checkers.question_id` 是单标量（`:505`），两 project 题无法表达 ⇒ content_key 绝不能按作业定义。最小复现：作业挂 q1(`type=code`, id 小) + q2(`type=project`) ⇒ 跑 `r2b7` 后断言记录的 `question_id==q1` 而物料来自 q2（口径分歧坐实，`:229-230`）。
⑤ **`grading_jobs`/`submissions`/页面**：见 §2-E/2-F。风险集中在 (a) 新表读取缺 try/catch ⇒ w15 假 prisma 崩；(b) worker 新增 `UPDATE grading_jobs SET content_key` 后 w15 的语句判别仍只认领取语句（`w15:29-37`）⇒ 断言应靠 DB 而非该假件。页面/API 与 `submissions` 不受影响。
⑥ **指纹规范化边界**：三个「同内容不同 key」陷阱 —— (a) 用 DB 原值 vs 导出字节（`buildAssignmentMd` 会 trim title/material 并补结尾 `\n`；rubric 是**无加工**字节复制）；(b) CRLF/BOM（DB 文本可能含 `\r`）；(c) 标准包口径（zip sha ≠ dir(ignore=[]) ≠ dir(3 项 ignore)）。最小复现：同一作业算两遍 key（DB 路径 / 导出文件路径）必须相等；再改一字必不相等。

1. **跨班/跨教师复用命中且零 LLM**：建 A1/A2 两作业（不同班、不同教师）挂同一 project 题与同一物料目录 ⇒ 先 `r2b7 --assignment A1` 造尺 ⇒ 再 `node scripts/r2b5-worker.mjs --once --reuse-checker --device node --device-arg scripts/stub-device.mjs`（A2 的 job）⇒ 判 `RULER_REUSE_HIT content_key=…`、`MODEL_CALLS=0`、`grading_rulers` 该 key 仅 1 行、两作业 `submissions.checker_id` 相同且分数逐位一致。（跨教师=换 `assignments.teacher_id` 第二例。）
2. **并发同内容只造一把（race）**：同一 content_key 两个入口并行（两个 `r2b7`，或 r2b7 ∥ worker）⇒ 断言 `SELECT COUNT(*) FROM grading_rulers WHERE content_key=?` = 1、无第二把 `checker_id`、等待者**未写库**（无第二行 `building` 之外的写入）；并用 `information_schema.statistics` 验证 `uniq_grading_rulers_content_key` 真实存在（不是只在 schema.prisma 里）。

4. **老锚点复用补建**：按 `w41-anchor-no-raw.test.js` 手法插「有 raw / 无 raw」两条历史锚点 ⇒ 有 raw：应复用补建 `grading_rulers`（`checker_raw`/`frozen_sha256` 与原锚点逐位一致）且 `MODEL_CALLS=0`；无 raw：必须明确「不命中」并 fail-closed 或重建，**不得假装命中**（防 `raw_bytes_unavailable` 被吞）。
