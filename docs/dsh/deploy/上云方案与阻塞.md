## 二、两个阻塞（必须先解决）

### ★阻塞 1：DSH 跑不了 Linux 云主机

```
本机 dsh = ELECTRON_RUN_AS_NODE=1 exec "…/MacOS/DeepSeek Harness" …（负载含 8 个 .node 原生模块）
```
- **方案 A（装置跑云主机）**：需要 **DSH 的 Linux 发行版** —— 待确认是否存在；
- **方案 B（推荐，已验证可行）**：**装置/worker 留在 Mac**，SSH 隧道连云上 MySQL；uploads 用 rsync 同步（9 MB）：
  ```bash
  # 隧道（用 13306 避免与本机 MySQL 冲突）
  ssh -N -L 13306:127.0.0.1:3306 root@203.0.113.10
  # 物料：本机跑导出器（读隧道 + 本机 uploads 镜像）
  node server/scripts/r2b20-export-materials.mjs --assignment <id> --out <dir> \
    --db-url mysql://root:***@127.0.0.1:13306/exam_system --allow-db exam_system --allow-prod \
    --uploads-root <本机镜像>
  ```
  代价：**这台 Mac 需保持开机**；吞吐受本机限制（单实例、闸=1）。

### ★阻塞 2：云上 schema 落后

云上库**没有** `_prisma_migrations`、没有 `questions.rubric_items`、没有 `submissions.grading_stale`、没有 `grading_*` 三表 ⇒ 不能直接 `prisma migrate deploy`。

**升级 SQL 已生成并验证为纯增量**：`docs/dsh/deploy/cloud-schema-upgrade.sql`（71 行）
```
新增 3 张表: grading_jobs · grading_checkers · grading_assignment_anchors
新增 12 列  : checker_id · canonical_sha256 · grading_stale · rubric_items · rubric_snapshot ·
             material_snapshot · snapshot_origin · standard_hash · checker_status/script/meta …
★ DROP 语句数 = 0  ⇒ 不动任何现有数据
```
**建议顺序**：① 备份云上库 → ② 应用该 SQL → ③ 校验（表/列存在、各表行数不变）→ ④ 备好回滚（恢复备份即可，因为无破坏性语句）。
