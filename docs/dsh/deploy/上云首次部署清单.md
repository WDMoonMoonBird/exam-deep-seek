## 0 云主机前置

| 项 | 要求 |
|---|---|
| 规格 | 2C4G+（常驻 worker 实测 58 MB；批改期间进程树 58–75 MB） |
| 磁盘 | ≥ 40 GB；每次运行产生 24 MB 级 run-root（`/tmp/r2b4-job-*`），需配清理 |
| 时钟 | 走 NTP；**回收判据按 UTC**，DB 与宿主时钟差必须 ≤ 60 s（自检第 ⑦ 段会查） |
| 软件 | Node ≥ 20；MySQL 可达（生产库 `exam_system`）；**DSH 已安装在目标机**（装置会调 `dsh --profile headless`） |
| 部署面 | **只部署服务端 + worker**；前端（`client/**`）由 UI 团队另发版，不要因为同推而带上线 |
| ★模型端点 | 装置走 **Anthropic 风格 Messages API**，根必须是 **`https://api.deepseek.com/anthropic`**（写成 `https://api.deepseek.com` ⇒ 拼出 `/v1/messages` ⇒ **404** ⇒ 造尺必失败）。平台 `deepseek_base_url` 是 OpenAI 风格口径，**不可直接喂装置**；装置会按 `DSH_GRADER_BASE_URL` > `DEEPSEEK_BASE_URL`（host 为 api.deepseek.com ⇒ 自动补 `/anthropic`）> 默认 派生端点 |

### 0.1 模型端点验活（2 分钟，别等造尺才发现 404）

```bash
KEY=<平台 system_configs.deepseek_api_key>
# OpenAI 风格（平台客户端用）—— 期望 200
curl -s -o /dev/null -w '%{http_code}\n' https://api.deepseek.com/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"ping"}]}'
# Anthropic 风格 Messages（★装置要的根）—— 期望 200
curl -s -o /dev/null -w '%{http_code}\n' https://api.deepseek.com/anthropic/v1/messages \
  -H "x-api-key: $KEY" -H 'anthropic-version: 2023-06-01' -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-chat","max_tokens":8,"messages":[{"role":"user","content":"ping"}]}'
```

装置准备 profile 时会打印生效端点（只打 scheme+host+path，**不含 key**）：`MODEL_ENDPOINT=… model=…`；若你要覆盖，在 worker 环境里设 `DSH_GRADER_BASE_URL=<Messages 根>`。

## 3 安装部署文件

```bash
sudo mkdir -p /etc/dsh-grader /srv/grader/materials
sudo cp docs/dsh/deploy/worker.env.example /etc/dsh-grader/worker.env
sudo chmod 600 /etc/dsh-grader/worker.env
sudo cp docs/dsh/deploy/dsh-grader-worker.{service,timer} /etc/systemd/system/
```

`/etc/dsh-grader/worker.env` **必填/建议**：
```ini
DATABASE_URL=mysql://exam_app:***@127.0.0.1:3306/exam_system
DSH_GRADER_MATERIALS_ROOT=/srv/grader/materials    # ★多作业必需：按 <id> 子目录取该作业物料
DSH_WORKER_STALE_RUNNING_MS=900000                 # 必须 > 单次运行时间
GRADER_SUBMISSIONS=63                              # 仅在未用 MATERIALS_ROOT 时生效
```
`dsh-grader-worker.service` **必改三处**：`WorkingDirectory=/opt/exam/server`、`DSH_GRADER_BIN=<Linux 上的 dsh>`、`node` 绝对路径。

## 4 ★首次批改的顺序（不能颠倒）

```bash
# ① 导出该作业物料（纯读生产库）
node server/scripts/r2b20-export-materials.mjs --assignment <作业ID> \
  --out /srv/grader/materials/<作业ID> \
  --db-url "$DATABASE_URL" --allow-db exam_system --allow-prod
# 期望：EXPORT_OK n=<份数> question=<题ID> standard_sha256=…

# ② 用【同一份导出件】造尺（每作业首次；1 次模型调用；约 3–4 分钟）
node server/scripts/r2b7-build-checker.mjs --assignment <作业ID> \
  --db-url "$DATABASE_URL" --allow-db exam_system --allow-prod \
  --limit 2 \
  --device-extra-arg --source-dir --device-extra-arg /srv/grader/materials/<作业ID> \
  --device-extra-arg --allow-identical
# 期望：CHECKER_ID=sha256:… 且 grading_checkers 出现该作业的 ready 行

> ⚠️ **造尺是唯一需要真实模型调用的一步**（每次约 1 次会话、3–4 分钟）。必须先确认**平台/worker 使用的 key 对「模型 + 端点」有效**，否则造尺会话会**1 秒即失败**：错误在 `<run-root>/out/logs/session-build.err`（形如 `dsh: HTTP_404: DeepSeek Messages request failed`），job 报 `build-session-nonzero(rc=1,child=1)`。
> 另：装置凭据解析顺序为 `env:DEEPSEEK_API_KEY` → `~/.dsh/.credentials.yaml` → 平台 DB；**若 env 为空会回退到 `~/.dsh` 的凭据**（那是 DSH 自己 provider 的 key，与 `deepseek-v4-flash @ api.deepseek.com` 不匹配 ⇒ 404）。
> **key 从哪里取（本项目实测）**：平台运行时用的是 **DB `system_configs`** 的 `deepseek_model` / `deepseek_base_url` / `deepseek_api_key`；`server/.env` 里的同名副本**可能已失效**（实测报 `AUTH: ... Your api key: ****cce1 is invalid`）。云上前先确认：`mysql -e "SELECT \`key\`,LEFT(value,8) FROM system_configs WHERE \`key\` LIKE 'deepseek%';"`，并用该 key 跑一次造尺。

# ③ 起服务（二选一）
sudo systemctl enable --now dsh-grader-worker.timer     # 峰谷窗口形态（上线推荐）
# 或常驻形态（测试期）：见 deploy/README.md §6

# ④ 触发（测试期用平台「立即批改」；上线后由峰谷窗口自动消费）
```

⚠️ **尺子与物料绑定**：尺子内钉着造尺时的 `rubric_hash`/`standard_hash`。**换材料必须重造尺**，否则装置判 `STALE=true reason=rubric_hash_mismatch,standard_hash_mismatch` 并**拒绝给分**（正确行为）。

## 5 验收（三连判据）

```bash
journalctl -u dsh-grader-worker -n 80 --no-pager | grep -E 'WORKER_START|MATERIALS_RESOLVED|CHECKER_REUSE|ANCHOR_MATERIALIZED|STALE_RECLAIMED|dsh_grader_end|消费完成'
mysql exam_system -e "SELECT id,status,written_count,LEFT(last_error,60) FROM grading_jobs ORDER BY id DESC LIMIT 3;"
```
| # | 判据 | 期望 |
|---|---|---|
| 1 | 装置退出码 | `dsh_grader_end exit_code=0` |
| 2 | 消费 | `written>0` 且 `map_reason=manifest|materials_manifest` |
| 3 | job | `status=done` 且 `last_error` 为空 |

## 6 排障与回滚

- **失败第一现场**：`journalctl … | grep DEVICE_LOGS` 拿到 `<run-root>/out/device.stderr.log`（含根因行，凭据已脱敏）+ `grading_jobs.last_error` 尾部
- **退出码含义**：`127` 装置脚本路径/cwd ｜ `5` 形状闸/缺尺子 ｜ `1` 装置内部失败 ｜ `3` 冻结完整性（字节不一致）｜ `124` 超时 ｜ `exit=0 但 written=0` 映射失败
- **造尺会话失败**：`build-session-nonzero(rc=1,child=1)` ⇒ key 与「模型+端点」不匹配（看 `out/logs/session-build.err` 的 `HTTP_404`）；确认 `DEEPSEEK_MODEL`/`DEEPSEEK_BASE_URL` 与 key 同源
- **回滚**：`git checkout <上一个 freeze tag>` + `systemctl restart dsh-grader-worker`；DB 迁移均为**增量且带 `rollback.sql`**，按备份恢复（备份见 `~/r2-backups/` 口径）

## 7 上线收尾（方案文档已裁定）

1. **关闭「立即批改」**（用**配置开关**，不删按钮）+ 教师端显示「预计开始时间」与「为什么还没出分」文案；
2. `run-root` 清理 cron（成功现场可清、失败现场留证）：`find /tmp -maxdepth 1 -name 'r2b4-job-*' -mtime +3 -exec rm -rf {} +`；
3. journald 轮转；`/srv/grader/materials/<作业ID>` 视总量保留策略清理；
4. 每周核对一次：`grading_jobs` 是否有异常 `running` 残留（应为 0；worker 启动会自动回收并打印 `STALE_RECLAIMED`）。
