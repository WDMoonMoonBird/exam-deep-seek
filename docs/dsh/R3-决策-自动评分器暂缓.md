# 决策记录：自动评分器（checker）入口暂缓开发、能力保留

日期：2026-10-14　｜　决策人：用户　｜　记录：队长

## 决策
教师端「自动评分器」入口按钮**继续隐藏**；该功能**暂不开发**，但**代码与后端接口全部保留**（不做删除、不做重构）。

## 当前实际状态（核实于 2026-10-14）
- 入口按钮：`client/src/composables/project/useChecker.js:42` → `const FEATURE_CHECKER_ENTRY = false;`（模板 `ProjectQuestionEdit.vue:41` 依此隐藏）
- 隐藏由来：2026-10-11 按用户要求暂时取消（两处代码注释均写明恢复方式：把开关改回 `true`）
- 教师手册：`client/src/components/manual/sections/ProjectSection.vue:24` 已说明该按钮被开关关闭、不绘制（文档与实现一致）
- 后端接口保留：`POST/GET /teacher/questions/:id/checker{,/generate,/confirm,/rollback}`（不删、不改）
- 唯一仍会露出的面：**保存守卫逃生通道** —— `useSaveQuestion.js:19-52` 在「评分器过期 / 生成中 / 已生成未确认 / 未生成」时弹出该模态框（新建题首次保存放行）；模态框内提供可复制脚本，供转交运维造尺

## 由此带来的已知限制（接受，不修）
1. 应用侧无 builder（API 进程无 `DSH_GRADER_BIN`）⇒ 教师点「生成」会 fail-closed：日志 `RULER_NO_SOURCE … reason=no_builder_and_no_adoptable_source（不写库）`
2. 造尺目前依赖运维序列（导出装置物料 + `--source-dir` + 带 env 跑装置），实测一次约 8.7 分钟 / ¥1.245；尺就绪后**复用命中**（`cost_total=0 no_model_session=1`）
3. `questions.checker_status` 与作业级 checker 不同步（题目状态恒为 none）⇒ 若以题目状态判断「尺就绪」会误判

## 恢复方式（将来要做时）
把 `FEATURE_CHECKER_ENTRY` 改回 `true`；若要真正可用，还需给应用侧接上「导出物料 → 造尺」链路（或在应用内接入装置 builder）。
