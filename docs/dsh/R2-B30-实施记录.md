## 2 计数口径（写进代码注释，契约）
```
measured     = 成功量尺的份数（有分且判为可量）
unmeasurable = C8 预检/量尺判定为不可量的份数
```

## 3 造尺路径的会话清理边界（★说明与建议，本轮不实现）
- **现状**：`server/scripts/r2b7-build-checker.mjs`（造尺）**不经** worker 的 `runOnce` ⇒ 它的 run-root 不会被 `purgeRunRootSessions()` 处理 ⇒ 若造尺用了隔离 home，其 `home/sessions/**` 与 `home/.keep-scene` 会**留在 /tmp**（会话未销毁）。
- **风险**：造尺同样会拉起装置（产生会话）；长期运行会在 `/tmp` 累积会话与 run-root；`r2b23-audit-runs.mjs` 能报告残留（`session_residue`/`credential_residue`），但**当前只在批改路径的 run-root 上默认生效**，造尺的 run-root 需运维手工指向。
- **建议（择一，按代价从低到高）**：①**运维兜底**：把审计脚本纳入定时任务（`node server/scripts/r2b23-audit-runs.mjs`，非 0 退出即告警），并按 `.keep-scene` 的 `keep_days` 手工/定时清理；②**同样包装**：给造尺路径加与批改一致的 teardown 包装（把 `purgeRunRootSessions()` 提到一个共享的「run-root 生命周期」helper，两条路径都调用）；③**统一入口**：让造尺也走 worker 编排（改动最大）。
- **建议采用 ②**（与批改同口径、语义一致、改动面小），但需队长确认后再排轮次（本轮 inScope 不含 `server/scripts`）。
