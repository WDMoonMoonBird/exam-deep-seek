## 1. P0-3：/api 未命中 ⇒ 统一 JSON 404（含"公网为何是 HTML"的结论）
- 代码：`server/src/app.js` 在路由挂载之后、`makeErrorMiddleware()` 之前插入 `app.use('/api', (_req,res)=>res.status(404).json({code:1404,message:'接口不存在',data:null}))`。
- **排查结论**：云上 `NODE_ENV` 未设置 ⇒ `app.js` 的"生产块"（静态 + SPA fallback）不执行、由 nginx 承担 SPA fallback ✓；但 `/exam/api/*` 仍被 nginx 转发到 Express（前缀改写为 `/api/*`）。Express 侧**从未注册** `/api` 兜底 ⇒ 命中 Express 内置 404 ⇒ HTML `Cannot GET /api/foo` ⇒ **与 nginx 无关**，补上该中间件后同一请求返回 JSON。
- 证据（本机，Express 实际看到的路径与 nginx 改写后一致）：`GET /api/definitely-missing` ⇒ `404` + `content-type: application/json` + `{code:1404,message:'接口不存在',data:null}`；带 `Accept: text/html` 仍为 JSON（API 前缀恒 JSON，HTML 分流只作用于错误中间件）；`GET /api/nope` 同上。**经 nginx 的公网路径** `/exam/api/nope`：nginx 仅做前缀改写 + 转发 ⇒ Express 收到的即 `/api/nope`（同一条中间件），故行为一致；本批**不改 nginx**（P0-1/P0-2 由队长处理），未部署 ⇒ 无法在公网实测，此结论基于 nginx 配置语义 + 本机同路径断言（已如实说明）。

## 2. P1-4：上传超限 413 + code1403（两条路径同口径）

## 3. P1-6：错误中间件 Accept 分流（含 error-pages 不存在时的回落）
- `makeErrorMiddleware({ errorPagesDir = <repo>/client/public/error-pages, log })`：`status = err.status || 500`；`req.accepts(['html','json']) === 'html'` ⇒ 若 `<dir>/<status>.html` **存在**则 `sendFile`（状态码不变），否则**回落 JSON**；JSON 分支：500 ⇒ `{code:2001,message:'服务器内部错误'}`、其它 ⇒ `{code:1404,message:'请求处理失败'}`（**既有 500 契约逐字不变**）。
- **回落行为说明**：仓库当前**没有** `client/public/error-pages/` 目录（`client/` 亦不在本批 inScope）⇒ 线上 HTML 错误将走 JSON 回落；将来放入错误页文件即自动生效（无需改代码）。测试用 `os.tmpdir()` 造临时目录分别覆盖"存在 ⇒ HTML"与"不存在 ⇒ JSON 且状态码不变"两条分支。
