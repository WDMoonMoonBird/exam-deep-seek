# R2-B37 实施记录：监测展示（只读 API 扩展 + 「批改记录」详情三块面板 + 中文化）

> 摘要（≤10 行）：① 只读 API 扩展：列表增 `cost_total/cost_currency/cache_hit_rate/no_model_session/model_calls`；
> 详情增三块 `usage`（token 四项+命中率+费用+模型调用次数+价目版本+时段档+运行标识）、`meta`（老师/班级**全量**/作业名+ID/
> 标准工程包**短 sha+文件名+可折叠 manifest 摘要（不提供下载）**/题目描述/评分标准，全部优先取**发布冻结快照**）、
> `tools`（工具名/次数/耗时/失败；不可得 ⇒ `tools:null` + `tools_info.reason`）；② 不可得/空数据一律 `null + reason`（不 500、不显示假 0）；
> ③ 零 LLM 运行 ⇒ `no_model_session=true`，页面显示「**本次无模型会话（零 token）**」，命中率显示「不适用（无模型调用）」；
> ④ 页面新增三块面板 + 列表用量列，并按要求**中文化**（中文标签为主，英文原键在 tooltip/小字保留）；⑤ 构建通过且
> 产物含 `GradingRuns-*.js` chunk；⑥ 顺手修两处既有缺口：`grading_job_runs.failed` 列缺失兼容、`grading_job_runs`/`grading_run_usage`
> 孤儿行清理（否则 w56「恰好 3 条」断言随历史随机失败）。

## 1. 只读 API 扩展（`server/src/controllers/adminGradingRunsController.js`；挂既有 `/api/admin/grading-runs`）
| 位置 | 新增字段 | 数据来源 / 口径 |
|---|---|---|
| 列表 `GET /api/admin/grading-runs` | `cost_total` `cost_currency` `cache_hit_rate` `no_model_session` `model_calls`（每条） | `grading_run_usage`：worker 行按 `job_id IN (…)`、造尺行按 `run_ref='build:<assignmentId>:<归档目录名>'`（与 R2-B36 落库键一致）批量取（1~2 条 SQL） |
| 详情 `GET /api/admin/grading-runs/:id` | `usage` / `usage_info` | 同上；无落库行时**回落 `run-teardown.json.usage` 摘要**（`source='teardown_json'`，如实标注口径变化） |
| 详情 | `meta` | `assignments`(+老师) / `assignment_classes`→`classes`(全部) / `assignment_questions` 快照(+`questions`)；标准工程包另尝试读归档与 `DSH_GRADER_MATERIALS_ROOT/<aid>/export-manifest.json` 富化 manifest |
| 详情 | `tools` / `tools_info` | `grading_run_usage.tools_json`（工具名/次数/耗时/失败数）；`tools_json IS NULL` ⇒ `tools:null` + `reason='tools_unavailable'` |

**不可得语义（不 500、不假 0）**：`usage`/`tools` 为 `null` 时必带 `usage_info.reason`/`tools_info.reason`：
`no_usage_record`（旧运行）/ `usage_table_missing`（迁移未落地；`usage_info.table_missing=true` 且 `note` 说明可能的回落来源）/`tools_unavailable`。
表缺失时列表 `source.usage_table=null` 且列表列全为 `null`（页面显示 `—`）。```failed`` 列缺失（差量建表的库）时自动回退无该列 SELECT，`failed` 取 teardown 证据（不因缺列整页退化）。

**标准工程包展示口径**（已批准）：`standard_package = { sha256, short_sha256(前 12 位), file_name(题目附件名，缺省 '标准工程包.zip'), source(publish_snapshot|live_dir|absent), download:false, manifest }`；
`manifest` 优先 `export_manifest`（file/sha256/bytes/entries/rubric_chars/assignment_doc_chars/n_submissions），否则 `snapshot` 摘要
（standard_hash + 来源 + captured_at + rubric_sha256 + material/rubric 字符数）——**只读展示，不提供下载**。

**零 LLM 语义**：`usage.no_model_session=true` 且 token/费用全 0；页面在用量面板与列表以「本次无模型会话（零 token）」呈现，
命中率显示「不适用（无模型调用）」（`cache_hit_rate=null` 不得写成 0%）。

## 2. 页面（`client/src/views/admin/GradingRuns.vue`）
- **详情抽屉三块新面板**：📊 用量（模型/调用次数/输入未命中/输入命中/输出/缓存写入/命中率/费用/价目版本/时段档 + 本次无模型会话）、
  🧾 元信息（老师、作业名+ID、班级**全量标签**、标准工程包短 sha+文件名+**可折叠 manifest**、题目描述、评分标准 + 快照口径说明 + 告警）、
  🔧 工具调用（工具/次数/耗时/失败表；不可得显示 reason 提示，不显示假数据）。
- **列表**：列名中文化（归档/类型/作业/状态/已量尺/不可量/无法评分/未写分/已写分/费用/命中率/会话销毁/时间），
  费用 `¥0.0000`（4 位小数）、命中率百分比（无输入 ⇒ 不适用）、时间本地化（UTC 进 tooltip）、耗时作为时间列小字。
- **中文化映射**（队长追加）：中文标签为主，**英文原键保留在 tooltip/小字**（`原键：xxx=值`，≥12 处）——
  类型（批改运行/造尺运行）、装置退出码（0=正常）、销毁范围（会话文件 + 凭据（保留 home 骨架））、会话是否销毁（已销毁/未销毁）、
  会话文件数（前 → 后）、会话字节数（B/KB/MB）、凭据是否删除（已删除/未删除（警示））、隔离目录是否保留（保留（预期）/已删除）、
  销毁策略人话化（“成功即销毁会话；失败保留现场 N 天；装置退出码 X” + 原串 tooltip）、证据来源（批改 worker/造尺脚本）、证据时间（本地+UTC tooltip）、
  运行标识（`job:<id>` ⇒ 批改任务 #id；`build:<作业ID>:<目录>` ⇒ 造尺（作业 #ID））。
- **原始证据（JSON）折叠面板**：`run-teardown.json` / `session-usage` / `tools` 原文展开（字段名与 DB/日志一致，便于逐项对照）。
- **BASE_URL 铁律**：本页不引入任何绝对根路径资源（`src="/…"`/`href="/…"`/`url(/…)` 均为 0 处；测试断言）；请求走既有 `src/api/request.js` axios 实例。
- 空/异常语义：详情 404/读取失败 ⇒ 明确错误提示；用量/工具不可得 ⇒ 文案 + reason；`detail` 为空时不渲染面板（不白屏、不显示假 0）。

## 4. 构建与回归（逐条结果）
- `npm run build` ⇒ `✓ built in ~34s`，`dist/assets` 含 `GradingRuns-*.js` + `GradingRuns-*.css` + `GradingRuns-legacy-*.js`（`grading_chunk=3`），`index.html` md5 记录在交付字段。
- `node scripts/check-layers.mjs` ⇒ 139 文件、**0 违规**。
- 回归（静默窗口内串行，均 rc=0）：unit **750 例 / 60 套件**；contract **50 例 / 3 套件**；integration **496 例 / 68 套件**（含本批 W57-U 7 例）。
- 生产库指纹（amend 口径 `env -u DATABASE_URL -u NODE_OPTIONS`）⇒ `FINGERPRINT_OK`、`TABLE_COUNT=28`（本次无迁移，生产零写入）。
- **★verify 命令的 `-t "w56|w57"` 段：既有缺陷（非本批引入）**——jest 的 `-t` 大小写敏感，既有用例名为 `W56/W57`（大写）⇒ 该段**选不中任何用例**（本批前就如此）；
  用例全部被过滤时 jest 迅速收尾，而 `src/app.js:start()`（异步起 socket）尚未完成 ⇒ `require after teardown` ⇒ `process.exit(1)` 杀进程（rc=1、0 例）。

  全量 `test/integration` 静默窗口内 **67 套件 / 489+ 例全绿**（含 W57-U 13 例）。建议队长把 verify 该段改为
  `… test/integration/w56-admin-grading-runs.test.js test/integration/w57-admin-grading-runs-http.test.js test/integration/w57-admin-grading-runs-usage.test.js`
  （或 `-t "W56|W57"`）。

## 5. 顺手修掉的既有缺口（本批现场发现，均在本任务 inScope 内）
1. `grading_job_runs.failed` 列在**差量建表的库**里不存在 ⇒ 控制器原 SELECT 直接抛错、整页退化为「仅归档视图」；
   现改为「带 failed 查 → 失败回退无该列」并把 `failed` 回落 teardown 证据（R2-B31 已写入）。
2. `test/setup.js:cleanupOrphanGradingRows` 此前**只清`grading_jobs`/`grading_checkers`/锚点/绑定**，不清 `grading_job_runs`/`grading_run_usage`
   ⇒ 每跑一次全量 integration 都在库里堆孤儿行，让 w56「恰好 3 条」断言随历史随机失败；现按同口径（assignment 已不存在）清理，
   **在产运行记录一行不动**（w44 的边界断言仍绿）。
3. 控制器出口统一 `toJsonSafe`（Prisma 原始 SQL 的 BIGINT ⇒ Number），避免 `res.json` 抛 `Do not know how to serialize a BigInt`。

## 6. 边界
- 本批不提供标准工程包下载（口径：短 sha + 文件名 + manifest 摘要）；`export-manifest.json` 仅在归档或物料根存在时用于富化，缺失则回落快照摘要。
- 元信息取**运行时的发布冻结快照**（`rubric_snapshot`/`material_snapshot`/`standard_hash`），历史作业无快照时回落活值并在面板注明（`from_snapshot=false`）。
- 页面只读；不改 `server/src/services`（t3 范围）与装置侧脚本；未 npm install；未部署（构建产物由队长统一构建部署）。
