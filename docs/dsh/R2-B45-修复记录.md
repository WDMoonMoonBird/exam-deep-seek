> 摘要（≤10 行）：① **O1**：未登记价目的型号（实测 `--model deepseek-reasoner`）下 `computeCost` 返回 `ok:false / cost_total:null`，
> 旧实现把它当 0 ⇒ 逐份 `cost=0.000000` ⇒ **`--max-cost` 静默失效**。**选择修法 (a)**：未知型号按**价目表内最高的 peak 档**（现为 `deepseek-v4-pro.peak = 0.30/9/27` 元/百万 token）作
> **保守上限**估算，并打印 `PRICE_FALLBACK model=<m> rule=deepseek-v4-pro.peak …`、`--json` 摘要带 `price_fallback` ⇒ 未知型号下护栏**仍能拦住**（宁可高估、不可静默放过）；

## 1. O1：未知型号下让成本护栏可信（修法 a + 警示）
- 触发条件：`priceModelKey(model, resolvePriceTable(null))` 为 `null`（型号未登记在 `system_configs.llm_prices`，也未命中默认表的 `match` 规则）。
- 行为：启动时打印一次
  `PRICE_FALLBACK model=<m> rule=<最高档 model_key>.peak（未登记价目 ⇒ 按价目表最高档作**保守上限**估算：cache_hit=0.3 cache_miss=9 output=27 元/百万 token ⇒ 成本护栏仍可信；如需精确价目请在 system_configs.llm_prices 登记该型号）`，
  `MODEL=…` 行追加 `PRICE_FALLBACK=yes`；逐份 `cost=…` 用保守价计算（不再 0.000000）；`--json` 摘要含 `price_fallback:{model,rule,peak}`。
- 已登记型号：路径完全不变（`computeCost` 正常返回，`fallback:false`，不打印警示）。
- 实测：`estimateCostOfUsage({prompt_cache_miss_tokens:1e6,completion_tokens:1000}, 'deepseek-reasoner')` ⇒ `cost_total=9.027 CNY / tier=fallback_upper_bound(peak) / fallback_rule=deepseek-v4-pro.peak`；同 usage 走 `deepseek-v4-flash` ⇒ `1.004 CNY / idle / fallback:false`（不变）。

## 2. O2：依据行显示真实失分项数
- 写入侧（`gen-ai-summary.mjs`）：`summary.facts = { passed, total, score, **failed_count**, failed_items }`；`failed_count` 来自 `extractBreakdownFacts()`（**未截断**计数），`failed_items` 仍是 ≤12 条的 id 列表（**prompt 的 12 条上限不变**）。
- 展示侧（`client/src/composables/review/parseCheckerFeedback.js`）：`buildBasisText({…, failedCount})` 用 `n = max(failedCount, 列表长度)`：有 summary 且带 `failed_count` ⇒ 显示真实值；旧 summary 缺字段 ⇒ 回落列表长度；无 summary ⇒ 用未截断分项数。`failedCount` 同时作为解析结果的字段暴露（便于测试/其它消费方）。
- 实测（纯函数）：13 项失分 + `failed_count:13` ⇒ `failedCount=13`、依据行「… 等 13 项」；旧数据（无 count、列表 12）⇒ 「等 12 项」（**不虚报**）；无 summary ⇒ 「等 13 项」（与修复前一致）。
