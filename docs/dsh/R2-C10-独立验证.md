## 1 方法
- 生产防呆：逐例独立 TCP 监听窗（`t31-tcp-conn-probe.py 19399`），`--db-url` 指向**我的探针端口**（库名 `exam_system` 触发生产门）；**全程未指向真实生产实例**、未启动真实装置。
- 复用接线：测试库夹具（作业+提交+pending job+`grading_checkers` ready 行，`checker_json` = 真实 `/tmp/e2e353-run/out/checker/checker.json` 的解析值）+ **自建记录型装置**（`t53-recording-device.cjs`：把 argv/env 落盘 `out/argv.json`，并把真实产物 `s01.json` 复制进来、把 `submission.id` 改成目标提交）⇒ 可同时观测"装置参数"与"复用产物"，零 LLM。
- 分数一致性：对比复用路径写入 DB 的分数/canonical 与**同一 checker 已入库的同名产物**（`/tmp/e2e353-run/out/measure/s01.json`）。
- 安全：`db-fingerprint.js` 跑前后对拍、生产 92 分摘要只读核对、探针自清理（夹具/作业/尺子行、我建的 run-root、临时凭据）。

## 2 ★生产防呆（逐例探针）
| 用例 | rc | TCP 探针 | REFUSE_STUB | REFUSE_PROD | STAGE=connect | WORKER_START |
|---|---|---|---|---|---|---|
| 生产授权 + 默认（stub） | **2** | **accepted=0** | **yes** | no | no | **no** |
| 生产授权 + 显式 stub | **2** | **accepted=0** | **yes** | no | no | **no** |
| 生产授权 + 真实装置参数 | 0 | accepted=2 | no | no | **yes** | yes |
| 测试库 + 默认 stub | 0 | （测试库） | no | no | **yes**（`target_db=exam_system_test`） | yes |
- 拒绝态原文：`RESULT=REFUSE_STUB_DEVICE_ON_PROD reason=device_is_stub:must_pass_real_device_args` + `REFUSED_BEFORE_CONNECT=yes`（+ `HINT=生产请显式给真实装置…`）。
- 语义：`accepted≥1` 仅表示"越过守卫并尝试连接"，**≠ 写入**；本轮无任何生产写入（§5）。

## 6 观察与未核验（非阻断）
- **O-1**：integration 全量又出现新 flake 成员（本轮 `t2-teacher-scope`，单跑必绿）——建议统一标注或隔离测试库。
