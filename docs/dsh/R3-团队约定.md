# R3 团队协作约定（防止上下文爆炸）v1

> 所有成员开工前读一次本文件（≤40 行）并遵守。违反它的代价在 §6 写明了（本仓真实踩过）。

## 1. 信息走文件，不走消息
1. 交接物一律落盘（报告/清单/证据文件）；**消息只放**：结论 1–3 行 + 文件路径 + 需要对方做什么。
2. 成员之间的交接（A→B 的拆分清单、C→D 的缺陷清单）**只通过文件 + 任务**完成，不要在消息里粘大段内容。
3. 队长给你的唤醒/追问消息同样 ≤3 行；你也照此回复。

## 2. 读的纪律（省 context 的大头）
4. **先读 `docs/dsh/R3-团队速查.md`**（A 在 t1 产出）：文件清单/行数/三开关落位/US-A1 现状 ⇒ **不要各自全仓 grep**。
5. 需求只读 `docs/plan/2026-10-14-需求-实训重评与反复提交.md` 中**你负责的 US 段落**，不要通读后复述。
6. 大文件用 `grep` / 带 offset+limit 的读取；**禁止整文件通读 >500 行的文件**（除非它是你的改造对象且确有必要）。
7. 不重复读已读过的内容；不把源码大段复制进报告。

## 3. 写的纪律（产出体积硬上限）
8. 报告行数上限：t1 ≤120 行 ｜ t8 ≤80 ｜ C1/C2/C3 ≤90 ｜ C4 ≤100；超出部分拆到 evidence 文件。
9. 证据文件只放**可核验的最小片段**（命令 + 关键输出 10–30 行）；完整日志写 `/tmp` 或 `docs/dsh/evidence/`，报告里只写路径。
10. **命令输出一律截断**：`| tail -N` 或 `| grep -E`；禁止把 jest/构建的全量输出贴进报告或消息。
11. 完成消息 ≤12 行：结论 + verdict + changedPaths/commandsRun 摘要 + 1 个最关键证据。

## 4. 任务的纪律
12. 开工先 `claim_task`；完成先 `update_task`（completed + verdict/acceptanceResults/commandsRun），**再**发简短消息。
13. 越界改动不另写报告：记入该任务的 `evidence_note`（文件、行、理由）。
14. 发现"**验收标准本身无法达成**"⇒ 立刻用 1 条消息报队长，不要硬凑或空转（上轮真实发生过：迁移会让某条验收项不可能达成）。
15. **不发进度播报**：只在「开工 / 完成 / 阻塞」三类情形发消息。

## 5. 质量底线（与体积无关，必须做）
16. 三道门禁与目标测试在**改动前后**都要跑：`arch-metrics`（rc=0、GodFile>800=0、未分层 ≤41）、`check-layers`（违规 0）、`cycle-check`（SCC 0）。
17. 测试命令用仓库真实路径 `test/jest.config.js`，并先把 `DATABASE_URL` 派生为 `exam_system_test`（否则被 `test/setup.js` 的生产库护栏拦下）。
18. C（验证）必须独立：自建夹具、独立复算、≥2 条变异自证；不依赖实现方写的测试。

## 5.5 共享资源串行化（R3 实战新增）
22. ★**任何两个"verify 会跑全量套件"的任务之间，必须加一条依赖边串行化** —— 调度器不知道共享测试库（`exam_system_test`，唯一白名单）的存在，只有规划者能防；R3 因此连续两次出现"两套全量并行 ⇒ 大量假红"（25~32 条），都要靠安静窗复跑才能还原真相。
23. 成员侧应对：`pgrep -fl jest` 先看有无并发；发现污染时**先如实记录污染、再隔离复跑**，不要把假红当缺陷或当通过。

## 6. 为什么（本仓真实教训）
19. 单进程跑全量 jest 会撞 MySQL 连接耗尽 ⇒ **大量 failed to run 是假象**（全量必须逐套件进程隔离）。
20. 上下文爆炸的三个典型来源 = 全量测试输出 + 大文件通读 + 长报告 ⇒ 按 §2/§3 掐断。
21. 只读预检很值钱：上轮成员在等依赖时做只读核查，提前发现"验收项自相矛盾"，省下一次必然返修。

## 5.6 verify 命令的两条硬规矩（R3 实战新增）
24. ★禁止把 unit 与 integration 合并成一条 jest 命令：实测（t30/S5）合并单进程会撞 MySQL Too many connections（max_connections=151）⇒ 90 个套件级 failed-to-run，全部是假红，白跑一轮。
25. ★全量回归用【一套件一进程】逐套件隔离（或至少 unit/integration 分开跑）；安静窗内串行执行，跑前 pgrep -fl jest。
