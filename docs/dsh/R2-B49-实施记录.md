## 2. 三态呈现（DSH_SUMMARY_MODE）
| 开关/情形 | 服务端 | 页面呈现 |
|---|---|---|
| off（或旧运行、未开启评语） | summary_session.generated=false、state=not_generated、cost_total=null；cost_split={judge:<判据费>,summary:null,total:<判据费>} | 评语格：**未生成评语（开关 off / 旧运行）**；合计只含判据费（不假 0）；提示条写明「未生成评语」 |
| cached 命中 | state=cached_hit、cache_hit=true、mode=cached | 「缓存命中（未新增模型调用）」+ 评语费用；提示条「评语已单独生成（缓存命中…）」 |
| cached 未命中 / always | state=generated、cache_hit=false | 「本次会话生成」+ 评语费用/tokens；提示条「评语已单独生成（本次会话生成…）」 |
| 老数据缺 cache_hit/mode | 由归档 out/summaries.json meta 推导（全命中 ⇒ cached_hit；混合 ⇒ generated；无 meta ⇒ cache_hit=null） | 命中/未命中可辨；确实无从判断 ⇒ 「生成方式未记录（旧数据）」 |

## 4. 后续（不在本批 inScope，供队长决策）
- B48 的 recordSummaryUsage（server/src/services/）目前只落 {tokens,cost_total,model,recorded_at}；若把 {mode,cache_hit,cache_hits,generated} 一并落库（一行改动，属 server/src/services/ ⇒ 需另开批次纳入 inScope），则**无需依赖归档**即可直接判三态（当前已按「usage_json 优先、归档 meta 兜底」实现，功能不受阻）。
