# R2-A26 总评入会话设计（自然语言总评由 DSH 改卷会话产出）

**结论摘要**
1. **现状核实**：总评目前由**事后脚本**产出（`server/scripts/gen-ai-summary.mjs`：读 `ai_feedback.breakdown` + rubric 快照 ⇒ 组 prompt ⇒ 调平台模型 ⇒ 读-改-写 `ai_feedback.summary`，payload 见 `:362-371`，须 `--apply`）；**改卷装置在复用路径根本不起会话**（`run.sh:58 MODE=measure-only` ⇒ `:368-372` 跳过会话；`lib_assignment.sh` S4 逐份只跑 `check.py`，`MEASURE_CALLS=0`）⇒ 要"改卷时产出"就必须**新增一次会话**。
2. **契约**：新增独立产物 `out/summaries.json`（`summaries/1`），**不写进 `check.py` 的 result 文档**（否则 `canonical_sha256`/stale 审计被污染）⇒ 判据确定性与分数路径零影响。
3. **推荐方案 D**＝"每次运行一个**批量评语会话**"＋"(content_key, 结果摘要哈希) 缓存"＋可关开关：成本 ≈ **¥0.10~0.25/运行（59 份）**（默认 `deepseek-flash` 档，`dshSessionUsage.js:50` 峰值 0.04/2/8 元·M）～ **¥0.6~1.2**（若用 `deepseek-v4-pro` 档，`:51` 峰值 0.30/9/27）⇒ **¥0.002~0.020/份**，与现状脚本同量级或更低。
4. ★**诚实结论**：缓存**不能**让"跨班同内容"变成零成本 —— 学生不同 ⇒ 结果不同 ⇒ 结果摘要哈希不同 ⇒ 必 miss；缓存真正省的是**重跑/重评/同结果**（命中 ⇒ 增量为 0）。"复用运行零 LLM"须改述为"**尺子零 LLM**；评语按需生成、单独计量、可关"。
5. **实施位置**（推荐 A2）：平台侧在**同一次运行的 run-root/DSH_HOME** 内起第二个会话（复用 `runDshGrader`）⇒ **装置 `scripts/dsh-grader/**` 零改动**（S3 夹具/闸/selftest 零回归），且会话消耗被 t3 取证自动计入 `grading_run_usage`。
6. 4 步：①消费与降级（含"重评不得抹评语"）②会话产出（fail-soft+预算）③缓存键/表 ④监测与展示口径。①必须先行；②③可并行；④依赖②。

## 2. 契约位置与格式

### 2.1 位置（三选一，推荐 ②）
① 装置内 S5 阶段（`lib_assignment.sh` 之后加 `--summary-mode`）：与产物同源，但改装置脚本 ⇒ 提示词/闸/S3 回归风险最大。
② **平台同运行第二会话**（`dshGradingJobWorker.runOnceInner` 在**装置跑完、`consumeMeasureResults` 之前**启动；`runDshGrader({command: DSH_GRADER_BIN, args:[--profile, headless, promptText], runRoot, extraEnv:{DSH_HOME:<run-root>/home}})`）：装置零改动、监测自动计入、离线可 stub。
③ 事后脚本（现状）：不在"改卷时"，且不进入运行监测。

### 2.2 `out/summaries.json`（`summaries/1`；一份一行，按 slug 键控）
```json
{"schema_version":"summaries/1","generated_at":"2026-10-13T05:00:00.000Z","model":"deepseek-v4-flash",
 "session_id":"…","prompt_version":"ai-summary/2",
 "items":[{"submission_id":"丁静45","text":"本次完成度较好，主要失分在…。建议先…。",
   "facts":{"passed":7,"total":9,"score":88,"failed_count":2,"failed_items":["P03","P07"]},
   "tokens":{"prompt":820,"completion":180,"reasoning":null,"cache_hit":0,"cache_miss":820},
   "cache":{"hit":false,"key":"sha256:…"},"truncated":false}]}
```
- 键控：`submission_id`=装置 slug（与 `deriveSlugMapFromRunRoot` 同口径，消费侧复用 `resolveSubmissionId:305`）；`items` 缺失/空/坏 JSON ⇒ **视为"无评语"**（不改分数、不改 job 终态）。
- 落库形状与脚本完全同构：`summary={text,facts{passed,total,score,failed_count,failed_items},model,prompt_version,tokens,generated_at,source:'session',session_id,cache_hit,truncated?}` ⇒ `parseCheckerFeedback.js:65-75` **零改动**。
- 归档：`archiveRun:523` 增拷 `out/summaries.json`（与 `grading-results.json` 并列）⇒ 审计可溯源到 run/job/session。

### 2.3 兼容与"装置只写允许产物"
- 方案②下 `scripts/dsh-grader/**` 与 `scripts/dsh-checker/**` **一行不改**；会话提示词由平台给出，**只允许写 `out/summaries.json`**，其余路径只读（与装置既有禁令一致）。
- 老数据：脚本已写的 `summary` 不受影响；新运行未产出 ⇒ 不写 `summary` 键 ⇒ 教师页回落旧面板（与 `gen-ai-summary` 之前行为一致）。
- 版本：`prompt_version` 升 `ai-summary/2`，并以 `source:'session'|'script'` 区分来源（审计可比对两代口径）。

## 3. 提示词与输出约束（对齐现口径 + 判据确定性隔离）
**system**（与 `gen-ai-summary.mjs:118-120` 逐句同义）：助教视角；2~4 句中文；①总体结论 ②失分点及**可能原因**（**只能依据给定的未通过项**，不得编造、不得臆测学生代码）③1 条可执行建议（具体到文件/类/方法或检查项）；禁止逐条复述、禁止客套话；**不得出现学生姓名/学号**（缓存可共享的前提）。
**user**：①本次得分 `score/max` 与 `passed/total/failed_count`；②未通过项 ≤12 条（`id｜title｜score/max｜comment 截断 300`，取自 `out/grading-result/<slug>.json`）；③rubric 节选 ≤1200 字（优先发布快照）；④**输出契约**：只输出 JSON 数组 `[{"submission_id":"…","text":"…"}]`，不要额外字段/标题/列表符号。
**确定性隔离**：会话**不得**写 `out/checker/**`、`out/measure/**`、`out/grading-result*/**`；平台侧仅读 `summaries.json`，分数与 stale 判定仍只来自 `listMeasureResults()/decideScoreWrite()`。批量 ≤N 份时**单次会话**完成（避免 N 次会话：dsh 启动开销 × `dsh_grading_concurrency=1` 串行会让 59 份变成小时级）。

## 4. ★成本模型：三方案对比与推荐
| 方案 | 生成时机 | 成本量级（59 份/运行） | 复杂度 | 风险 |
|---|---|---|---|---|
| (a) 每次运行都生成 | 每个运行一个批量会话 | **¥0.10~0.25**（flash 档）/ **¥0.6~1.2**（v4-pro 档）——59 份、输入 ~30–36k、输出 ~10.6k；单份 **¥0.002~0.020**（按内置价目 `dshSessionUsage.js:50-51`：flash peak 0.04/2/8、pro peak 0.30/9/27 元·M） | 中（会话+预算护栏） | 复用运行不再零 token；成本随份数线性 |
| (b) 按 (content_key, 结果摘要哈希) 缓存 | 同上，但先查缓存 | 首次同 (a)；**命中 ⇒ 0**；跨班首次 **0% 命中**（学生不同）、重评/重跑 **~100%** | 中+（表/键/失效/审计） | ★"同内容复用仍零成本"是**不成立**的期望，需向用户讲清 |
| (c) 仅 build 生成 | 只在造尺运行 | **≈0** | 低 | ★致命：生产常态是复用运行 ⇒ 只有 build 时 1~2 份学生有评语，第二班基本全空 |
**推荐 D＝(b)+(a)**：默认在**每个运行**（build 与 reuse 都）产出，命中缓存则跳过；`DSH_SUMMARY_MODE=off|cached|always`（生产默认 `cached`），并加**单运行预算护栏**（`DSH_SUMMARY_MAX_COST`，超限 ⇒ 停止生成、标 `summary_skipped=budget`，**不影响分数与 job 终态**）。数字依据：脚本实测 80 份≈¥0.4（≈¥0.005/份，含缓存命中与推理 token）；批量化后按上表单份上限 ¥0.020（v4-pro 档、无缓存命中）仍属同量级，默认 flash 档更低（≈¥0.002~0.004/份），且不再需要人工 `--apply`。

## 5. 平台消费路径
1. **worker**（`dshGradingJobWorker.runOnceInner`）：装置返回 0 且 `resolveCheckerPath` 成功后、`consumeMeasureResults` 之前 ⇒ `maybeGenerateSummaries()`（开关/预算/缓存）⇒ 写 `out/summaries.json`；失败只记 `SUMMARY_SESSION_FAILED reason=…`，**不改变 job 终态**（照常写分）。
2. **consumer**（`dshCheckerConsumer`）：新增 `loadSummaries(runRoot)`（纯读、坏 JSON 跳过）⇒ `buildWriteback({result, score, summary})` 注入 `ai_feedback.summary`；★`consumeMeasureResults`/`regradeWithStoredChecker` **必须传入已有 summary**（或改"保留既有 summary 键"的合并语义），否则重评会把总评抹掉 —— 这是本设计**最高优先**的兼容点。
3. **降级**：无 `summaries.json`/无该 slug/超预算/会话失败 ⇒ 不写 `summary` 键（教师页回落旧面板）；`summary_error` 记入运行日志与 `ai_feedback.summary_meta{attempted:true,error:…}`（可选，不参与渲染）。
4. **`gen-ai-summary.mjs` 定位**：**退役为回填/兜底**（历史作业、会话失败补录、教师手动重生成）；保留 `--apply`/`--force`/成本护栏不变；新旧产物同构 ⇒ 可混用。
5. **监测口径**：评语会话与批改会话共用 `<run-root>/home` ⇒ `captureSessionUsage` 自动计入（`session-usage.json` → `grading_run_usage`）；建议在 `usage_json` 增 `summary_session:{model_calls,output_tokens,cost}` 以区分"判据消耗/评语消耗"。★展示口径变化：启用评语后复用运行**不再是零 token**，t4 页面的"本次无模型会话（零 token）"只在 `mode=off`（或未起会话）时出现 —— 需同步文案：分列"判据 0 token / 评语 N token"。

## 6. 缓存键与表（采纳 b 时）
- **键**：`summary_key = sha256(content_key + '\n' + result_digest)`；`result_digest = sha256hex(canonical JSON of [{id,max_score,score,status}] + totals.score)`（**只含判据结果，不含学生身份** ⇒ 同结果必同键，也是"不许写学生姓名"的原因）。
- **失效**：rubric/标准包/描述变 ⇒ `content_key` 变 ⇒ 自然失效；判据变（尺子重造/结果不同）⇒ `result_digest` 变。
- **存放**：优先 **DB 表** `grading_summaries(summary_key CHAR(64) PK, content_key CHAR(64), model, prompt_version, text TEXT, tokens_json JSON, created_at, updated_at)`（跨机共享、可统计命中率）；运行目录 `out/summaries.json` 只作**当次产物**。
- **审计**：命中/新生成都必须落 `cache_hit` 与 `summary_key`，并在 `ai_feedback.summary` 里保留 `session_id`/`run_ref` ⇒ 每句评语可溯源到某次运行的证据（评分标准、`checker_id`、`canonical_sha256`）。

## 7. 风险清单（含最小应对）
| 风险 | 说明 | 应对 / 最小验证 |
|---|---|---|
| 确定性边界 | 评语是生成式、分数必须确定 | 评语独立文件；`canonical_sha256` 不覆盖它；分数只读 `out/measure`。验证：同尺同提交两次跑 ⇒ `ai_score/canonical_sha256` 逐位相同，只有 summary 变 |
| 重评抹评语 | `buildWriteback` 整体替换 `ai_feedback` | writeback 带 `summary`（或合并语义）。验证：有 summary 的提交跑 `regradeWithStoredChecker` ⇒ summary 仍在 |
| 成本失控 | 份数×运行次数 | 单运行预算 + 全局日预算 + `mode=off` 开关 + `max_tokens`（沿用 2000/放大重试）+ 超预算标 `summary_skipped`。验证：把预算设为 0 ⇒ 不生成绩语、分数照写 |
| 会话失败/离线/无 key | 模型不可达 | fail-soft（不影响写分）；`SUMMARY_SESSION_FAILED` 留痕；脚本兜底补录。验证：stub 返回非 0 ⇒ job 仍 done、评语缺省 |
| 装置提示词回归 | 仅方案①存在（改 run.sh/闸/夹具） | 本设计选②回避；①若要做，必须走 S3/selftest/shape_gate 全量回归 |
| 教师侧兼容 | 页面只认既有形状 | 保持 `{text,facts,truncated?}`；新增键只增不改。验证：无 summary 的旧数据渲染与改动前逐屏一致 |
| 展示语义漂移 | "零 LLM 运行"不再成立 | 分列判据/评语消耗（§5.5）。验证：`mode=off` 时 `no_model_session=1`；默认时含 summary 消耗 |
| 幻觉/编造 | 评语超出判据 | prompt 只给未通过项 + 禁止编造；`facts` 由平台计算（不采信模型）；文本长度上限（≤300 字/份） |

## 8. 最小实施步序（每步含验证）
1. **消费与降级（必须最先）**：`loadSummaries` + `buildWriteback(summary)` + 重评保留 + 归档 `summaries.json`。验证：单测夹具放 `out/summaries.json` ⇒ 断言写库 `summary`；不放 ⇒ `ai_feedback` 无 summary 键且渲染不变；`regradeWithStoredChecker` 后 summary 仍在。
2. **会话产出（fail-soft + 预算）**：worker 插 `maybeGenerateSummaries()`（`runDshGrader` + `DSH_HOME=<run-root>/home`）。验证：注入 `stub-dsh.sh`（`STUB_MODE=ok`）断言产出形状；`STUB_MODE=nonzero_noout` ⇒ job 仍 done 且仅留痕；预算 0 ⇒ 不生成。
3. **缓存键/表（可与 2 并行）**：migration（纯增量 + rollback）+ 命中/写回 + 命中率日志。验证：同 `(content_key,result_digest)` 二次运行 ⇒ 命中且零会话；改 rubric ⇒ `content_key` 变 ⇒ miss；改一份结果 ⇒ miss。
4. **监测与展示口径（依赖 2）**：`usage_json.summary_session` + `no_model_session` 文案分列 + 文档。验证：真机小样（1 作业 2 份）⇒ `grading_run_usage` 的 token/费用含评语部分；`mode=off` ⇒ 与现状逐位一致。
**并行/串行**：1 →（2 ∥ 3）→ 4；2 与 3 的接口（`summary_key` 计算与查表）先在 1 里定死。
