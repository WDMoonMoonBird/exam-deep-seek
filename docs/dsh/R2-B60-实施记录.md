## 1. 快速失败设计（`server/src/config/jwtSecret.js`）
| 输入 | 非生产（development/test） | 生产（NODE_ENV=production） |
|---|---|---|
| 缺失 / 空 / 非字符串 | **抛错**「JWT_SECRET 未配置：拒绝启动…」 | **抛错**（同上） |
| 命中弱值（`exam_system_fallback_secret`/`secret`/`changeme`…） | **抛错** | **抛错** |
| 长度 16~31 | 通过 + `[安全告警] JWT_SECRET 长度 N < 32…` | **抛错**「过短」 |
| 长度 <16 | **抛错** | **抛错** |
| 长度 ≥32 | 通过、无告警 | 通过 |
- 错误/告警**只含长度与环境**，从不打印密钥本身（用例断言 `message`/`warn` 不含密钥 ✗ 泄漏）。
- `getJwtSecret()` 进程内缓存 ⇒ `auth.js`（校验）与 `authController.js`（签发）拿到**同一密钥**；`__resetJwtSecretCache()` 供测试重置。
- 现状说明：`server/.env` 里的密钥长度 27 ⇒ 非生产放行并告警；**生产**必须换成 ≥32 随机串（部署前由队长配置；本批未改 `.env`）。

## 2. 测试（w68，8/8）
- 缺失/空/纯空白/非字符串 ⇒ 抛错；弱值（含 `CHANGEME` 大小写）⇒ 任何环境都抛；
- 短密钥边界：15 字符 ⇒ 抛；27 字符非生产 ⇒ 通过 + **恰一条**告警（含「32」且不含密钥）；27 字符**生产** ⇒ 抛；
- ≥32 ⇒ 通过且零告警；抛错消息不含密钥；`getJwtSecret` 缓存同一值（第二个 env 被忽略）；
- `jwt.sign` + `jwt.verify` 用同一密钥 round-trip 通过、换密钥则 verify 失败；
- **仓库静态断言**：`server/src/**`（剥注释）不存在 `process.env.JWT_SECRET ||` 写法；`exam_system_fallback_secret` 只出现在 `config/jwtSecret.js` 弱值清单；`middleware/auth.js` 与 `controllers/authController.js` 都引用 `getJwtSecret`（唯一来源）。
