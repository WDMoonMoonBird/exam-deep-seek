## 1 F-C1（高）隔离归因盲区 —— 已关闭
**原问题**：`classify_changes.py` 对 `cache/ memories/ llm-deepseek/ sessions/ storages/ attachments/` 做无条件豁免，
于是「漏 export DSH_HOME ⇒ 子进程写真实 home」这一类失败仍会报 `isolation=PASS`（只有含子会话 id 的路径能被抓）。
**改成什么**（`classify_changes.py` 头部有完整判据表）：

| 规则 | 含义 | 归类 |
|---|---|---|
| R1 | 路径含【子进程路径指纹】（子会话 id / 隔离 home 路径或其 slug / workdir 路径或其 slug） | CHILD（FAIL） |
| R2 | 文件内容「变化窗口」含【子进程内容指纹】（子会话 id / 隔离 home 路径） | CHILD（FAIL） |
| R3 | 路径在 `<real-home>/profiles/` 下 | CHILD（FAIL） |
| R4 | 路径含 UUID 会话 id 且 ≠ 子会话 id | HOST |
| R5 | 该路径在「3 秒空窗对照」里也变化过 | HOST |
| R6 | 宿主共享存储目录下、文件存在、内容窗口扫描干净 | HOST |
| R6b | 同上目录，且本次是删除 | HOST |
| R7 | 其余（文件不存在/读不到/无法归因） | UNATTRIBUTED（FAIL） |
| R8 | 路径不在真实 home 下 | OTHER（FAIL） |

内容窗口 = 新状态尾部 `max(新size-旧size,0)+4096` 字节、单文件上限 8 MiB（聚焦本次变化，避免历史内容误伤）；
输出新增 `__UNATTRIBUTED__` 段、`__REASONS__`（每条变化的判据原文）、`__SUMMARY__`；`isolation-report.txt` 增
`changed_child_write / changed_unattributed / changed_other / verdict_reasons`。

**复算命令**
```
bash scripts/dsh-grader/selftest.sh                     # 其中 F-C1 段：阳性 3 + 阴性 2 + classifier 单元四态
# 端到端阳性对照（零模型调用，沙箱真实 home）：
DSH_GRADER_REAL_HOME=<沙箱>/.dsh DSH_GRADER_SIMULATE_LEAK=profile-dir \
  bash scripts/dsh-grader/run.sh --submissions 1 --workdir <w> --timeout 900 --dry-run
```
**真实输出（阳性对照，摘 `isolation-report.txt`）**
```
changed_total=1  changed_child_write=1  changed_unattributed=0  changed_other=0  changed_host=0
verdict=FAIL          verdict_reasons=child-write
RULE R3-CHILD-PROFILE <沙箱>/.dsh/profiles/headless/cordis.yml :: profiles dir under real home
```
另两个阳性对照：`workdir-slug` → `RULE R1-CHILD-PATH … sessions/--…-…--/<id>/… :: path fingerprint=…`；
`content-fingerprint` → `RULE R2-CHILD-CONTENT …/memories/daily/simulated-leak.md :: content fingerprint=<隔离 home>`（三者均 verdict=FAIL、rc=1）。
**阴性对照（证明没有变成「永远 FAIL」）**：`host-delete` → verdict=PASS、rc=0；干净 dry-run → verdict=PASS、rc=0。
**该判据如何被证伪**（残余洞，已写进 README）：若存在一种未隔离写入，其路径既不含子进程指纹、内容也不含子进程指纹，
且落在宿主共享存储里且内容窗口「干净」——R6 会把它误判为 HOST。已用「路径 slug（workdir 编码）+ 内容指纹（隔离 home 路径）+
profiles 目录」三条独立通道把已知的泄漏形态都覆盖；要推翻本判据，只需构造出上面那种反例并喂给
`classify_changes.py`（本目录的 selftest 已把「喂合成 diff」这一步做成可复算的单元用例）。

SESSION_FAIL：丁静45 会话退出码 rc=3 child_exit=3 ≠ 0 ⇒ 不得判 PASS（F-C2）；产物仅供诊断
EXTRACT_DIAGNOSTIC：丁静45 产物已提取（source=file fallback=none）但会话退出码非 0 ⇒ 不计入成功（F-C2）

## 3 F-C3（中）DSH_HOME 硬护栏 —— 已关闭
**改了什么**：`lib.sh` 新增 `guard_isolated_home()`：非空 / 绝对路径 / ≠ `$DSH_GRADER_REAL_HOME`（默认 `~/.dsh`）/
≠ `~/.dsh` / ≠ `$HOME` / 必须位于临时目录（`/tmp`、`/private/tmp`、`/var/folders`、`$TMPDIR`）之下；
`dsh_bin`、`scaffold_home`、`install_credentials` 都前置调用，`run.sh`/`probe.sh` 在算完 HOME_DIR 后立刻断言
（顺序上**先护栏后加锁**，避免被拒时留下锁目录）。可用 `DSH_GRADER_ISOLATED_HOME` 覆盖隔离 home（覆盖值同样过护栏）。
**复算命令与真实输出**
```
$ bash <沙箱>/guard.sh ""            → rc=2  guard: DSH_HOME 未设置/为空 —— 拒绝调用 dsh（F-C3）
$ bash <沙箱>/guard.sh <沙箱>/.dsh    → rc=2  guard: DSH_HOME 不能是真实 home：…（F-C3，拒绝调用 dsh）
$ bash <沙箱>/guard.sh ~/.dsh        → rc=2  guard: DSH_HOME 不能是 ~/.dsh（F-C3，拒绝调用 dsh）
$ bash <沙箱>/guard.sh /etc          → rc=2  guard: DSH_HOME 必须位于临时目录下…
$ bash <沙箱>/guard.sh <沙箱>/iso/home → rc=0  GUARD_ACCEPTED
$ DSH_GRADER_ISOLATED_HOME=<沙箱>/.dsh bash scripts/dsh-grader/probe.sh --workdir <w> → rc=2（stub 调用数 0→0）
$ DSH_GRADER_ISOLATED_HOME=~/.dsh      bash scripts/dsh-grader/run.sh  --submissions 1 … → rc=2（stub 调用数不变）
```
**证伪方式**：若你能让任一脚本在被拒的 DSH_HOME 下**仍然调用到 dsh**，护栏即失效——selftest 用
`STUB_CALL_LOG` 记录 stub 调用次数并断言「拒绝后调用数不变」（对应复发判据：`~/.dsh/profiles/headless` 再现、
`~/.dsh/sessions/` 出现 tmp slug、`~/.dsh/.credentials.yaml` mtime 被改）。

## 4 F-C4（中）--workdir 原子锁 —— 已关闭
**改了什么**：`acquire_workdir_lock()` 用 `mkdir "$WORKDIR/.dsh-grader.lock"` 原子获取，写 `owner.txt`（pid/started）；
拿不到锁时读 owner：**进程还活着就立即 die（rc=2，指出 pid）**；owner 已死则记「陈旧锁 → 接管」并留痕；
锁内清理（materials/home/out）只在拿到锁之后执行；`cleanup()` 里 `release_workdir_lock`。
**复算命令与真实输出**（见证据 11）
```
$ STUB_MODE=ok STUB_SLEEP=6 bash scripts/dsh-grader/run.sh --submissions 1 --workdir <w> --timeout 900 &
$ bash scripts/dsh-grader/run.sh --submissions 1 --workdir <w> --timeout 900   # 第二次
[FATAL] workdir 已被 pid=12067 占用（<w>/.dsh-grader.lock）：同一 --workdir 不允许并发运行（F-C4）；请换 --workdir 或等它结束
rc=2；首次 in-flight 工件仍在：out/logs/session-s01.out、materials/materials-manifest.json；首次最终 rc=0；退出后锁已释放
```
**证伪方式**：同 workdir 两次并发、第二次不被拒（或首次 in-flight 工件被删）即为失效——selftest 的 F-C4 段
（4 条断言：立即失败 / 给出占用者 / in-flight 存活 / 首次成功 + 锁释放）就是复现脚本。

## 5 F-C5（低）stdout 回退口径 —— 已关闭（按队长裁定）
**裁定**：结果**必须**来自模型自写的产物文件；回退默认关闭、不可静默、运行摘要必须可见。
**改了什么**：`extract_result.py` 默认不读 stdout——没有可用文件就 `EXTRACT_FALLBACK=refused` + `EXTRACT_OK=0 reason=no-file-artifact` + rc=1；
只有显式 `--allow-stdout-fallback`（run.sh 同名开关）才回退，并输出 `EXTRACT_SOURCE=stdout-fallback`、`EXTRACT_FALLBACK=explicit`；
摘要打印 `RUN_RESULT_SOURCE=<slug>:<source>/<fallback>` 与 `stdout_fallback_enabled=0|1`。
**真实输出**
```
（默认，STUB_MODE=stdout_only）EXTRACT_SOURCE=none / EXTRACT_FALLBACK=refused / EXTRACT_OK=0 reason=no-file-artifact → 运行 rc=1，无 grading-result.json
（显式）EXTRACT_SOURCE=stdout-fallback / EXTRACT_FALLBACK=explicit / EXTRACT_OK=1 → RUN_RESULT_SOURCE=s01:stdout-fallback/explicit stdout_fallback_enabled=1
（正常）RUN_RESULT_SOURCE=s01:file/none  stdout_fallback_enabled=0
```
**证伪方式**：出现 `GRADED … source=stdout`（旧记号）或「没有模型产物却写出 out/grading-result.json」即为失效——selftest 有对应断言。

## 8 selftest 抓出的 3 个新 bug（本轮自纠）
1. **bash 3.2 `local` 展开陷阱**：`local wd="$1" lock="$wd/…"` 里第二个变量在展开时 `wd` 还是空的 ⇒ `unbound variable`，
   锁函数直接崩。已拆成三行 `local`。
2. **锁形同虚设**：`printf 'pid=%s' "$$"` 缺换行，与 `started=` 粘成 `pid=12067started=…` ⇒ `kill -0` 永远失败 ⇒
   任何第二次运行都判「陈旧锁」并接管（selftest 的「失败信息给出占用者」断言当场报 FAIL）。已改为一次 printf 带 `\n`。
3. **pipefail 提前退出**：隔离报告块里 `sed | grep -v ^__ | head -40` 在无匹配时 grep 返回 1 ⇒ 整个 run.sh 在写摘要前退出
   （表现为「verdict=PASS 却 rc=1」）。已加 `|| true`。

## 9 未验证 / 无法核验项（单列）
1. **PTC/desktop 形态**下的执行工具隐藏仍未验证（本轮只覆盖 headless profile + 本装置 patch）。
2. **内容指纹的假阳性风险**：若其它活跃会话在自己的记忆/日志里**原样引用**本装置的隔离 home 绝对路径，
   R2 会把该文件判成 CHILD（fail-closed）。本轮 3 次真实运行未出现（smoke2：changed=12 全 HOST）；
   规避方式是让隔离 home 用随机 mktemp 路径（默认行为）。
3. **锁的陈旧判定依赖 pid 存活**：pid 复用极端情况下可能把活着的他人进程当自己（概率极低，已用「接管留痕」暴露）。
4. `run.sh --submissions >1` 的多份并发/串行口径未在本轮重测（本轮只跑 1 份）。
