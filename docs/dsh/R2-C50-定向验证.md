## F1（阻断）：守卫的 import 抽取器隔条跳过 ⇒ 取数页可被静默豁免

- ① 真实仓库（验证时刻，日志记 sha）：
  - `client/src/views/teacher/ProjectReviewNew.vue`（sha 2c88f996，442 行）声明静态 ⇒ 门禁 **guard=PASS、获豁免**；独立闭包命中 `../../api/projects.js`（经 `composables/projectReviewNew/useProjectReviewPage.js`）。
  - `client/src/views/teacher/Assignments.vue`（sha 2cba2cc0，426 行）声明静态 ⇒ **guard=PASS、获豁免**；独立闭包命中 `composables/assignments/useAssignmentsPage.js`。
  - 对照 `client/src/views/student/Submit.vue`（631 行）⇒ 正确判红（链：useSubmitPage.js ⇒ useCountdown.js ⇒ api/request.js）。
- ② 镜像 A/B 夹具（语义等价、只有 import 顺序不同）：PageA（composable 的 API import 是第 1 条）判红；**PageB（仅多一行 `import { ref } from 'vue';` 在它前面）被静默豁免**。
- ③ PageC（页面自身 `import request from '../../api/request.js';` 位于第 2 条 import、无 `request.get(` 调用形式）被静默豁免。
- ④ 根因（白盒）：`extractImports` 对 `[vue, api/request.js, helper.js, other.js]` 四条连续单行 import 只抽到 `[vue, ./helper.js]`。
  `static-exempt.mjs` 内层循环从 `i+1` 起累积 `text` 并对整段匹配 `from`：单行 import 在第 i 行就已命中，却 push `j+1` 行号并 `i=j`，把下一条 import 整条吞掉（行号同时偏移）。
- 影响：只要"取数 import"落在被跳过的位置（真实拆分后的页面极易命中），白名单文件即被判干净 ⇒ 从 GodFile 判据集合移出。B63 的核心承诺（"声明为静态却含 I/O ⇒ FAIL"）不成立；同理，"守卫 0 违规"不能作为"白名单内确实无 I/O"的证据。
- 建议修复：单行优先匹配（`^\s*(?:import|export)\b[^\n]*?\bfrom\s*(['"])([^'"]+)\1` 命中即 push 并 continue，不推进 i），仅当本行无 `from` 时才向后拼接多行；自测补两条必红用例：白名单文件的 I/O import 处于第 2/4 条、A/B 夹具 PageB/PageC。
