# R2-B19 实施记录（时钟异常（未来时刻）僵尸行处置 + 测试基建孤儿清理）

## 摘要（≤10 行）
1. **缺口（F-T66-1，high）**：回收判据是 `updated_at < 现在-阈值`；若某行 `updated_at` 落在**未来**（时钟异常/探针/跨机漂移），它**永远不满足判据** ⇒ 永久占住 DB 级闸（limit=1）⇒ 后续所有窗口**静默停摆**。实证：t66 首轮 verify 因一条未来探针行导致 12 个 worker 系套件集体 `consumed=false` 假失败。
2. **★修法**：回收器增加**相位 2（时钟异常）**——`updated_at > UTC_TIMESTAMP(3) + 容差` ⇒ 按 attempts 规则处置：未用尽置 `pending`（`last_error=stale_running_clock_ahead`）、用尽置 `failed`（`stale_running_clock_ahead_exhausted`）、同对已有 pending 走既有防御分支（`stale_running_clock_ahead_conflict`）；处置时把 `updated_at` **归位**到当前 UTC（恢复判据语义）。
3. **容差可配**：`DSH_WORKER_CLOCK_TOLERANCE_MS`（缺省 **60s**，允许 0，非法值回退），`parseWorkerConfig` 暴露 `clockToleranceMs`，`WORKER_START` 打印 `clock_tolerance_ms=`。
4. **留痕（不静默）**：摘要行 `STALE_RECLAIMED n=… to_pending=… to_failed=… conflicts=… clock_ahead=<n> stale_ms=… clock_tolerance_ms=…`；`details[]` 每项带 `phase='expired'|'clock_ahead'`；`logger.warn` 结构化记录。
5. **不误伤**：容差内（含 +30s 与新鲜行）实测保持 `running`、`last_error` 仍 `null`、不出现在 `details`；相位 2 的更新同样带条件（`status='running' AND updated_at > now+容差`）⇒ 并发安全。
6. **★闸解锁端到端（w44-5）**：按生产领取语句把 pending 置 running（正常量）⇒ 把 `updated_at` 推到 +2h ⇒ `runOnce(dbLimit=1)` **领不到**（复现事故）⇒ 回收相位 2 ⇒ 再 `runOnce` ⇒ **领取并完成**（`done`/`written_count=1`/`ai_score=83`）。
7. **★测试基建（F-T66-2）**：`server/test/setup.js` 新增 `cleanupOrphanGradingRows()` 并在 seed 入口调用：删除 `assignment_id` **已不存在**的 `grading_jobs`/`grading_checkers`/`grading_assignment_anchors`。**边界**：只删「外键目标已不存在」的行，任何 assignment 仍存在的行一行不动（w44-6 正反双向断言 ✓）；seed 实跑打 `ORPHAN_GRADING_CLEANUP jobs=… checkers=… anchors=…`。
8. **测试**：新增 w44（7 例全绿）：容差解析 / 未来行处置 / 容差内不误伤 / 用尽 ⇒ failed / 冲突防御分支 / 闸解锁端到端 / 孤儿清理边界。
9. **verify（串行）**：check-layers 0 违规；unit 54 套件/715 例；contract 3/50；三重度 17/61/21；integration 57 套件/429 例；smoke 8/8；生产库指纹 before/after **逐位相同**。
10. 三种时钟口径对照表见 §2；未验证项与自纠见 §5/§6。

## 2 ★三种时钟口径对照表（排障用）
| 情形 | 现象 | 判据 / 处置 | 实测 |
|---|---|---|---|
| **正常过期** | 行 `updated_at` 早于阈值（真僵尸） | `updated_at < UTC_TIMESTAMP(3) - 阈值` ⇒ pending（`stale_running_reclaimed`）/ failed（`stale_running_exhausted`） | w42-1、w43-1（30 分钟前 ⇒ 回收） |
| **会话口径差异** | 同一列被「会话本地时钟」写过（历史/旧版本写方） | 统一用 **UTC** 判据；若行由会话时钟写入且相对 UTC 在未来 ⇒ 落入「未来时刻」分支；本轮实测偏移 28800s（UTC+8） | w43-2（`session_age=1800` 而 `utc_age=-27000` ⇒ 不满足过期判据）、W43-6（两写方均 UTC ⇒ `utc_age=0`） |
| **★未来时刻（时钟异常）** | `updated_at > 现在 + 容差`（探针/手工/跨机漂移）⇒ **永远不会过期**、永久占闸 | 相位 2：`updated_at > UTC_TIMESTAMP(3) + 容差` ⇒ pending（`stale_running_clock_ahead`）/ failed（`..._exhausted`）/ 冲突（`..._conflict`），并把 `updated_at` 归位 | w44-1（+2h ⇒ pending + `clock_ahead=1`）、w44-3（用尽 ⇒ failed）、w44-5（闸解锁端到端） |
| 容差内 | `0 < 未来偏移 ≤ 容差`（正常并发写/轻微漂移） | **不动** | w44-2（+30s、新鲜行均保持 running） |

## 4 测试基建清理的范围与边界
- **范围**：`grading_jobs`、`grading_checkers`、`grading_assignment_anchors` 中 `assignment_id NOT IN (SELECT id FROM assignments)` 的行（三类都有该列语义；anchor 表用原始 SQL，客户端未生成该模型）。
- **边界**：判据是「外键目标已不存在」——只要 assignment 还在（含所有在产作业与测试夹具作业），其 job/checker/锚点**一行都不删**；w44-6 用「真作业的 job」做正向边界断言。
- **失败容错**：任一 DELETE 异常按 0 计（不阻断 seed）。

## 5 未验证项（单列）
1. **真实生产窗口**未跑（不写生产）：机制在测试库端到端验证；生产首个窗口请核对 `STALE_RECLAIMED … clock_ahead=<n> clock_tolerance_ms=60000`。
2. **容差的跨机漂移实测**未做：本环境两写方同为 UTC（偏移 0）；跨机时钟漂移（NTP 未同步）下的容差取值建议（≥ 最大漂移的 2 倍）已写入文档，但未实测。
3. **未来行 + 活动键冲突的真实数据**未构造（DB 层活动键禁止同对两条活动行）⇒ 冲突路径仅以假 prisma 直测（w44-4）。
4. **孤儿行的历史规模**未统计：清理是「顺手清」而非「定期任务」；如需常态化，建议复用回收器的启动相位（已在 worker 启动路径之外单列，未纳入本轮的 worker 启动序列）。

## 6 自纠清单
1. **两次编辑叠加导致重复行**：`clockToleranceMs` 在 runtime 与 worker 各出现两次（worker 侧重复 `const` 会直接语法错误）⇒ 用精确 old_string 去重后 `node --check` 通过；教训：连续同文件编辑失败后，先读回实际内容再补。
2. **插在 `export` 之后的注释块**：`setup.js` 里我在 `export ` 与其后的 `async function seedTestData()` 之间插入了函数 ⇒ 产生 `export /**` 语法错误 ⇒ 改为整块替换（含 `export`）修复。
