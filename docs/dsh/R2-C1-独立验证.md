## 5 Findings（needs_revision）
**F-R2C1-1（中）回滚脚本守卫顺序错误 + 缺列时不可用**
- 现象：`rollback-snapshots.js` 先 `new PrismaClient(...)` 并执行 `buildRollbackSelectSql()`，之后才做白名单判断（dry-run 也在连接之后）。实测：
  - `node server/prisma/scripts/rollback-snapshots.js --dry-run --db-url <test>` → **rc=1**、`ROLLBACK_ERROR Invalid \`prisma.$queryRawUnsafe()\` … Unknown column 'snapshot_origin' in 'where clause'`（当前快照列未落地 ⇒ 无法 dry-run）；
  - `node … --apply --allow-db exam_system_test --db-url <生产URL>` → **rc=1**（同一异常）：说明它**已连上生产库并发出查询**，白名单守卫**根本没生效**；与 backfill（`--apply` 生产 URL ⇒ rc=2 且连库前拒绝）口径不一致。
- 影响：写风险仍为零（UPDATE 在守卫之后，任何写入路径都不可达），但（a）"生产库连都不连"这一安全性质在回滚脚本上**不成立**；（b）**回滚路径在当前部署状态下不可用、不可验证**（rc=1 异常而非明确前置条件）；（c）w8 单测只覆盖 backfill 导出的 `assertApplyAllowed`，未覆盖回滚 CLI 的守卫时机 ⇒ 该缺口不可见。
- 最小复现（零风险，只读）：`cd server && node prisma/scripts/rollback-snapshots.js --dry-run --db-url "$(grep -m1 '^DATABASE_URL=' .env | cut -d= -f2-)"`（或任意测试库 URL）⇒ rc=1 + ROLLBACK_ERROR。
- 要求修复：把白名单/生产库判定**前置到 `new PrismaClient(...)` 之前**（与 backfill 的 `assertApplyAllowed` 同结构，并导出供单测直测）；快照列缺失时按 `RESULT=PRECONDITION_MIGRATION_NOT_APPLIED` **exit 3** 返回而非抛异常；w8 增补「回滚 CLI 生产 URL ⇒ rc=2 且不发生任何连接/查询」的断言。

**F-R2C1-2（低）t26 记录的 contract 数字与仓库实际不符**
- t26 记录：`contract: 8 套件 / 86 例`；实测：`server/test/contract/*.test.js` 只有 **3 个**（`use-cases-contract`、`ports-contract`、`extensibility`），**50 例全过**（rc=0）。
- 最小复现：`ls server/test/contract/*.test.js | wc -l` → 3；`npx jest --config test/jest.config.js --runInBand --forceExit test/contract` → `Test Suites: 3 passed, 3 total | Tests: 50 passed, 50 total`。
- 要求：修正记录中的 contract 基线数字（不影响代码结论）。

**F-R2C1-3（低，口径/环境）重度套件不得与主组同进程**
- 现象：把 `fact-extractor`/`rule-executor` 与主组放进**同一 jest 进程** ⇒ 稳定复现 **2 套件 22 例失败**：`TypeError: Cannot read properties of undefined (reading 'type')` at `src/infrastructure/rule/syntax.js:44`（tree-sitter 解析在批量进程下失效）；按项目自身 `npm test` 口径**各自单跑则 17/61/21 全绿**。
- 另：**缺 `NODE_OPTIONS=--experimental-vm-modules`** 时 47/47 套件 parse 失败、0 例执行（环境缺变量，非回归；队长已 amend 契约命令）。
