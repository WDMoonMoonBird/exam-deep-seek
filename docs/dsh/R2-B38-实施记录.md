## 1. 日志全量下载（`server/src/controllers/adminGradingRunsController.js`）

## 5. flake 隔离（`server/test/setup.js`）+ 连跑 3 次
- **根因（t3/t4 实测）**：多个 jest 进程并发时，`seedTestData()` 的「先删后插」撞上
  `Foreign key constraint violated: class_id` / `Duplicate entry` / 死锁 ⇒ `beforeAll` 抛错 ⇒ 表现「套件失败但 0 例失败」，同一命令退出码随机变红。
- **修法**：`seedTestData` 改为**重试包装**（`seedTestDataOnce` 为原体）：只对明确的 DB 争用签名重试（最多 5 次、`200*i+抖动` ms 退避、留痕
  `SEED_RETRY attempt=i/5 wait_ms=… reason=db_contention`）；护栏拒绝/连接失败/SQL 语法等**一律原样抛出**（不掩盖真实缺陷）。
- **连跑 3 次结果**：见 §7（同一 verify 命令逐字复跑，退出码与逐段摘要留档 `/tmp/b38-verify3.log`）。

## 8. 队长追加项 O1–O4 的处置（scope 经队长 amend 补齐）
- **O4（w59-1 反例断言可归因）✓ 已修**：夹具改为「候选作业快照 = bare hex64 / 目标内容快照 = `sha256:<…>`」两侧**形状与取值确实不同**；
  断言改为**按 `checker_id` 定位本候选行**的 `RULER_ADOPT_SKIP`（同库其它锚点行的同名 reason 不再能凑数），并附**正向对照**：
  同一夹具、同一行、只把候选快照改回正常形状 ⇒ 该行被 `adopted`（判据「能失败也能通过」）。变异 M1（两侧都改回 bare hex64）⇒ W59-1 rc=1。
- **O2（`grading_jobs.last_error` 双前缀 `ruler_ruler_failed:`）✓ 已修，收口方式 = (A)：worker 幂等前缀 + store 前缀归一**
  （队长决策并把 `server/src/services/dshGradingJobWorker.js` 加入 inScope）：
  · worker 新增 `withRulerPrefix()`：reason 已带 `ruler_` 家族前缀时**原样返回**，否则补 `ruler_`；349/351/370 三处（含 `CHECKER_REUSE=none … reason=` 日志行）统一改用它；
  · store 新增 `composeFailedReason()`：剥离 last_error 已有的 `ruler_failed:`/`ruler_` 前缀后再拼一层，防 `ruler_failed:ruler_failed:…` 嵌套；
  · **实测样例**：W59-5 断言 `last_error` **以 `ruler_failed:` 开头**、**不含 `ruler_ruler_`**、且保留原因尾巴（`夹具：装置造尺失败`）；
    `withRulerPrefix('ruler_failed:x')==='ruler_failed:x'`、`withRulerPrefix('cfg_missing')==='ruler_cfg_missing'`、`composeFailedReason('ruler_failed:嵌套')==='ruler_failed:嵌套'`；
    变异 M5（幂等退回裸拼接）⇒ W59-5 rc=1；变异 M3（store 归一退回裸前缀）⇒ W59-8 rc=1。
- **O1（遗留锚点无 `checker_raw` 的字节重序列化）✓ 已修**：`registerRulerFromLocalChecker()` 明确**优先**锚点原始字节（`source=anchor_raw`，逐字节原样）；
  无原始字节时才走 `checker_json` 重序列化，此时**必须与锚点 `frozen_sha256` 对账**：不一致 ⇒ **拒绝登记**并留痕
  `RULER_INGEST_SKIP reason=reserialized_frozen_mismatch`（理由：该尺子按 content_key 全局共享，而装置 frozen 预检必然拒收 ⇒ 永远不产分，
  比「不登记、走正常造尺」更差）；无 `frozen_sha256` 可对账时允许登记但**明确留痕** `source=checker_json_reserialized` 与「★重序列化登记路径」。
  变异 M2（删掉对账）⇒ W59-8 rc=1。
- **O3（r2b7 复用路径 `MODEL_CALLS=0`）✓ 已记档**：该值是 `scripts/r2b7-build-checker.mjs` 的**脚本显式输出**（复用命中时不跑模型会话，
  脚本按「本次未起模型会话」显式打印），**不是装置侧推导值** ⇒ 只作「本路径未起模型会话」的标记，不得当作「模型确实调用 0 次」的证据。
