# R2-C4 独立验证（批4：job 执行器 + 闸=1 + 不写分 + ★跨系统联调）

## 结论摘要（10 行）
1. **verdict = needs_revision**（任务按 failed 提交）：批4 的执行器骨架（领取/闸/超时/双领取/不写分决策）**全部通过**，但**跨系统联调暴露一条阻断缺陷**——真实装置产物与平台提交 id 无映射，回写静默空写却把 job 报成 `done/written=N`（F-R2C4-1，高）；另 O-1 复核不达标（F-R2C4-2，中）。
2. **★跨系统联调（本轮核心）**：真实拉起装置 **1 次**（`MODEL_CALLS=1`、`ASSIGNMENT_RESULT=PASS N=2`、`CHECKER_ID=sha256:0972d185…`、`REBUILDS=0`、`RUN_EXIT=0`），把真实产物喂给平台消费路径：
   - **产物原样**（装置 slug：`submission.id='s01'/'s02'`）⇒ worker 返回 `status=done / written=2 / skipped=0`，job 行 `done / written_count=2`，**但目标提交 `ai_score` 仍为 NULL（零写入）** ⇒ 假成功（见 F-R2C4-1）。
   - **产物 id 映射为平台提交 id** 后 ⇒ **写分成功**：`ai_score=59`、`checker_id=sha256:0972d185…`、`canonical_sha256=b7474d7e…`、`grading_stale=0`，`aiFeedback` 含 49 项 breakdown ⇒ **平台消费路径本身正确**。
3. **stub 端到端【通过】**：自跑 `node scripts/r2b4-smoke.mjs` ⇒ `R2B4_SMOKE=PASS checks=6 failed=0`（consume_ok_path / exit6_no_score / artifacts_missing_needs_rerun / gate_full_keeps_pending / timeout_retryable / no_double_consume），状态流转与 B 声明一致。
4. **闸=1【通过】**：两个 pending job，第一次占用闸后第二次立即 `consumed=false / reason=gate_full`，第二个 job 保持 `pending / attempts=0`（时序证据见 §3）。
5. **★四类不写分【通过（单产物口径）】**：exit6 / score=null / stale / unsupported 四种单产物 run-root ⇒ job 全部 `needs_rerun`、`written_count=0`、提交 `ai_score` 保持 NULL；正常产物 ⇒ 写分且带 `checker_id`+`canonical_sha256`。

## 2 ★跨系统联调（真实产物 → 平台消费）
| 用例 | worker 返回 | job 行 | 提交行（读回） |
|---|---|---|---|
| A 真实产物原样（id=`s01`/`s02`） | `status=done, written=2, skipped=0` | `done, written_count=2, attempts=1` | **`ai_score=null`、`checker_id=null`、`canonical=null`**（零写入） |
| B 真实产物 + id 映射为平台提交 id | `status=done, written=2, skipped=0` | `done, written_count=2` | **`ai_score=59`、`checker_id=sha256:0972d185…`、`canonical_sha256=b7474d7e…`、`grading_stale=0`**、`aiFeedback` 49 项 breakdown |

- 结论：**平台消费路径正确**；缺口在**装置 slug ↔ 平台 submission id 的映射契约**与**写入计数口径**。

## 3 闸=1（时序）
```
第一次 runOnce（慢装置，占用闸）→ consumed=true, status=done
150ms 后第二次 runOnce（另一个 pending job）→ consumed=false, reason=gate_full
第二个 job 事后核对：status=pending, attempts=0, written_count=0（未被领取、未被拉起）
```
⇒ 闸=1 生效：同一时刻只有一个 job 被拉起。

## 4 四类不写分（单产物公平口径）
| mode | worker 返回 | job 行 | 提交 `ai_score` |
|---|---|---|---|
| `exit6` | `needs_rerun` | `needs_rerun, written_count=0, error=device_exit_6` | NULL |
| `null`（totals.score=null + exit 6） | `needs_rerun` | `needs_rerun, written_count=0, error=device_exit_6` | NULL |
| `stale` | `needs_rerun, skipped=1, error=all_needs_rerun:stale_true` | `needs_rerun, written_count=0` | NULL |
| `unsupported` | `needs_rerun, skipped=1, error=all_needs_rerun:unsupported_items:1` | `needs_rerun, written_count=0` | NULL |
| `正常`（映射后） | `done, written=1` | `done, written_count=1` | 59 + `checker_id` + `canonical_sha256` |
- 混合产物口径说明：同一 job 里若既有可写份又有不可写份，job 状态由 `written>0` 决定为 `done`，不可写份记入 `skipped`/reason（设计如此）。

## 5 ★O-1 复核（小数分口径与可追溯性）
- 构造真实 checker + 产物 `totals.score=62.5` ⇒ 平台写入后读回：`ai_score=62`（**截断**，列类型 INT）、`aiFeedback` 键集合 = `[source, checker_id, canonical_sha256, max_score, aggregate, breakdown]`，**`feedback.includes('62.5') === false`**；breakdown 为逐项分（之和不等于 62.5，本轮为 59）。
- 结论：**"原始分可在 aiFeedback 中追溯"不成立**（F-R2C4-2）。

## 6 Findings（needs_revision 依据）
**F-R2C4-1（高，阻断跨系统路径）真实装置产物无法回写，却被报成成功**
- 现象：装置产物以 **slug** 为 `submission.id`（`s01/s02`），而 `consumeMeasureResults` 只对 `Number(result.submission.id)` 有限的值执行 `prisma.submission.update`；`Number('s01')` = NaN ⇒ **静默跳过**，但 `written` 计的是**决策**（`write=true`）而非实际更新 ⇒ job 标 `done/written=2`，用户会以为已批改。
- 最小复现：`node /tmp/t36/c4-probe.mjs` 的 `A_realUnmapped` 分支（真实 run-root 原样消费）⇒ `status=done, written=2` 且提交行 `ai_score=null`；对照 `B_realMapped` ⇒ `ai_score=59`。
- 要求修复：① 建立 slug↔平台提交 id 的映射（装置侧按平台 id 命名产物，或 worker 在消费前重写 `submission.id`，或 `--submission-id` 逐份传入）；② `written` 只在 `prisma.submission.update` 成功后 +1，未映射/未命中的份记 `needs_rerun`（reason 如 `unmapped_submission_id:s01`），禁止出现"决策可写但实际未写"时 job=done；③ 增补集成测试：真实装置 run-root（slug 命名）经 worker 消费后，要么真写分、要么 needs_rerun。

**F-R2C4-2（中）小数分静默截断且原始分不可追溯（O-1 未闭合）**
- 现象：`totals.score=62.5` ⇒ `ai_score=62`（INT 截断），`aiFeedback` 无原始总分字段 ⇒ 事后无法复盘"装置给了 62.5"。
- 最小复现：`node /tmp/t36/c4-probe.mjs` 的 `C_decimal` 分支（`ai_score=62`、`feedback_has_62_5=false`）。
- 要求修复：把原始分写入 `aiFeedback`（如 `raw_score`/`score_raw`，并在口径里写明取整规则），或把分数字段改为 `DECIMAL(6,2)`；同时在教师可见口径中说明。
