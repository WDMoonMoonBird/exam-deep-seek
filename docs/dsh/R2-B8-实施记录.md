# R2-B8 实施记录（①装置模型/端点与平台配置对齐 ②r2b7 支持 --run-root 复用产物）

## 摘要（≤10 行）
1. **①真因**：装置隔离 home 的 profile 用的是 headless 默认 `agent-default-model.config = {provider: deepseek-official, model: deepseek-flash}`，与平台配置（`deepseek-v4-flash` + `api.deepseek.com`）不一致 ⇒ 真实生产入库时装置 404（`HTTP_404: DeepSeek Messages request failed`）。
2. **①修法（装置侧最小改动，仅 `scripts/dsh-grader/lib.sh` 的 `scaffold_home`）**：当环境变量 `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL` 存在时，向隔离 profile 的 `cordis.patch.yml` 追加 `- id: agent-default-model`（provider/model）与 `- id: llm-deepseek`（baseURL）两条 patch；**两者都缺时完全不追加 ⇒ 默认行为与既有验证结论不变**。
3. **①实测（真代码路径）**：以 `DEEPSEEK_MODEL=deepseek-v4-flash DEEPSEEK_BASE_URL=https://api.deepseek.com` 调 `scaffold_home` 后 `dsh --dump-config` ⇒ `agent-default-model.config.model=deepseek-v4-flash`、`llm-deepseek.config.baseURL=https://api.deepseek.com`，且 `tool-bash disabled: true` 仍在。
4. **①r2b7 侧**：解析平台配置（`system_configs.deepseek_model` / `deepseek_base_url` → env 兜底）并**只经子进程 env** 传给装置（`DEEPSEEK_MODEL`/`DEEPSEEK_BASE_URL`），摘要打印 `PLATFORM_MODEL=` / `PLATFORM_BASE_URL=`；凭据仍只经子进程 env。
5. **②r2b7 `--run-root <dir>`**：跳过装置，直接复用该 run-root 的产物走批 3 消费路径入库，打印同样的 SUMMARY（`CHECKER_ID/CONSUMED/WRITTEN/NEEDS_RERUN/MODEL_CALLS`；复用路径 `MODEL_CALLS=0`）。
6. **②校验与互斥**：缺 `out/checker/checker.json` ⇒ `RESULT=RUN_ROOT_INVALID reason=checker_json_missing expected=…` + 非零退出（不静默成功）；`--run-root` 与 `--device-arg` 同给 ⇒ rc=**4**（用法错误）；生产授权三态与「拒绝在连库之前」对 `--run-root` 同样生效。
7. **测试**：新增 w24（4 例：复用入库 / RUN_ROOT_INVALID / 互斥 / 授权语义）与 w25（3 例：env 透传 + 未提供不传 + DB→env 兜底），全绿；既有测试文件零修改。
8. **装置侧不变式**：`bash scripts/dsh-grader/selftest.sh` ⇒ **82 PASS / 0 FAIL / exit 0**；`classify_changes.py` 与 `scripts/dsh-checker/**` 指纹未变；**`scripts/dsh-grader` 合并摘要由 `e746b888…` 变为 `e535c547…`（因 lib.sh 变更，逐条列出）**。

## 2 ①装置模型/端点：真代码路径实测
```bash
H=/tmp/b8-scaffold-$$; mkdir -p "$H"
DSH_HOME="$H" DEEPSEEK_MODEL=deepseek-v4-flash DEEPSEEK_BASE_URL=https://api.deepseek.com bash -c \
  'source scripts/dsh-grader/lib.sh; scaffold_home "$DSH_HOME"; \
   dsh --profile "$DSH_PROFILE_NAME" --dump-config' 2>/dev/null | grep -A3 -E "agent-default-model|llm-deepseek|tool-bash"
```
```
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-v4-flash        ← 平台模型已生效
- id: llm-deepseek
  config:
    baseURL: https://api.deepseek.com   ← 平台端点已生效
- id: tool-bash
  disabled: true                    ← 隔离约束仍在
```
- 目标 id 的确定方式（读码 + 只读探针）：`dsh --dump-default-config` 显示 headless 默认树里 `agent-default-model` 携带 `provider/model`、`llm-deepseek`（`@deepseek-ai/dsh-llm-deepseek-api-key`）携带 `baseURL`；`--dump-config-schema` 显示 `agent-default-model` 的 config 只接受 `provider/model/reasoningEffort`（**不含 baseURL**），`dsh-llm-deepseek-api-key` 才接受 `baseURL`。
- **未提供时不变**：不设这两个 env ⇒ patch 文件只有原来的 4 条工具禁用项（断言见 w25-2 的「(unset:device-default) ⇒ 子进程 env 为 null」一致性检查）。

## 3 ②--run-root 复用：实测
```bash
cd server
# 复用（产物由 stub 生成或真实装置留下）
node scripts/r2b7-build-checker.mjs --assignment <id> --run-root <dir>
# 缺产物
node scripts/r2b7-build-checker.mjs --assignment <id> --run-root <空目录>
# 互斥
node scripts/r2b7-build-checker.mjs --assignment <id> --run-root <dir> --device-arg x
```
```
复用：RUN_ROOT=<dir> (复用已有产物，未启动装置) / 无 STAGE=device / SUMMARY：ASSIGNMENT=<id> CHECKER_ID=sha256:… CONSUMED=2 WRITTEN=2 NEEDS_RERUN=0 MODEL_CALLS=0 → rc=0
缺产物：RESULT=RUN_ROOT_INVALID reason=checker_json_missing expected=<dir>/out/checker/checker.json → rc=1（非零，不静默成功）
互斥：RESULT=USAGE_ERROR reason=run_root_conflicts_with_device_arg → rc=4
授权：默认/单开关 ⇒ RESULT=REFUSE_PROD_DB + REFUSED_BEFORE_CONNECT=yes + 无 STAGE=connect + rc=2；双开关 + 不可达 URL ⇒ STAGE=connect + CONNECT_FAILED=yes + rc=1（无 REFUSE）
```

## 6 自纠清单
1. **测试期望写错**（w25-2）：我最初断言「不传 env ⇒ `PLATFORM_MODEL=(unset:device-default)`」，但**测试库的 system_configs 若带该键**（或后续被写入）会走 DB 分支 ⇒ 断言不该固定成 unset。已改为**一致性断言**：输出里的 `PLATFORM_*` 与装置子进程实际收到的 env 必须一致（unset ⇒ null；有值 ⇒ 相等）——既覆盖机制又不依赖库状态。
2. **patch 目标 id 先验证再落码**：先用 `--dump-default-config`/`--dump-config-schema` 确认 `agent-default-model` 只吃 provider/model、`baseURL` 归 `llm-deepseek`，避免把 `baseURL` 写进不接受的插件里（那样会静默无效 ✗）。
3. **互斥校验放在守卫之前**：`--run-root` 与 `--device-arg` 的用法错误（rc=4）在连库/起进程之前判定，符合「拒绝在建立连接之前」的口径。
