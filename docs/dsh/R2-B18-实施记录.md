# R2-B18 实施记录（回收器时钟口径错配修复 + 消除同因假绿 + timeout≥阈值告警）

## 摘要（≤10 行）
1. **C 判定（t65，needs_revision，阻断级）**：回收器阈值用客户端 UTC 字面量，而领取路径写 `CURRENT_TIMESTAMP(3)`（会话本地）⇒ 生产口径（`time_zone=SYSTEM`，UTC+8）下真僵尸要等约 8h15m 才会被追上 ⇒ **闸持续被占**，机制核心目的落空。
2. **更深一层的实测发现（本轮新增）**：`updated_at` 这一列上其实有**两个写方**——Prisma（`@updatedAt`）写 **UTC**，领取语句写**会话本地**。实测：Prisma 写的行 `TIMESTAMPDIFF(updated_at, UTC_TIMESTAMP(3)) = 0`；旧领取语句写的行 `TIMESTAMPDIFF(updated_at, NOW(3)) = 0` ⇒ 同列两种时钟。
3. **★修法**：把评测路径**统一到 UTC** —— 领取语句 `buildClaimSql` 由 `CURRENT_TIMESTAMP(3)` 改为 `UTC_TIMESTAMP(3)`（与 Prisma 一致），回收器判据改为 SQL 侧 `updated_at < (UTC_TIMESTAMP(3) - INTERVAL ? SECOND)`，并在回收时用 `UTC_TIMESTAMP(3)` 刷新 `updated_at` ⇒ **写方与判据同源**。
4. **旧测试为何漏（假绿同源）**：w42 的 `backdate()` 用 `new Date(...).toISOString().slice(0,23)`（UTC 字面量）——与旧判据共享同一 UTC 口径 ⇒ 夹具与判据**同错相消**，单测全绿而真实路径失效；且该夹具对「会话口径行」根本不可见。
5. **新测试为何能抓**：w43 的僵尸行**走生产领取语句**（`buildClaimSql` + 原始 SQL）写入，回填时间用 **SQL 侧时钟**（`UTC_TIMESTAMP(3) - INTERVAL ? MINUTE`）；并加负向对照（会话时钟回填 ⇒ UTC 判据下看起来在未来 ⇒ 不回收）⇒ 判据对口径的敏感性被直接断言。
6. **回归守卫**：w43-4 断言判据 SQL 含 `UTC_TIMESTAMP(3) - INTERVAL ? SECOND`、领取 SQL 含 `UTC_TIMESTAMP(3)`、且**不得**出现 `CURRENT_TIMESTAMP(3)`/`NOW(3)`/`updated_at < ?`（本次缺陷形状）。
7. **O-2**：`checkTimeoutVsStale` + worker 打印 `WARN=timeout_ms_ge_stale_ms timeout_ms=… stale_ms=…`（`--timeout-ms ≥ 回收阈值` 时）；w43-5 用 helper 与 CLI（不可达测试库 URL）双向实测。
8. **实测证据（测试库）**：会话与 UTC 偏移 `offset_seconds=28800`；W43-1 生产口径僵尸（UTC 口径 30 分钟前）⇒ **回收命中 pending**；W43-2 会话口径 30 分钟前 ⇒ `utc_age=-27000` ⇒ **不回收**（负向）；W43-6 Prisma 写行与领取语句写行 `utc_age` 均为 **0**（两写方已同源）且都不被误回收。
9. **verify（串行）**：check-layers 0 违规；unit 54 套件/715 例；contract 3/50；三重度 17/61/21；integration 57 套件/428 例；smoke 8/8；生产库指纹 before/after **逐位相同**。
10. w42 的必要改动与未验证项见 §3/§4。

## 2 时钟口径的事实基座（实测，测试库）
| 写方/判据 | 旧写法 | 实测年龄口径 | 修后 |
|---|---|---|---|
| Prisma `@updatedAt`（创建/终结 job） | UTC | `utc_age=0` | 不变（UTC） |
| 领取语句 `buildClaimSql` | `CURRENT_TIMESTAMP(3)` | `session_age=0` | **`UTC_TIMESTAMP(3)`** |
| 回收器判据 | 客户端 UTC 字面量 | 与会话写方差 8h | **SQL 侧 `UTC_TIMESTAMP(3) - INTERVAL ? SECOND`** |
| 回收器刷新 `updated_at` | `CURRENT_TIMESTAMP(3)` | 会话 | **`UTC_TIMESTAMP(3)`** |
偏移量证据：`TIMESTAMPDIFF(SECOND, UTC_TIMESTAMP(3), NOW(3)) = 28800`（`@@session.time_zone=SYSTEM`）。

## 3 w42 改动的必要性（逐条）
1. **`backdate()` 改口径**（`new Date(...).toISOString()` ⇒ `UTC_TIMESTAMP(3) - INTERVAL ? MINUTE`）：旧夹具与旧判据同源（都是 UTC）⇒ 假绿；若不改，夹具在**生产口径**下不可见（会话口径行会被判「在未来」）⇒ 用例恒绿/恒红，失去判据意义。**断言未放松**（仍是 `pending`+`last_error`/`failed` 的强断言）。
2. **假 prisma 匹配串更新**（`updated_at < ?` ⇒ `FROM grading_jobs WHERE status = ?` + `INTERVAL ? SECOND`）：判据 SQL 形状变了，旧匹配串不再命中（W42-3b 一度失败）⇒ 这是**夹具跟随实现**，不是放松断言（冲突分支的断言仍要求 `failed` + 冲突原因）。
3. **W42-4 补 `dbLimit: 5`**：该用例里测试库可能残留其它 running 行占满 DB 级闸 ⇒ `runOnce` 领不到 job（`consumed=false`）。显式 `dbLimit` 让用例聚焦「回收后能否被领取并完成」，**不改变**任何断言语义。

## 3.5 ★反向验证（证明新用例真能抓住原缺陷）
方法：临时把修复点各自还原为缺陷形状 ⇒ 跑 w43 ⇒ 观察变红 ⇒ 还原（`cmp` 校验字节一致）⇒ 复跑应全绿。
| 反向实验 | 还原内容 | 结果 |
|---|---|---|
| A（写方时钟） | `buildClaimSql` 的 `updated_at = UTC_TIMESTAMP(3)` ⇒ `CURRENT_TIMESTAMP(3)`（t65 的写方） | **W43-6 红**：`utc_age=-28799`（正是 C 实测的缺陷签名）+ **W43-4 红**（守卫断言领取 SQL 含 UTC） ⇒ 2 failed / 4 passed |
| B（判据时钟） | `STALE_CLOCK_SQL` ⇒ `'NOW(3)'`（会话口径） | **W43-4 红**（判据必须 UTC）+ **W43-2 红**（会话口径下负向对照失效）+ **W43-6 红**（UTC 口径的新行被会话判据误回收） ⇒ 3 failed / 3 passed |
| 还原后 | 两文件均由备份恢复 | `restore_A_identical=yes`、`restore_B_identical=yes`；w42+w43 **12/12 全绿** |
⇒ 新用例对**写方**与**判据**两侧的口径漂移都敏感：任一侧单独回退都会变红，两侧同时回退（旧假绿状态）才会绿 ⇒ 正是「夹具与判据同源」的假绿机制被拆除的证据。

## 3.6 环境清理披露（非代码改动）
首次全量 verify 有 12 个 worker 系套件失败（`consumed=false`）：根因是共享测试库里一条**孤儿 probe running 行**（`grading_jobs.id=1021`、`assignment_id=25184` 已被删除、`checker_id=sha256:probe-c17e`、`updated_at` 为**未来时刻** ⇒ 回收器看不见它 ✗）占满了 DB 级闸（limit=1）⇒ 所有 `runOnce` 都领不到 job。处置：把该孤儿行置 `failed`（`last_error=t66_orphan_probe_cleanup`，保留可追溯），并删除 9 条孤儿 job + 2 条孤儿 checker（`assignment_id` 已不存在的行）。清理后 8 个套件 **21/21 全绿** ⇒ 确认此前失败是**环境**而非本轮回归。

## 5 自纠清单
1. **首版修法只改了判据（NOW(3)），没查清写方有几个** ⇒ 实测发现 Prisma 与原始 SQL 写的是**两种时钟**，只把判据改成会话时钟会误回收 Prisma 写的新行（W42-2 立刻红）。最终改为**全链路 UTC**（判据 + 领取语句 + 回收刷新），并用 W43-6 断言两个写方的 `utc_age≈0`。
2. **W43-2 方向一开始写反了**（以为 UTC 字面量让行看起来更旧；实测会话时钟**领先** UTC，所以 UTC 写的行在会话口径下看起来更旧、会话写的行在 UTC 口径下看起来在未来）⇒ 改成负向断言（会话口径行不被 UTC 判据回收），并保留 `diff=28800` 的偏移量证据。
3. **夹具与判据必须来自不同代码路径**：本轮把「构造僵尸行」改为走**生产领取语句**（`buildClaimSql` 原始 SQL），避免再次出现「同一转换函数互相抵消」的假绿。
