### 2.2 回填脚本 server/prisma/scripts/backfill-snapshots.js
- 默认 dry-run；写库必须显式 --apply。
- --apply 守卫前置：目标库必须 ∈ ALLOWED_APPLY_DBS = [exam_system_test] 且 --allow-db <同名>，否则 RESULT=REFUSE_PROD_DB 且 exit 2（连接数据库之前就返回）⇒ 生产库永不写入。
- 迁移未落地（快照列不存在）时：dry-run 自动退化为 preflight 计数（等价目标集，不引用新列）；--apply 直接 PRECONDITION_MIGRATION_NOT_APPLIED exit 3。
- 幂等：目标集与单行 UPDATE 都带 rubric_snapshot IS NULL ⇒ 二次 --apply matched=0。
- 内容在 DB 侧从 questions 复制（JOIN questions），rubric 正文不经 JS/日志；摘要只输出 (assignment_id, question_id, rubric_sha12)。
- 回填行带 snapshot_origin=backfill；standard_hash 默认 NULL（发布时刻的标准包哈希不可考，批 2 W2 起写入）——不声称历史重评逐位一致。

复算（安全、只读）：
```bash
node server/prisma/scripts/backfill-snapshots.js --dry-run --db-url <测试库 URL>   # MODE=dry-run … DRY_RUN_OK would_update=N（未写库）
node server/prisma/scripts/backfill-snapshots.js --apply --db-url <生产库 URL> --allow-db exam_system   # RESULT=REFUSE_PROD_DB，exit 2（未连库）
```
