## 1 问题与根因
- 现象（C 的 §5）：`child_session` 为空时，含**宿主会话 id** 的路径被判 `R7-UNATTRIBUTED` ⇒ `changed_unattributed>0` ⇒ `verdict=FAIL`、`rc=1`，**而没有任何未隔离写入**。
- 根因：R4 分支只写了 `if not child_session: return R7`，从未引用 `args.host_session`（该参数在第 120 行声明、全文再无使用）；与头部自述判据「R4：路径含 UUID 会话 id 且该 id != 子会话 id ⇒ HOST」不一致。
- 触发条件（C 指出、本轮复现）：①stub / dry-run / 子会话被超时裁剪等**隔离 home 内没有子会话文件**的场景 ⇒ `CHILD_SESSION` 为空；②窗口内宿主实例（或并行会话）写了 `~/.dsh/sessions/<cwd>/<宿主 id>/…` 或 `~/.dsh/storages/session_projcache/sessions/<宿主 id>.json`。两者同时成立即假 FAIL，属**时序相关 flaky 通道**（我方 selftest 57/0 是因为 stub 用例恰未撞上该窗口）。
- 方向安全性：只可能假 FAIL，不会假 PASS（C 的判断成立）。

## 2 修复内容
```python
# classify_changes.py —— R4 分支（修复后）
sid_match = UUID_RE.search(path)
if sid_match:
    sid = sid_match.group(0)
    if child_session and sid == child_session:
        return 'R1-CHILD-PATH', 'path carries child session id'          # 兜底：子进程自己的写入
    if host_session and host_session in path:
        return 'R4-HOST-SESSION', 'host session id in path'              # ★F-C2C-1 修复点
    if not child_session:
        return 'R7-UNATTRIBUTED', 'session-id path matched neither host nor child session (fail-closed)'
    return 'R4-HOST-SESSION', 'session id in path != child session'
```
头部判据表同步改为：「R4 HOST-SESSION 路径含 UUID 会话 id 时依次判：(a) 命中 `--host-session`（或 `--child-session` 已给出且 id≠子会话）⇒ HOST；(b) 两者都不命中且 `--child-session` 为空 ⇒ UNATTRIBUTED（fail-closed，不猜）；(c) 两者都不命中且 `--child-session` 非空 ⇒ HOST」。

## 5 未验证 / 残留风险（单列）
1. **「宿主 id 未知」组合仍可能假 FAIL**：若某次运行既拿不到子会话 id、`--host-session` 也为空或与路径不符（例如宿主会话被裁掉导致 `DSH_SESSION_ID` 缺失，或路径里的 id 属于**第三方会话**），R4 仍判 UNATTRIBUTED ⇒ 仍会假 FAIL。这是刻意的 fail-closed 取舍（宁可报警不可假 PASS）；若要进一步降噪，需要把「已知活跃会话 id 集合」也传进来（设计上属 R0-B4 可选项，本轮未做）。
2. **端到端用例有时序依赖**：它要求宿主实例恰在我方窗口内写了会话文件（selftest 通过「等 control.txt 落盘后再改文件」把该条件变成确定性的受控条件，但真实运行中该窗口是否命中仍取决于并发的宿主活动；命中时归因已正确，未命中时该用例不触发）。
3. 未实测：多份 `--submissions >1` 场景下的归因（路径 id 变化与 child 会话 id 的对应关系），本轮只覆盖单份。
