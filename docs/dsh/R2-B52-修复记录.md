# R2-B52 修复记录：右侧整块空白（懒加载 chunk 失败 / 过渡卡死）⇒ 自愈 reload-once + 错误边界 + 绝不白屏

> 摘要（≤10 行）：① **症状复现链**（用户实测）：审核学生后点「返回」或点**任何**左侧菜单 ⇒ 右侧整块空白、必须硬刷新；对应三条根因：
> 部署 `rsync --delete` + 资源哈希 ⇒ 旧标签页取旧 chunk **404**（动态 import 拒绝）→ 路由懒加载失败**无人接管**（全仓无 `router.onError`）→
> `<transition mode="out-in">` 在「进入组件解析失败」时停在 out 阶段 ⇒ 右侧永久空白，之后任何菜单点击同样空白。
> ② **自愈**：`router.onError` 识别四类动态导入失败措辞 ⇒ **整页 reload 一次**，`sessionStorage` 键 `chunk-reload:<fullPath>` 防循环；第二次不再 reload 而显示错误 UI。
> ③ **错误边界**：新增 `components/ErrorBoundary.vue`（`onErrorCaptured`）并置于两处 Layout 的 `<transition>` **之外**；错误态显示「页面加载失败 + 重试 + 刷新页面 + 路由」；**随路由变化自动复位** ⇒ 后续导航仍可渲染（症状核心）。
> ④ **全局可见**：`app.config.errorHandler` + `window.unhandledrejection` ⇒ 可见提示（message）且 `console.error` 带路由信息，**不静默**；⑤ 两处 Layout 去掉 `mode="out-in"`（取舍见 §4）。
> ⑥ 测试：`verify-frontend` 新增 ⑦a–⑦h（**注入桩件**跑纯逻辑 + 接线契约）⇒ 全绿；三条变异（M1 去掉边界 / M2 加回 out-in / M3 破坏防循环）⇒ 各自 rc=1 且还原逐字节一致。
> ⑦ 回归：前端核验（含构建）21/21 rc=0；jest w52+w61+w62 全绿；check-layers 0 违规；clean-env 指纹见 §5（生产表数 28→29 由批次4迁移引入，**如实记录不掩盖**）。

## 1. 症状复现方式（为什么"只验代码路径"不够）
- 用户路径：`review/project/:submissionId`（审学生）→ 点「← 返回」→ 期望回到 `review/class/:classId`；实测右侧整块空白，**且此后点任意菜单仍空白**（左侧菜单仍在）⇒ 说明问题不在某一个页面，而在**路由/视图渲染层**。
- 触发条件（部署后典型）：浏览器缓存里是旧构建的 `index.html`（或旧标签页常驻），新发布已 `rsync --delete` 删掉旧哈希资源 ⇒ 动态 `import()` 404。
- 复现方式（本批，可在无浏览器下执行）：`node client/scripts/verify-frontend.mjs` 的 **⑦a–⑦e** 用**注入桩件**模拟"动态导入拒绝"（`Failed to fetch dynamically imported module: …`）与"非 chunk 错误"，观测：reload 次数、`sessionStorage` 键、可见提示；⑦f–⑦h 校验两处 Layout/main.js 的接线契约（边界在 transition 之外、无 out-in、mount 前安装、全局 handler 齐备）。

## 2. 三条根因 → 三条处置
| 根因 | 处置（文件） |
|---|---|
| 懒加载失败无人接管（无 `router.onError`） | `components/errorRecovery.js`：`isChunkLoadError()`（四类措辞）+ `handleRouterError()`（reload-once + 防循环）+ `installRouterErrorHandling()`；`main.js` 在 **mount 之前** `installErrorRecovery({ app, router, notify })` |
| `transition mode="out-in"` 卡在 out ⇒ 永久空白 | ①错误边界置于 transition **之外**（`ErrorBoundary.vue` 包住 `router-view`）②两处 Layout 的 router-view 过渡去掉 `mode="out-in"` |
| 错误被静默（无全局兜底） | `app.config.errorHandler` + `window.unhandledrejection` ⇒ `message.error(...)` 可见提示 + `console.error` 带 `route` 信息；未捕获的 chunk 失败也走自愈 |
- 防循环：键 `chunk-reload:<fullPath>`（`sessionStorage`）；**每个路径各自一份预算** ⇒ 后续导航到新路由仍可自愈一次（⑦c），而同一路径第二次失败只提示不刷新（⑦b，避免死循环刷新）。
- `ErrorBoundary` 复位规则：`watch(() => props.resetKey || route.fullPath, () => state.value = null)` ⇒ **点菜单/返回后错误态自动清空**（症状"点任何菜单都空白"的根治点）；「重试」会清掉该路径的防循环标记，允许再次自愈尝试。

## 4. 取舍：为什么去掉 `mode="out-in"`
- 保留 out-in 的收益：切换时"旧页先出、新页再进"，视觉上更干净；风险：**进入组件解析失败时可能停在 out 阶段 ⇒ 整块空白**（正是本缺陷）。
- 去掉后：默认模式允许进出重叠一瞬（`tab-fade` 仍是 opacity 过渡，观感差异很小），但**不再存在"解析失败即永久空白"这一类死锁**；同时错误边界在 transition 之外，任何渲染错误都会显示可见错误 UI。⇒ 以"绝不白屏"优先，取舍记此。
