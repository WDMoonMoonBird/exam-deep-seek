# R2-B21 实施记录（worker 按 job 解析该作业物料目录与份数 + 缺失 fail-closed）

## 摘要（≤10 行）
1. **缺口**：worker 的装置参数在**启动时写死**（`--source-dir` / `--submissions` 只有一份全局值）⇒ 生产多个项目型作业时，要么永远批改仓库里的 `实验/` 夹具（**错料**），要么每个作业重启一次 worker（不可行）。
2. **①按 job 解析**：新增 env `DSH_GRADER_MATERIALS_ROOT`（缺省空）。非空时，worker 为每个 job 解析 `--source-dir <ROOT>/<assignmentId>`（**绝对路径**），并**覆盖**启动时写死的旧值（剥旧值再追加，见 `withMaterialsArgs`）。
3. **②fail-closed，不回落默认**：`<ROOT>/<assignmentId>` 不存在或为空 ⇒ 打印 `MATERIALS_MISSING assignment=<id> path=<dir>`，该 job 置 `needs_rerun` + `last_error=materials_missing_for_assignment:<id>`，**装置从未启动、不写分、不回落 `实验/`**。
4. **③份数从物料派生**：优先取该目录 `export-manifest.json` 的 `n_submissions`（`source=manifest`）；清单缺失/损坏 ⇒ 回退「目录内 `*.zip` 数 − 1（标准件）」（`source=zipcount`）；两条路径都打印 `MATERIALS_RESOLVED assignment=<id> dir=<dir> submissions=<n> source=…`。
5. **④向后兼容**：未设该 env ⇒ `mode='device-default'`，装置参数与既有**逐一相同**（w48-3 回归断言：无 `--source-dir` 注入、`--submissions` 仍为启动值）。
6. **⑤可观测**：`WORKER_START` 增打 `materials_root=<值或(unset:device-default)>`。
7. **⑥导出器（低优先）**：库不可达等连接类错误归一为 `EXPORT_FAIL reason=db_unreachable`（其余仍 `unhandled:<msg>`）—— 实测死端口 + 双开关 ⇒ `db_unreachable`（原先会是 `unhandled:<连接错误>`）。
8. **测试**：新增 w49（unit，6 例：unset/缺失/为空/绝对路径、zipcount 回退与坏清单、args 覆盖两种写法、打印行契约、错误归一）与 w48（integration，5 例：捕获 args 断言、fail-closed 不启动装置、向后兼容回归、zipcount 标记、两个作业不串味）。
9. **文档**：`docs/dsh/deploy/README.md` §7-1 增补「多作业顺序（先导出物料再拉起 worker）」+ fail-closed 语义 + 示例；`worker.env.example` 增 ②b `DSH_GRADER_MATERIALS_ROOT`（含顺序与 fail-closed 注释）并把 ②份数改为「设了 ROOT 时可不填」。
10. **verify（串行）**：check-layers 0 违规；unit 56 套件/726 例；contract 3/50；三重度 17/61/21；integration 59 套件/440 例；smoke 8/8；生产库指纹 before/after **逐位相同**。

## 3 语义与边界
- **覆盖语义**：`withMaterialsArgs` 先剥离 `--source-dir`/`--submissions` 的**两种写法**（分隔式与 `=` 式）再追加 ⇒ 无论装置取「先出现」还是「后出现」的值，结果都唯一（不依赖装置解析顺序）。
- **不回落**：解析失败分支在**装置启动之前**返回（`fake runner` 调用次数=0 已实测）⇒ 不存在「用错料批改」的可能；job 记 `needs_rerun`（可修复：导出物料后重试），不记 `failed`（非产品缺陷）。
- **份数口径**：`manifest.n_submissions` 优先（导出器写入的权威值）；无清单时 `*.zip 数 − 1` 假设「标准件也在同目录」（装置契约要求 `标准工程包.zip` 与提交同目录）⇒ 该回退在导出器产物上恒等于提交数。

## 4 未验证项（单列）
1. **未在生产与真实装置上验证**（不写生产、不跑装置）：`MATERIALS_RESOLVED`/`MATERIALS_MISSING` 的行为以捕获式断言 + 装置参数契约覆盖；真实装置对 `--source-dir <绝对路径>` 的接受性在 R2-B20 记录 §2 已核实（`os.path.join` 遇绝对路径原样返回）。
2. **多作业并发**未实测：w48-5 是**连续**两个作业（互不串味）；并发领多个 job 时每个 job 的解析是局部变量（无共享状态）⇒ 结构上安全，但未做真并发压测。
3. **`<ROOT>/<assignmentId>` 的目录名约定**未做兼容（只认 assignmentId 字符串）；若运维用别的命名（如 `assignment-311`）会判缺失 ⇒ fail-closed（明确报错，不静默）。
4. **导出器 `db_unreachable`** 只对连接类错误归一（w49-6 单测 + 一次 CLI 实测）；其它 DB 错误仍 `unhandled:<msg>`（按需再细分）。
