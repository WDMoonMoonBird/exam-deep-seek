## 0 结论
1. **队长的假设成立**（核心）：EXIT trap 内的 teardown 失败**覆盖了装置原退出码 3 → 1**，于是 selftest 的 [ $? -eq 3 ] 为假 ⇒ 报「篡改未被拦」；而日志里其实已有 frozen-tampered(precheck)（装置确实拦住了）。
2. **但机制不是「$OUT 未就绪导致 teardown 失败」**（该子假设不成立，见 §3.3）：中止发生在**参数展开期**的 set -u 中止，与目录是否存在无关。
3. **真机制（同一类缺陷、两处）**：$var 紧跟**全角标点**，在 LC_CTYPE=C.UTF-8 下 bash 3.2 把多字节字符**吞进变量名**（去查 rc） 这个不存在的名字）⇒ unbound variable ⇒ bash **立即以 1 退出**，而 || true **拦不住**（中止不是普通命令失败）。
   - 产品侧 scripts/dsh-grader/lib.sh:344：`exit=$rc）`、`keep_days=$keep_days，`（字节扫描共 **4 处**：$rc×2、$keep_days×2 紧跟 0xEF）。
   - 测试侧 冻结快照 selftest.b26.sh:428：`见 $SANDBOX/b26-fail.log 与 $TD2）` ⇒ 两份留档日志都以 selftest.sh: line 428: TD2?: unbound variable 收尾。
4. **PURGE_HOME=0 无效**已解释：中止所在分支是 `elif [ "$rc" != "0" ]`（lib.sh:341-344），**与销毁策略无关**（purge_want 只影响 :334 与 :345 分支）。
5. 修复 = 两处 ${var} 定界（必须）+ trap 内 set +u 兜底（加固）+ 静态 lint 与回归断言（防复发）；**不改任何判据语义**，只把被吞掉的退出码还回去。

## 3 对假设的判定
### 3.1 主假设（trap 内失败覆盖退出码）→ **成立**
- 链路：run.sh:110-111（新增 teardown 调用）→ lib.sh:341（rc≠0 分支）→ :344（中止）。
- **最小可判证据 A（语义实验，零文件写入）**：`bash -c 'set -euo pipefail; cleanup(){ local rc=$?; echo "trap sees rc=$rc"; echo "boom=$zz）" || true; exit "$rc"; }; trap cleanup EXIT; echo RUN_EXIT=3; exit 3'` → 打印 RUN_EXIT=3 / trap sees rc=3 / `bash: zz?: unbound variable`，**实测 observed_rc=1**；去掉全角括号的对照版本 observed_rc=3。

- `git show HEAD:scripts/dsh-grader/run.sh` 的 cleanup()（旧 :99-107）**没有** teardown 调用（仅 cleanup_credentials + release_workdir_lock + `exit "$rc"`）；`git show HEAD:scripts/dsh-grader/lib.sh | grep -c teardown_home` = **0**。
