## 5 ★F1（中危）：实训题学生视图 vs 计入分口径不一致
- 实测（探针 Q18，U18）：同一份 `published` 提交（aiScore 64 / bestScore 91 / finalScore null / 作业口径 best）：
  - `GET /api/student/assignments/:id`（作业详情，走 `toStudentSubmissionView`）⇒ **计入分 91**；
  - `GET /api/student/assignments/:aid/project/:qid`（实训题页，走 `domain/services/project-view.js#toStudentView`）⇒ `score: null`（status=published）。
- 判定：**不是纯「有意安全边界」**。安全边界（未发布不下发、不泄漏 aiScore/aiFeedback）在两条路径都已成立；但 **US-B6 AC2** 要求「published 且当前可见时显示当前计入的最高分」，而 `toStudentView` 只发 `finalScore`，在教师未给分时给出 null ⇒ 与同页/同需求的另一条路径自相矛盾（学生看到「—」而列表显示 91）。
- 建议（超本任务 in-scope，交队长裁定）：`toStudentView` 接收作业 `scorePolicy`，仅在 `status==='published'` 时用 `pickCountedScore({scorePolicy, finalScore, aiScore, bestScore})`；`reviewed/ai_graded` 维持 null（US-B6 AC3 + D4 边界不变）。改动面：`project-view.js` + 2 个调用点（`student/project-question.js`、`student/project-submit.js`）。
- 影响：仅显示口径（无数据/权限风险），**不阻塞门禁与波次终验**；若本期不修，建议记入 P2 并在手册/验收说明中标注。
