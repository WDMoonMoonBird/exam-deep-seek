## 1. 已批准口径（复述，逐条落地）
1. 复用范围：同一 `content_key` ⇒ 跨班、跨教师复用；**不做学期隔离**；本期**不做「重新造尺」UI**，只在数据模型上预留
   （新尺不覆盖旧分：尺寸由 content_key 唯一，改内容 ⇒ 新 key ⇒ 新尺，老尺与老绑定保持原样）。
2. 多班作业：一次运行覆盖多班（不变；运行/归档仍按 assignment 归集）。

## 2. content_key 口径（唯一真相 = `server/src/services/dshRulerContentKey.js`）
```
norm(s)     = String(s ?? '').replace(/\r\n?/g, '\n').trim()        # 统一换行（CRLF/CR→LF）+ 去首尾空白（UTF-8）
canonical   = 'standard_sha256=' + norm(S) + '\n' + 'rubric=' + norm(R) + '\n' + 'description=' + norm(D)
content_key = sha256hex(canonical)                                    # 64 位小写十六进制
```
三个组成**与装置实际读到的字节同源**（装置侧零注入）：

| 组成 | 取值 | 为什么不取别的 |
|---|---|---|
| `standard_sha256` S | `sha256hex(标准工程包.zip 的字节)`（`deterministicZip.zipDirectory(uploads/project-questions/<qid>/standard)`，固定 DOS 时间戳 ⇒ 确定可复算） | 目录缺失/为空/不可读 ⇒ **fail-closed**（`standard_package_missing|empty|unreadable`），**绝不**回落 `assignment_questions.standard_hash`（那是 `sha256:<dirSha256(ignore=[])>`，形状不同 ⇒ 同内容两个 key）；也不用装置 `standard.extract_digest`（ignore 列表不同、平台侧不可复算） |
| `rubric` R | `rubric_snapshot.rubric ?? questions.scoring_rubric`（发布冻结快照优先） | 与装置 `materials/评分标准.md` 同字节；`rubric_sha256` 记 `textSha256(原始字节)`（与 `checker.assignment_ref.rubric_hash` 同口径，可对拍） |
| `description` D | `buildAssignmentDescription({title, material})` ≡ r2b20 `buildAssignmentMd`（标题 + `material_snapshot ?? material`，各自 trim） | 与装置 `materials/题目描述.md` 同字节；`material_snapshot`（快照）与导出（r2b20，本轮改为 `snapshot ?? live`）同源 ⇒ **同 key ⇒ 同物料** |

**可复算示例**（真实导出 `/tmp/grader-materials/311`，S=`b924952aead5df8c058f14ff6bc1b556855740e51d42a8a6ad7281a6788fb5ac`，
rubric `15d0b74d…3fdf`、题目描述 `eb6a153c…18e4`）：
```
content_key = c031b1fee35020ea6c93d464d4a06ef105ad7d0d116cc31ad71c80b169958470
仅把 rubric 改一个字（功能→功 能）⇒ 51418469488e94259581eaaa15a87e8c75610f26b94656aa8e7dfe577ab2cf45（≠）
```

## 4. 解析流程（时序）与三入口接线
```
① 解析内容指纹（只读、零 LLM；无发布快照/无标准包/题目非唯一 project ⇒ 不参与内容化，回落旧路径）
② 查 grading_rulers(content_key)：
   ready    → ★直接复用（零 LLM；日志 RULER_REUSE_HIT content_key=… checker_id=…），原始字节逐字节落位 run-root
   building → 等待（轮询；★等待者不写库、不造尺）；超时/失败 ⇒ fail-closed（不产出分数）
   无       → 先确认「有人能造尺」（老锚点可采纳 / 本地已入库尺子 / 本次装置造尺），否则不抢占；
              抢占 INSERT … status=building（UNIQUE 兜底）⇒ 老锚点可采纳则 RULER_ADOPTED_OLD_ANCHOR（不造尺）
              / 否则造尺一次 ⇒ ready（写 checker_id/frozen_sha256/checker_raw）⇒ 绑定
   failed   → 造尺入口可原子重试（RULER_RETRY_CLAIMED）；消费方 fail-closed（reason=ruler_failed:…）
③ 绑定 assignment_question_rulers(assignment_id, question_id)=ruler（首次）；已有绑定校验一致，不一致 ⇒ RULER_BIND_CONFLICT + fail-closed
```
| 入口 | 改动 |
|---|---|

## 5. 并发与失败（同一份内容只造一把尺）
- 抢占：`INSERT IGNORE … status='building'` + `UNIQUE(content_key)` ⇒ 只有一个进程 affectedRows=1；
- 等待者：只读轮询（`DSH_RULER_POLL_MS`，缺省 5s；`DSH_RULER_WAIT_MS`，缺省 60min），**不写任何库**；
- 超时/建造失败 ⇒ 等待者 `failClosed`（reason=`wait_timeout`/`builder_failed:…`/`ruler_failed:…`）⇒ 调用方不产出分数（worker ⇒ `needs_rerun`）；
- 造尺失败 ⇒ `status='failed'` + `last_error` 留痕（可重试：`reclaimFailedRuler` 原子抢占，仅造尺入口启用）；
- **陈旧 building 接管**（补 `DSH_RULER_BUILDING_STALE_MS` 缺省 30min，仅造尺入口）：造尺进程被强杀留下的 building 行可原子接管，避免同内容永久 fail-closed；（等待者永不接管）

## 6. 老锚点复用（不重复造尺）与就地登记
`findAdoptableOldAnchor`（老表 `grading_checkers` × `grading_assignment_anchors`）**四重判据**，任一不成立即跳过并留痕（`RULER_ADOPT_SKIP reason=…`）：
1. 候选所在作业有**发布冻结快照**，且 `standard_hash`（`sha256:<dirDigest>` 形状）与目标**逐位相等**；
2. rubric 正文、题目描述正文（同源构造）与目标相等；
3. 候选 checker 的 `assignment_ref.rubric_hash == textSha256(目标 rubric 原始字节)`；
4. **装置口径**：按候选 checker 自己的 `input_contract.ignore` 复算**目标标准包目录**摘要 == 候选 `assignment_ref.standard_hash`（与 `check.py:412-423` 同规则，平台侧用 `utils/snapshotHash.dirSha256`）；
另加：`checker_raw` 非空、JSON 合法且 `checker_id` 自洽、`sha256(checker_raw)` 与 `frozen_sha256` 一致。
采纳后**补建 `grading_rulers` 记录**（ready + checker_raw/frozen_sha256，零 LLM/零装置）；**不搬老作业的名单**（见 §7）。
就地登记（`registerRulerFromLocalChecker`，迁移期把**本作业已入库的 ready 尺子**纳入新表）：同样必须通过判据 3+4，否则 `RULER_INGEST_SKIP`。
★反例断言（A 复核要求）：候选快照 `standard_hash` 若写成 bare hex（形状不符）⇒ **不得采纳**（测试 W59-1 覆盖）。

## 7. 锚点不变量与「复用命中补锚点」
- ★不变量：`grading_jobs.checker_id == grading_rulers.checker_id == grading_assignment_anchors.checker_id`；
  worker 命中复用时会 `UPDATE grading_jobs SET checker_id=<ruler.checker_id>`（`RULER_JOB_CHECKER_ALIGNED`，失败即 fail-closed）；
  尺子原始字节**逐字节**写入 `out/checker/checker.json` + `out/assignment/checker.frozen.json`（不重序列化 ⇒ 装置 `frozen_intact` 预检不会被误判篡改）。
- 复用命中若本作业**无锚点行** ⇒ 装置跑完后用**本次 run-root 的真实名单**补建（`persistAnchor`，`ANCHOR_ROW_BACKFILLED=yes`）；
  **绝不**把别的作业/班级的 `submissions` 搬过来（那会让消费侧 slug 映射把分写到错的学生上）。
- `test/setup.js:cleanupOrphanGradingRows` 增补：按「assignment 是否仍存在」清 `assignment_question_rulers`；
  `grading_rulers` 是**全局资产**（跨班共享）⇒ **不随绑定消失而删**。

## 9. 边界与已知限制（明确声明，不静默）
1. **HTTP 触发只对「有发布快照」的作业走内容化**；无快照的历史作业保持旧行为（按作业找 ready checker）；
2. 内容化要求**标准包目录存在**（`uploads/project-questions/<qid>/standard`，测试/演练可用 `DSH_GRADER_UPLOADS_ROOT` 重定位）；目录不可用 ⇒ 该作业不参与复用（fail-closed），旧路径照旧；
3. 「重新造尺」UI 本期不做；`--force-checker` 在内容命中时被显式忽略并留痕（新尺不覆盖旧分）；
4. 采纳/登记**不以无法证明同内容的老行为来源**（判据不成立即跳过并留痕）；
5. 生产迁移未执行（仅测试库；生产由队长在授权窗口执行，先备份 + `rollback.sql` 就绪）。
