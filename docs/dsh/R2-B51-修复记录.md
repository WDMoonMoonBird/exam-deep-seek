## 1. F-T32-1：根因与修法（1 行 × 2）
```js
// 旧（缺陷）：Number(null) === 0 是有限数 ⇒ 默认参数 null 被短路成"显式 0"
const hitsRaw = Number.isFinite(Number(cacheHits)) ? Number(cacheHits) : (meta ? Number(meta.cache_hits) : null);
// 新（R2-B51）：先把 null/undefined/"" 归一为 null，再判有限性；?? 保证 meta 兜底可达
const numOrNull = (v) => (v === null || v === undefined || v === "" ? null : (Number.isFinite(Number(v)) ? Number(v) : null));
const hits = numOrNull(cacheHits) ?? numOrNull(meta ? meta.cache_hits : null);
const gen = numOrNull(generated) ?? numOrNull(meta ? meta.generated : null);
```
- 语义保持：**显式参数优先**（`cacheHits: 0, generated: 3` ⇒ 仍以显式值为准，w66b-4 后半段对照断言）；`cache_hit = gen===0 && hits>0`（全命中才 true）。
- 导出 `numOrNullStrict` 供复用/测试（避免同类 `Number(null)` 陷阱再现）。

## 2. T32-O1：删除恒 inert 的归档候选（选择与理由）
- 现象：控制器候选列表含 `out/summaries.json`，但 `readArchiveFile` 的**文件名白名单按设计拒绝含 "/" 的路径** ⇒ 该候选**恒 inert**（实测 nested ⇒ `not_generated`），实际生效的是**平铺** `summaries.json`（B50 布局，A10 已证字节一致）。
- 选择：**删除无效候选**（不放宽白名单）——理由：①放宽白名单会削弱归档读取的路径安全约束（白名单正是防穿越的第一道口）②归档布局由 B50 定为平铺，双位置兼容属"看似支持、实为死代码"③删除后在注释中写明原因，避免后人再"修回来"。
- 契约断言：w66b-5 断言控制器仅含 `for (const rel of ["summaries.json"])`、**不含**嵌套候选，且留痕注释在位。
