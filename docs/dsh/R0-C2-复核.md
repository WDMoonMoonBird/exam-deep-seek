## 5 新缺陷 F-C2C-1（中）：R4 判据忽略 `--host-session` ⇒ 假 FAIL
- **实现原文**（`scripts/dsh-grader/classify_changes.py:94-97`）：
  ```
  if UUID_RE.search(path):
      if not child_session:
          return 'R7-UNATTRIBUTED', 'session-id path but no --child-session (fail-closed)'
      return 'R4-HOST-SESSION', 'session id in path != child session'
  ```
  而同一文件第 11 行的自述判据是「R4 HOST-SESSION：路径含 UUID 形态会话 id，**且该 id != 子会话 id**」——只要给的 id 不是子会话的，就该判 HOST。实现却要求 `child_session` 非空，且 `--host-session` **只在第 120 行声明、全文再未使用**（`grep -n host_session` 仅命中 24/120 行）。
- **确定性最小复现**（合成 diff，不碰 ~/.dsh）：
  `python3 scripts/dsh-grader/classify_changes.py --changed <含 ~/.dsh/storages/session_projcache/sessions/716b24ce-…json 的一行> --control <空> --host-session 716b24ce-… --child-session '' --isolated-home /tmp/iso --workdir /tmp/dsh-verify2/repro --dsh-home $HOME/.dsh`
  → `RULE R7-UNATTRIBUTED … session-id path but no --child-session (fail-closed)`（该 id 正是 `--host-session` 传入的宿主会话）。
- **端到端实例**：stub 运行（或不产生子会话文件的任何运行）期间，我自己的会话写了 `~/.dsh/storages/session_projcache/sessions/<宿主 id>.json` → `isolation-report: changed_unattributed=2 / verdict=FAIL / verdict_reasons=unattributed-change` → run.sh 最终 `RUN_RESULT=FAIL rc=1`，**而没有任何未隔离写入**。B 的 `selftest.sh` 之所以 57/0，是因为那些 stub 用例恰好没撞上宿主写入窗口（时序相关，属 flaky 通道）。
- **影响**：只会造成**假 FAIL**，不会造成假 PASS（方向安全）；但 ① `--dry-run`/CI/stub 路径（B 自己在 README 推荐的用法）会随机整体失败；② 会话被超时裁剪、隔离 home 内未落会话文件时，真实的 isolation 结论会被污染成 FAIL；③ `--host-session` 参数形同虚设。
- **要求修复**：把 `args.host_session` 传入 `classify()`，UUID 分支改为：命中 child 指纹 → CHILD（R1 已覆盖）；命中 `host_session` → `R4-HOST-SESSION`；两者都不命中且 `child_session` 为空 → `R7-UNATTRIBUTED`（保持 fail-closed）；两者都不命中且 `child_session` 非空 → 维持现状 `R4-HOST-SESSION`。
- **复发判据**：任何 `isolation-report.txt` 出现 `RULE R7-UNATTRIBUTED … session-id path but no --child-session` 且该路径含 `--host-session` 传入的 id；或 `changed_unattributed>0` 而 `changed_child_write=0`。
