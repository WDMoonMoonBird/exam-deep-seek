## 2 口径与边界（聚合 = 既有批改结果，不新写一套）

- 结果来源：`Submission.aiFeedback`（`source='dsh-checker'`）的 `breakdown[]`；`status`：`hit` 命中 / `miss` 未命中 / 其它 ⇒ **未判定（unknown）不计入分母**，单独计数（不猜、不折算为 0 分）。
- 失分率 = `miss / (hit + miss)`（分母 0 ⇒ `null`，页面显示「—」）；同项同时返回 `numerator`/`denominator` 便于核对；排序：失分率降序 → miss 降序 → item 升序（确定性，测试固定断言）。
- 同一次提交内同项只计一次；坏 JSON / 空串 / 非对象一律安全降级（不抛、不进分母）；空作业 ⇒ `items: []` + 计数全 0。
- 版本块：`versions[]`（checker_id + canonical_sha256 + 份数）、`rulers[]`（questionId、rulerId（BigInt→字符串）、content_key、status、rubric/standard 指纹）。
  ★实现细节：生成的 Prisma Client DMMF **不含** `grading_rulers` / `assignment_question_rulers`（B35 起这两张表由原始 SQL 管理）⇒ 版本块走**参数化只读 `$queryRaw`**（不用 Unsafe 版本；⑭b 断言「有 `$queryRaw`、无 `$executeRaw`」）；`$queryRaw` 对 UNSIGNED INT/BIGINT 返回 **BigInt** ⇒ 出口显式收窄（`questionId → Number`、`rulerId → String`），否则 `res.json` 会因 BigInt 抛错。
- 只读：服务与两个 handler 无任何写路径（verify-frontend ⑭b 断言 + jest 覆盖）。
