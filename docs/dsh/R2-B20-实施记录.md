# R2-B20 实施记录（物料来源导出器：平台作业 → 装置可食物料源目录 + 部署缺口收口）

## 摘要（≤10 行）
1. **目标**：把平台作业导出成**装置可直接吃的物料源目录**（装置此前只读仓库内 `实验/` 夹具）——这是云上批改真实作业的最后一块拼图。
2. **装置契约（已核实、未改装置）**：源目录必须含 `标准工程包.zip`（STANDARD_NAME）、`评分标准.md`（RUBRIC_NAME）、**`题目描述.md`**（ASSIGNMENT_NAME）；学生提交为源目录下 `*.zip`（文件名即装置 manifest 的 `id`）。
3. **新增** `server/scripts/r2b20-export-materials.mjs`：`--assignment <id> --out <dir> [--db-url] [--allow-db] [--allow-prod] [--uploads-root]`；产出三必备文件 + 每个提交一个 `<real_name>.zip`（重名追加 `-<username>`）+ `export-manifest.json` 审计（submissionId → zip 名 / 来源路径 / 来源版本 / sha256 / 份数 / questionId / 生成时刻）。
4. **★确定性**：新增 `server/src/services/deterministicZip.js`（无第三方依赖、Node 内置 zlib）——条目名按字节序排序、DOS 时间戳固定 1980-01-01、压缩级别固定、无随机/时间字段 ⇒ 同输入两次导出，各 zip 与各 md 的 **sha256 逐一相同**。
5. **★只读**：不写平台 DB、不改 `server/uploads/**`（只写 `--out`）；路径定位**复用** `server/src/utils/projectPaths.js`（`standardDir`/`SUBMISSIONS_ROOT`/`UPLOADS_ROOT`），未另写一套（`--uploads-root` 只做「同相对路径重定位」，供测试/演练）。
6. **护栏**：生产库需 `--allow-db <库名>` + `--allow-prod`，**连接前**判定（缺开关 ⇒ `EXPORT_FAIL reason=allow_db_required:exam_system`、rc=2、不打印 `EXPORT_TARGET`、不连接）；作业没有**恰好一个** project 型题目 ⇒ `EXPORT_FAIL reason=project_question_not_unique:<n>`；标准包目录缺失/空 ⇒ `standard_package_missing`（不猜、不静默）。
7. **可观测**：成功 `EXPORT_OK n=<份> question=<id> standard_sha256=… rubric_len=… out=…`（+ `EXPORT_SKIPPED n=… reasons=…`），失败 `EXPORT_FAIL reason=…`。
8. **测试**：新增 w45（unit，5 例：装置常量逐字一致 / 命名与重名 / 护栏 / 确定性 zip / 题面 markdown）与 w47（integration，6 例：布局与装置契约 / 确定性逐文件 sha256 / 只读 / 无 secrets / CLI 护栏 rc=2 不连接 / CLI `EXPORT_OK n=2`）。
9. **文档**：`docs/dsh/deploy/README.md` 的「物料来源」缺口两处更新为**已实现**（用法、产出、确定性、只读与护栏、云上调用示例、前置条件）。
10. **verify（串行）**：check-layers 0 违规；unit 55 套件/720 例；contract 3/50；三重度 17/61/21；integration 58 套件/435 例；smoke 8/8；生产库指纹 before/after **逐位相同**。

## 4 云上调用（与 README §7-1 一致）
```bash
cd /opt/exam/server
OUT=/var/lib/dsh-grader/materials/assignment-311
node scripts/r2b20-export-materials.mjs --assignment 311 --out "$OUT" \
  --db-url "mysql://<user>:<pass>@127.0.0.1:3306/exam_system" --allow-db exam_system --allow-prod
# 期望：EXPORT_TARGET db=exam_system prod=yes ⇒ EXPORT_OK n=<份> question=<id> standard_sha256=… rubric_len=… out=…
# 之后：以 --source-dir "$OUT" 拉起装置（复用模式配 --reuse-checker ⇒ 零 LLM）
```
前置条件：①题目标准包存在（`attachment_url` 或 `uploads/project-questions/<qid>/standard/` 非空）②学生提交已落盘 `uploads/project-submissions/<qid>/<studentId>/<version>/` ③作业**恰好**绑定一个 project 型题目。

## 5 未验证项（单列）
1. **未在生产库上跑导出**（本轮禁写生产、且导出虽只读仍属跨库操作）：队长将在生产上做最终等价验证（导出 311 ⇒ 复用模式跑装置 ⇒ 期望 `written=59 skipped=0` 且分数逐生一致）。
2. **未跑真实装置的 `prepare_materials.py`**（不执行装置/不跑造尺会话）：本轮的装置契约对齐用**常量逐字比对**（w45-1）+ **布局/zip 可解析性**（w47-1）覆盖，均指向装置会走 `MATERIALS_OK` 分支；但「装置实际输出 `MATERIALS_OK`」未由我实测。
3. **`--uploads-root`** 是测试/演练开关（重定位 uploads 根）；生产请勿使用（不传即为真实 uploads）。
4. **与标准包逐字节相同的提交**未做跳过于导出侧（留给装置 `--allow-identical` 决策）——若某作业需要「导出阶段就排除雷同提交」，需后续增强。
5. **62/59 份规模的导出耗时**未压测（单份 zip 为 tens of KB 级；本机 w47 用例 2 份 < 10 ms）。

## 6 自纠清单
1. **第一次写导出器时脚本里有一个拼写错误**（对象字面量里多了一个字符串片段）导致语法错误 ⇒ 重写该行并 `node --check` 通过；教训：长文件先 `node --check` 再跑。
2. **未用第三方 zip 库**：需求禁止新依赖，且**确定性**要求排除库内时间字段 ⇒ 自写最小 ZIP writer（deflate + CRC32 + 固定 DOS 时间戳），并以 `readZipEntries` 做往返校验。
3. **测试改写真实 uploads 的风险**：装置与导出器的路径都锚在 `server/uploads`（out of scope、只读）⇒ 采用 `--uploads-root` **重定位**（复用 projectPaths 的相对路径），夹具放 `/tmp`，并把「导出前后夹具树不变 + 真实 uploads 未生成新目录」写成断言（w47-3）。
4. **同名同学的确定性**：两份提交 realName 相同 ⇒ 第二份按 `-<username>` 命名；命名函数接收 `used` 集合、由调用方按 `submission.id` 升序遍历 ⇒ 结果确定（w45-2/w47-1 覆盖）。
