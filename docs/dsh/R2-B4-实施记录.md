# R2-B4 实施记录（批 4：job 执行器 + 并发闸接线 + stub 端到端入口）

## 摘要（≤10 行）
1. **执行器落地**：`dshGradingJobWorker.js` —— 消费一个 pending job → 拉起隔离装置（`DSH_HOME` 注入、凭据只经子进程 env、run-root 在 `/tmp`）→ 读 run-root 产物 → 走批 3 的消费路径（校验仍由 `validate.py` 子进程负责）→ 写分或标 `needs_rerun`。
2. **并发闸**：上限 = `dsh_grading_concurrency`（默认 1，批 1 getter）；**闸满时不领取 job**（job 保持 pending、attempts 不变），跑完在 `finally` 释放。
3. **失败语义**：装置 exit 5/6 或产物缺失 ⇒ job=`needs_rerun`（**不写分、不落 0 分**）；超时 ⇒ SIGKILL + 释放闸 + attempts 递增 + 回 `pending` 可重试（≥3 次 ⇒ `failed`）。
4. **原子领取**：先选候选，再单条 `UPDATE … WHERE id=? AND status='pending'`（affectedRows=1 才算领到）⇒ 同一 job 不可能被两个 worker 同时消费。
5. **stub 端到端入口**：`node scripts/r2b4-smoke.mjs`（从 server/ 运行）——自建探针数据 + stub 装置，零模型调用，6 项断言全过、退出码 0。
6. **安全**：生产库只读指纹跑前/跑后**逐位不变**；新文件 `sk-` 命中 0；run-root 内 `.credentials.yaml` 0 个；不占 :5173/:3000/:19387（这三个监听是用户自有实例）。
7. 复用而非重写：装置拉起用批 1 的 `runDshGrader`（仅新增 `extraEnv` 透传，默认行为不变）；消费用批 3 的 `consumeChecker`/`consumeMeasureResults`/`decideScoreWrite`。
8. **测试**：新增 w15（7 例：闸不重叠/闸满不领取/原子领取/exit6/missing/超时可重试/finishJob 字段）+ 既有测试零修改；verify 七段串行全绿。
9. 未新增迁移（批 3 的 `grading_jobs` 列已够用：attempts/written_count/skipped_count/last_error/status）。
10. 未验证项与自纠见 §4/§5。

### 2.3 失败/超时语义
- W15-4（exit 6）⇒ `status=needs_rerun`、`lastError=device_exit_6`、**无任何 submission.update**；W15-5（产物缺失）⇒ `artifacts_missing`；W15-6（超时）⇒ 首次回 `pending`（可重试）+ `gate.active=0`；attempts=3 ⇒ `failed`。

## 4 未验证项（单列）
1. **真实装置（非 stub）的作业级联调**：执行器与真实 `scripts/dsh-grader/run.sh` 的组合未跑（会消耗真实模型调用；本批验收口径要求零模型调用）。接口层已对齐（run-root 布局、exit 码、`DSH_HOME` 注入）。
2. **常驻 worker 循环**：本批交付的是 `runOnce`（单次消费）+ 幂等语义；没有守护进程/定时拉起（建议由平台外部调度或批 5 实现）。
3. **多进程并发**：闸是**进程内**信号量；跨进程安全只依赖原子领取（同 job 不双消费 ✓），但「全局并发上限」在多进程部署下需 DB 级闸（未实现）。
4. **`needs_rerun` 的重跑入口**：job 状态已标，但没有「一键重跑」端点（重跑=再次 `runOnce`，语义已具备）。

## 5 自纠清单
1. **w15 假装置写偏 run-root**：初版把 fixture 写到固定目录，而 `runOnce` 自建 run-root ⇒ 断言退化成 `artifacts_missing`；改为从传入 `args.runRoot` 取真实路径。
2. **w15 fake prisma 未模拟 SQL**：`$executeRawUnsafe` 直接返回 1 但不翻状态 ⇒ 断言 `status='running'` 失败；改为忠实模拟（affected=1 时把该行翻 `running` 且 attempts+1）。
3. **w15 区间记录顺序 ≠ 时间顺序**：`log1` 按 push 顺序判断重叠会假失败；改为按开始时间排序后比较。
4. **两次并发 jest 自伤**：verify 尚未结束时又跑了 w15 ⇒ setup.js 的清理在同一测试库上竞态（`prisma.user.delete` 报记录不存在）。已在空跑环境下重跑 verify 全绿；再次印证「测试禁止并发」。
5. **清理**：运行期产生的 `server/out/checker/checker.json`（stub 在缺 `GRADER_RUN_ROOT` 时的落点）已删除，避免污染工作树。
