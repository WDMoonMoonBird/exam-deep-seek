# R2-B54 修复记录：根除路由过渡竞态（App.vue 顶层遗漏）+ UI 不再透出原始 JS 错误

> 摘要（≤10 行）：① **实机现象**（白屏修好后的后续）：强刷复测白屏已解决 ✓，但偶发弹「加载失败：Cannot read properties of null (reading 'parentNode')」，用户无法复现。
> ② **两处根因**：(a) 该文案出自 `Students.vue` 把 `e.message` 拼进 UI（同族还有 `ReviewClass.vue`/`Review.vue`/`admin/GradingRuns.vue`）⇒ 原始 JS 错误**上屏**；
> `Cannot read properties of null (reading 'parentNode')` 是典型 **DOM/过渡竞态**：路由过渡在异步组件解析或导航中途操作已移除节点。
> (b) ★**上批 B52 只改了两处 Layout，漏了 `App.vue` 顶层** `<transition :name="route.meta.transition||'page-fade'" mode="out-in">`（它包住整个顶层 router-view）⇒ 顶层仍保留 out-in 卡死 + 竞态路径。
> ③ **修法**：移除**全部**「包住路由组件」的 `<transition>`（App + teacher/admin/student 三个 Layout）；四个入口都用 `ErrorBoundary` 包住 router-view（外层），并在 `v-slot` 内再包一层 **keyed** `ErrorBoundary :reset-key="route.fullPath"`（页面自身抛错也进边界 UI、随路由复位）；
> 所有面向用户的错误文案改为**固定友好文案**（如「数据加载失败，请重试」），原始错误一律 `console.error`（带组件标签）——**不得进 UI**。
> ④ **防呆**：`verify-frontend` 新增 ⑨a（全仓无路由过渡）/⑨b（UI 无原始 JS 错误插值）/⑨c（v-slot 内 keyed 边界 + 外层边界）/**⑨d（抽取真实函数体执行）**⇒ `checks=30 failed=0 rc=0`；四条变异各自 rc=1 且还原逐字节一致。
> ⑤ 回归：前端核验（含构建）rc=0；jest w52+w61+w62 = 30/30；check-layers 141 文件 0 违规；指纹**按环境**：云上生产 **29** / 本机生产 **28** / 测试库 **30**。

## 1. 实机现象与两处根因
- 现象：偶发提示「加载失败：Cannot read properties of null (reading 'parentNode')」（不可稳定复现 ⇒ 竞态特征）。
- 根因 A（文案）：错误对象被直接拼进 UI 字符串（模板/`a-alert`/toast）⇒ 用户看到 JS 内部错误原文。
- 根因 B（竞态）：`<transition>` 包路由组件时，vue 过渡会在**异步组件解析/导航中途**操作节点；若该节点已被卸载/替换 ⇒ `parentNode` 为 null ⇒ 抛错（再由根因 A 上屏）。`App.vue` 的顶层过渡在 B52 被漏改 ⇒ 顶层仍有该路径。

## 2. 修法
| 项 | 处置 |
|---|---|
| 路由过渡 | **全部移除**：`App.vue`（顶层，B52 遗漏）、`views/teacher/Layout.vue`、`views/admin/Layout.vue`、`views/student/Layout.vue`。理由：路由过渡是**外观收益**，却带来「out-in 卡死 ⇒ 整块空白」与「操作已移除节点 ⇒ parentNode 竞态」两类硬故障 ⇒ 不值得。元素级动画（`tab-fade`/`page-fade` 等 CSS 类）仍可用于页面内部。 |
| 错误边界 | 四个入口：`<ErrorBoundary>`（外层，包住 router-view）**+** `v-slot` 内 `<ErrorBoundary :reset-key="route.fullPath">`（**keyed**，包住 `<component :is="Component" />`）⇒ 页面自身 setup/render 抛错也进边界 UI（重试/刷新/路由），并随路由变化自动复位（C40-O2 追加项）。两处均**无** transition。 |
| UI 文案 | `Students.vue` / `ReviewClass.vue` / `Review.vue`：新增 `friendlyLoadError(err)`（`console.error('[R2-B54] <组件> 数据加载失败…', err)` + 返回 `数据加载失败，请重试`）；`admin/GradingRuns.vue`：读取详情/读取日志/下载日志三处改为固定文案 + `console.error`；`ErrorBoundary.vue`：界面只显示**固定**文案（`friendlyText`），不再渲染 `state.message`（原始错误只在 console）。 |
| 服务端业务文案 | `response.data.message`（如上传结果里的业务提示）**保留**（那是服务端给出的友好文案，不是 JS 错误原文）；判定口径见 ⑨b。 |

## 3. 防呆断言（verify-frontend ⑨）
- **⑨a**：遍历 `src/**/*.vue`（先剥注释），任一 `<transition>` 的跨度内含 `<component :is="Component"` 或 `<router-view` ⇒ 失败（含 App.vue 顶层；实测 `violations=(none) scanned=56`）。
- **⑨b**：五个面向用户的文件里，非 console 行不得出现 `err.message`/`e.message`/`error.message` 插值（`data?.message` 服务端文案豁免；注释先剥离）⇒ `rawInUi=(none)`。
- **⑨c**：四个入口的 router-view `v-slot` 内必须是 `<ErrorBoundary :reset-key="route.fullPath">` 包住路由组件且**该处无 transition**；同时外层边界仍闭合在 router-view 之后（`outerMissing=(none)`）。
- **⑨d（可执行）**：从 `Students.vue`/`ReviewClass.vue`/`Review.vue` **抽取真实 `friendlyLoadError` 函数体**并用桩件 `console` 执行两次（模拟「加载中导航离开后再触发」）：断言返回固定文案、**不含** `parentNode`/`Cannot read`、原始错误每次进入 console、且**不抛**（三个文件均 OK）。
- 变异对照：M1 在 App.vue 给路由组件套回 `<transition>` ⇒ ⑨a rc=1；M2 把 `e.message` 拼回 Students.vue 的 UI 文案 ⇒ ⑨b rc=1；M3 去掉 Layout 的 `:reset-key`（keyed 边界失效）⇒ ⑨c rc=1；M4 把 teacher Layout 的外层边界换成普通 `<div>` ⇒ ⑦f rc=1；四文件还原后 sha256 **逐字节一致**。
