# R2-B11 修复记录（worker 调装置 cwd 错误 ⇒ 相对装置路径 exit 127）

## 摘要（≤10 行）
1. **真实现场复现**：`--device bash --device-arg scripts/dsh-grader/run.sh` 由 worker 拉起时，子进程 cwd 是 **run-root**（`/tmp/r2b4-job-*`）而非仓库根 ⇒ `bash: scripts/dsh-grader/run.sh: No such file or directory` ⇒ **exit 127** ⇒ job `needs_rerun` / `last_error=device_exit_127`（生产零写入 ✓）。
2. **根因（比报告更精确一处）**：`dshGradingJobWorker.js` **有**传 cwd，但传的是 `cwd: runRoot` ✗；正确口径是「仓库根」（与 `r2b7-build-checker.mjs:275` 的 `cwd: REPO` 一致）。
3. **修法一（cwd）**：`runOnce` 复用已有的 `repoRoot` 参数 ⇒ `const repoRootAbs = path.resolve(repoRoot)`，传给 runner 的 `cwd: repoRootAbs`。
4. **修法二（路径绝对化，双保险）**：新增导出函数 `absolutizeDeviceArgs(args, repoRoot, extraBases)`：裸相对路径按「仓库根 → server/」两个基准解析为绝对路径（仅当目标存在时才替换）；`PATH_FLAGS`（`--workdir/--checker/--source-dir/--checker-out/--out/--manifest`）的取值同样处理；绝对路径与非路径 token（`63`、`build-and-measure`）**原样保留**。
5. **★实测（w32）**：用**相对装置路径** `--device node --device-arg scripts/stub-device.mjs` 跑通真实消费 ⇒ job `done` / `written_count=1` / `last_error` 不含任何解析失败特征串，run-root 内有装置产物 ✓；负向对照 `bash scripts/dsh-grader/run.sh`（cwd=server/）⇒ **exit 127** + `No such file or directory`（复现同一故障类 ✓）。
6. **★cwd 断言（w31）**：用注入的假 runner 捕获真实参数 ⇒ `captured.cwd === 仓库根`（绝对且存在），`captured.args[0]` 由 `scripts/dsh-grader/run.sh` 变为**绝对路径**，其余 token 未被改动；复用模式下 `--checker` 也是绝对路径且 cwd 不变。
7. **相对路径依赖清单**：见 §3（逐条确认在 cwd=仓库根 下成立；装置内部 `HERE`/`DSH_REPO_ROOT` 均为绝对推导，`SOURCE_DIR` 的相对值由 `--repo <绝对>` 兜住 ✓）。
8. **cwd 口径一致性**：r2b7 = `cwd: REPO` ✓；worker 现在 = `cwd: 仓库根` ✓ ⇒ 两个入口一致。
9. **verify（串行）**：check-layers 0 违规；unit 53 套件/712 例；contract 3/50；三重度 17/61/21；integration **46 套件/389 例**；smoke **8/8**；生产库指纹 before/after **逐位相同**。
10. 本轮不写生产、不跑真实装置；既有测试文件零修改（只新增 w31/w32）。

## 1 缺陷与修法（代码级）
```diff
  server/src/services/dshGradingJobWorker.js
  // 修前（R2-B4 起一直如此）：装置子进程 cwd = run-root
-     cwd: runRoot,
  // 修后：仓库根（相对装置路径 scripts/dsh-grader/run.sh 才解析得对）
+     cwd: repoRootAbs, // ★R2-B11
  // 新增：参数路径绝对化（双保险，即使调用方 cwd 不对也不会解析错）
+     const finalArgs = absolutizeDeviceArgs(runArgs, repoRootAbs);
```
- `absolutizeDeviceArgs` 的基准顺序：**仓库根优先**（`scripts/dsh-grader/…`），其次 **server/**（平台自带脚本 `scripts/stub-device.mjs`）——两者都存在时以仓库根为准（与操作者心智模型一致）。
- 复用模式不变：`withReuseCheckerArgs` 追加的 `--checker`（绝对 frozen 路径）依旧绝对（w31-3 断言）。

## 6 未验证项（单列）
1. **真实装置 + 生产库的端到端**未跑（本轮不跑真装置、不写生产）：本轮证明的是「cwd 与路径解析口径正确 + 相对路径消费链路走通」；装置内部的模型调用链路由 R2-B8 的 dump-config 证据与队长实跑覆盖。
2. **`--source-dir` 指向仓库外目录的相对写法**未覆盖（`absolutizeDeviceArgs` 只在两个基准内查找；找不到时保留原值 ⇒ 由调用方保证绝对路径）。
3. **同名 token 边界**：若某次 `--device-arg` 里恰好有一个与仓库内文件同名的普通 token，它会被绝对化；当前装置参数集无此情形（已在该记录说明）。

## 7 自纠清单
1. **负向对照前提写错**：初版用 `node scripts/stub-device.mjs` + cwd=server/ 作「必然失败」对照，但该脚本**就在** server/scripts/ 下 ⇒ 它成功了 ✗ ⇒ 改为队长真实现场的形状 `bash scripts/dsh-grader/run.sh`（server/ 下不存在）⇒ exit **127** + `No such file or directory` ✓。
2. **相对参数基准不够**：只按仓库根绝对化时，`scripts/stub-device.mjs`（平台自带脚本，位于 server/）解析不到 ⇒ 改为**双基准**（仓库根优先、server/ 兜底）并补测。
3. **断言空值坑**：`expect(after.lastError).not.toMatch(...)` 在成功路径（`lastError` 为 `null`）会报「Received has value: null」⇒ 改为先 `String(x || )` 归一化。
