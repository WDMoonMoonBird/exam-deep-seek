## 4 ③r2b7 装置参数语义（修复「传一个参数丢掉默认集」的陷阱）
```bash
node scripts/r2b7-build-checker.mjs --assignment 1 --dry-run --device-extra-arg --allow-identical
# PLAN … device_args=["scripts/dsh-grader/run.sh","--checker-mode","build-and-measure","--submissions","2","--workdir","…","--timeout","1800","--allow-identical"]  ← 默认集仍在 + 追加在末尾
node scripts/r2b7-build-checker.mjs --assignment 1 --dry-run --device-arg a --device-arg b
# PLAN … device_args=["a","b"]                    ← --device-arg 仍是整体替换（既有语义不变）
node scripts/r2b7-build-checker.mjs --assignment 1 --device-arg x --device-extra-arg y --dry-run
# RESULT=USAGE_ERROR reason=device_arg_conflicts_with_device_extra_arg   rc=4
```
| 参数 | 语义 | 推荐用法 |
|---|---|---|
| `--device-arg <a>`（可重复） | **整体替换**默认参数（传一个就丢掉 `run.sh --checker-mode build-and-measure …`） | 仅当要完全替换装置命令时使用 |
| `--device-extra-arg <a>`（可重复，新增） | **追加**到默认参数之后 | ★微调默认装置（如加 `--allow-identical` / `--source-dir`）时用它 |

## 6 自纠清单
1. **「未配置」在测试环境不可直接构造**：`@prisma/client` 会自动把 `.env` 载入 `process.env`，因此 `DEEPSEEK_MODEL` 在测试进程里始终有值 ⇒ 我最初「断言一定打 (unset:device-default)」的写法是错的。改为**两层确定性口径**：纯函数（`llmEnv({})==={}`）+ 运行期一致性（摘要值 == 子进程收到的值）——既覆盖「未配置不注入」的语义，又不依赖具体环境。
2. **`env: { X: undefined }` 不等于删除**：spawn 的 env 合并里 undefined 值不会真正剔除，必须显式 `delete`/构造新对象（W28 的 `mergedEnv`）。
3. **测试库 `system_configs` 无 LLM 键**（只读核对：仅 `project_context_mode`）⇒ 之前误以为配置来自 DB；实际来源是 `.env` 经 Prisma dotenv 载入 env，已在该记录 §3 写清解析顺序。
4. **worker 假日志坑**：`--once` + 双开关 + 不可达 URL 的退出码是 **0**（循环把连接失败计为 failures 后正常收尾）⇒ 只看 rc 会误判；测试因此改为断言 `failures=1` + `STAGE=connect`（机制级），并反向断言拒绝态**没有**这些标记。
