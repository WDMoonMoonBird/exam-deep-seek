# R3.5-A 设计：作业级「一次造尺、N 次量」流程

## 摘要（≤10 行）
1. 缺口确认：现状 `run.sh --submissions N` 是**一份提交一把尺**（R3-B §6.4 自述；`run.sh:168` 起每份各走一次造尺会话），而方案的中心机制是「一次造尺、N 次量」。
2. 可复用件已存在：`--checker` ⇒ `MODE=measure-only`（`run.sh:38/60-61/364-368`，零模型调用）、C1–C8 闸（`shape_checks.py:53-195/`:220）、覆盖率与投影（`coverage_report.py`、`extract_result.py --project`）。
3. 本设计把三者串成**作业级流程**：造尺一次（**不含任何学生提交**）→ C8 全量可量性预检 → 固化（frozen checker + manifest）→ N 次 measure-only → 作业级 reconciliation / comparability。
4. 关键取舍：造尺输入只含标准包 + rubric + 作业描述；**把学生提交从造尺 prompt 里移除**，否则跨份不可比（现状 prompt 含 `$PROJ_ABS` 与 `$SLUG.model.json`，见 `run.sh:311-315`）。
5. C8 现状是**单份探针**（`shape_checks.py:161-168` 取 `--probe-submission` 或第一份）⇒ 必须扩为**全量探针**：全员不可量 = 造尺不合格（exit 5，计入重造）；部分不可量 = 单份 `unmeasurable`，作业 PARTIAL。
6. 失败语义分两层：**整作业 FAIL**（造尺失败/闸不过/尺子被篡改/全员不可量）与**单份 failed/unmeasurable**（不回滚其它份，不编造分数）。
7. 可比性：唯一可比组 `(assignment_id, checker_id)`；跨 `checker_id` 一律 `not_comparable`。**canonical 只用于「同一份跨遍比对」**（树摘要含文件名 ⇒ 跨份比 canonical 无意义，见 F-R3C-3）。
8. 实验 E-F（一次造尺 + N 份 measure-only 两遍 canonical 逐份一致，第二遍模型调用 0）、E-G（造尺失败整作业语义，含全员/部分不可量）、E-H（同尺同内容跨时间/跨 workdir 重跑口径与**明确不保证项**）。
9. 装置侧可完成全部流程与产物；平台侧只承担入库/触发/并发闸/分数回写（§2）。
10. 施工单 8 条限 `scripts/dsh-grader/**` 与 `docs/dsh/evidence/agent-b/**`；拍板 5 点见 §6。

## 1 作业级流程契约
### 1.1 六步流水（每步：输入 → 输出 → 失败语义）
**S1 造尺（一次，含 1 次模型调用）**
- 输入：`materials/{rubric.md, assignment.md, standard/}`（**不含** `submissions/`）；`rubric-sections.json`（R3-A §3 建议件，若尚未落地则以 rubric.md 为准）。
- 输出：`out/checker/{checker.json, rubric-coverage.json, checker.provenance.json}`。
- 失败：会话非 0/超时 ⇒ **整作业 FAIL**（exit 1 / 124，无任何分数）；C1–C7 不过 ⇒ K 重造（默认 1，上限 2，`run.sh:20/54-57`）⇒ 耗尽 **exit 5**、不产分数（`run.sh:452`）。

**S2 C8 可量性预检（零 LLM，**全量**）**
- 输入：S1 的 checker + **全部 N 份** `materials/submissions/<slug>`。
- 输出：`out/probe/c8-<slug>.json`（每份一份）+ `out/probe/c8-summary.json`（`{n, unmeasurable:[slug…], checked:true}`）。
- 失败：`unmeasurable == N` ⇒ **视为造尺不合格**（计入重造；耗尽 exit 5）——这正是 F-R3C-1 的形态（闸绿但量不动）；`0 < unmeasurable < N` ⇒ 这些份标 `unmeasurable`（无分），其余继续，作业 PARTIAL；`0` ⇒ 继续。
- 现状差距：C8 只探 1 份（`shape_checks.py:161-186`）⇒ 换布局后可能「探针过、其余全灭」，必须扩为全量。

**S3 固化（frozen）**
- 输入：S1 checker + materials 清单。
- 输出：`out/assignment/checker.frozen.json`（**字节复制**，不复算、不美化）+ `out/assignment/assignment-manifest.json`：`{assignment_id, checker_id, frozen_sha256, materials_manifest_digest, n_submissions, submissions:[{slug, zip_sha256, project_root_glob_probe}], device_version, created_at, mode}`。
- 失败：frozen 与 `validate.py` 复算的 `checker_id` 不一致 ⇒ **整作业 FAIL（exit 3）**，拒绝量尺（防中途换尺）。

**S4 measure-only（N 次，**零 LLM**）**
- 输入：frozen checker + 每份提交；命令模板：
  `python3 scripts/dsh-checker/check.py --checker out/assignment/checker.frozen.json --submission materials/submissions/<slug> --submission-id <slug> --rubric materials/rubric.md --standard materials/standard --out out/measure/<slug>.json`
- 输出：`out/measure/<slug>.json`（`checker-result/1`）+ 投影 `out/grading-result/<slug>.json`（`extract_result.py --project`，字段形状沿用平台兼容契约）。
- 失败：单份 `INPUT_PROBLEM`/`stale`/`unsupported` ⇒ 该份 `failed`（无分，不编造；投影拒绝编造是既有正确行为，见 R3-C §2:27）——**不回滚其它份**。

**S5 作业级产物**
- `out/assignment/reconciliation.json`：N 份矩阵拼合 + 计数（`items_total, hit, miss, missing, unreadable, unsupported`）。
- `out/assignment/comparability.json`：`{assignment_id, checker_id, n, ok:[slug…], failed:[…], unmeasurable:[…], digests:{slug: sha256}, comparable_within:true, comparable_across:false}`（**单一 checker_id**，出现 >1 即 FAIL）。
- `out/checker/coverage.json`（一次）+ `out/grading-results.json`（N 份投影数组，沿用 `run.sh:600-611` 的形状）。

**S6 汇总**
- 必须打印：`ASSIGNMENT_RESULT=PASS|PARTIAL|FAIL`、`N=`、`MEASURED=`、`FAILED=`、`UNMEASURABLE=`、`CHECKER_ID=`、`MODEL_CALLS=`（造尺 1 / 复用 0）、`MEASURE_CALLS=0`、`ELAPSED_SEC=`、`WORKDIR=`。
- 退出码：0=PASS/PARTIAL；1=PARTIAL 且 `--strict`；3=尺子被篡改；5=造尺不合格；124=造尺超时。

### 1.2 失败影响面（哪个失败整作业死、哪个只标该份）
| 失败点 | 影响面 | 产物 | 退出码 |
|---|---|---|---|
| 造尺会话非 0 / 超时 | **整作业** | 无分数；`out/logs/session-*.err` | 1 / 124 |
| C1–C7 不过（K 耗尽） | **整作业** | 无分数；`out/diagnostics/shape-checks.json` | 5 |
| C8 全员不可量 | **整作业**（=造尺不合格，计入重造） | 无分数；`c8-summary.json` | 5 |
| C8 部分不可量 | **单份** | 该份 `unmeasurable`、无分 | 0（`--strict`⇒1） |
| frozen 被改（id 复算不符） | **整作业** | 拒绝量尺 | 3 |
| 单份 measure INPUT_PROBLEM / stale | **单份** | 该份 `failed`、无分 | 0（`--strict`⇒1） |
| 单份投影失败（items_empty 等） | **单份** | 该份 `failed`，**不编造分数** | 0（`--strict`⇒1） |
| 覆盖率文件缺失（measure-only 复用） | 不失败 | `REQUIRE_COVERAGE=no`（现状 `run.sh:433`） | 0 |

## 2 与 R2 的边界（谁承担什么）
| 能力 | 装置侧（本设计） | 平台侧（R2-A 施工单） |
|---|---|---|
| 造尺一次 + 闸 + 重造 | ✅ 全部 | — |
| 固化与篡改防护 | ✅ frozen + manifest + id 复算 | 入库时二次校验 |
| N 份 measure-only | ✅ 串行、零 LLM | 并发闸 `dsh_grading_concurrency`（W4） |
| 作业级 reconciliation / comparability | ✅ 落文件 | 读文件入库（W6） |
| checker 持久化（版本/多作业复用） | ❌ 只落 workdir | ✅ `grading_checkers` 表（W6） |
| 何时触发（截止后/教师点） | ❌ | ✅ 作业级端点 + 队列（W7） |
| 分数回写（aiScore/aiFeedback/checker_id/canonical_sha256） | ❌ | ✅（W7） |
| 教师可见的尺子版本/覆盖率/uncovered 提示 | 只产数据 | ✅ UI 措辞（§3） |
- **两种分工取舍**：① **装置出产物、平台读文件入库**（建议）——装置零 DB、可离线复算、回滚=不读文件；代价是平台多一个"文件→库"的消费层与一致性检查。② 装置直连 DB 写分——省一层，但把装置绑死在库上、破坏"可离线复算"、且与"装置不写生产库"的铁律冲突。**建议 ①**。

## 3 可比性表达（写给教师看的措辞）
- **口径**：可比组 = `(assignment_id, checker_id)`；`checker_id` 不同（含 rubric/标准包/predicates 任一字节变化）⇒ `not_comparable`，禁止排名/均分对比。
- **建议文案（教师端）**：
  - 首屏：`本作业共 N 份提交，使用同一把尺子（checker_id 前 12 位）批改；分数可横向比较。`
  - 跨作业：`与其它作业的分数不可比（尺子版本不同）。`
  - 覆盖率：`评分标准共 M 段，本尺子覆盖 X 段、部分覆盖 Y 段、未覆盖 Z 段` + 展开列出**未覆盖段标题**，并注明`未覆盖项不计 0 分，按"未评估"处理`（避免用 0 分冒充"没做到"）。
  - 不可量份：`M 份提交因工程布局无法测量，未出分：<学号…>`（可点开看 `c8-summary.json` 的原因）。
  - 复算声明：`同一份提交重复测量得到完全相同的分数（装置已复算验证）`——只声明"可复现"，**不**声明"分数正确"。

## 4 实验设计（可证伪）
**E-F 一次造尺 + N 份 measure-only 的 canonical 复算一致性**
- 命令：第一遍 `bash scripts/dsh-grader/assignment_run.sh --source-dir 实验/注入测试集 --workdir /tmp/r35-f --timeout 1800`；第二遍 `bash scripts/dsh-grader/assignment_run.sh --reuse-workdir /tmp/r35-f --measure-only`（或 `run.sh --checker out/assignment/checker.frozen.json --submissions N`）。
- PASS：第一遍 `MODEL_CALLS=1`、第二遍 `MODEL_CALLS=0`；两遍**逐份**（按 `zip_sha256` 对齐）`canonical_sha256` 相同；`comparability.json` 只含 1 个 `checker_id`；全部 `unsupported` 为空。
- FAIL：任一份两遍 canonical 不同；第二遍出现模型调用；可比性里出现 >1 个 checker_id。
- 注：**禁止**用 canonical 跨份比对（`submission.digest` 含文件名与内容，见 F-R3C-3）；跨份只比"分数 + item 明细"。

**E-G 造尺失败时整作业的失败语义**
- (g1) C4 注入：故意把某个 predicate 的 `max_score` 撑爆满分 ⇒ 闸 C4 FAIL ⇒ K 重造耗尽 ⇒ **exit 5**、`out/grading-result/**` 为空、无 `assignment-manifest.json`（或只有 `status=shape-failed` 诊断件）。
- (g2) C8 全员不可量：按 F-R3C-1 复现（提交目录再套一层 + checker 用 `**/UserManagement*`）⇒ 期望**闸内**判不合格（exit 5），而不是"闸绿、量尺全灭"（现状 :433/:435 只探 1 份会漏）。
- (g3) 部分不可量：只把 1 份套两层 ⇒ 期望 `ASSIGNMENT_RESULT=PARTIAL`、`UNMEASURABLE=1`、该份无 `grading-result`、其余 N-1 正常出分；`--strict` ⇒ exit 1。
- FAIL：g1/g2 出现任何分数产物；g3 整作业被判失败、或该份被静默给 0 分。

**E-H 同一把尺子在不同时间/同机重跑的 canonical 一致性口径**
- **保证**：同 `checker_id` + 同提交内容（同一 zip 重新解压）⇒ `canonical_sha256` 逐位相同；与时间、CWD、`TZ`/`LC_ALL`/`PYTHONHASHSEED`、mtime、机器负载无关（容器：`run_meta` 已排除、遍历排序、utf-8 固定）。
- **不保证（必须写明）**：① 提交目录被增删改名 ⇒ `submission.digest` 变 ⇒ canonical 变（分数可能不变）；② 跨 OS / 跨 Python 小版本未验证；③ zip 内非 UTF-8 文件名的修复逻辑只在同版本内确定；④ `scanner` 时间戳类字段只允许存在于 `run_meta`。
- 命令：同 workdir 隔 ≥10 分钟重跑 measure-only；再换 workdir 用同一 frozen checker + 同一 zip 重放；`python3 -c "import json;…"` 比对 canonical。
- PASS：两处 canonical 相同（或差异能唯一归因到上述 ①–④ 之一并给出反证命令）。
- FAIL：同样输入 canonical 不同且无法归因 ⇒ **装置确定性口径被推翻**（R1/R3 结论作废，需回流）。

## 5 给 B 的施工单（≤8 条 · 每条 ≤5 行）
1. **作业级 driver**｜目标：把造尺/闸/固化/量尺/汇总串成一条命令
- 路径：新增 `scripts/dsh-grader/assignment_run.sh`（复用 `run.sh` 的 measure 段 `:214-260`）
- 验收：`--source-dir`/`--workdir`/`--timeout`/`--reuse-workdir`/`--measure-only`/`--strict` 全部可用；失败退出码符合 §1.2
- 风险：不要复制粘贴 run.sh 的隔离与凭据逻辑（调用而非重写）

2. **造尺 prompt 去学生化**｜目标：尺子只由 标准包 + rubric + 作业描述 造出
- 路径：`run.sh:305-330` 的产物与布局块（现状 `:311-315` 含 `$PROJ_ABS` 与 `$SLUG.model.json`）
- 验收：造尺 prompt 内不出现任何 `submissions/<具体 slug>`；`grep -c 'model.json' ` 造尺模板 = 0
- 风险：去掉学生样例会让模型对"真实工程"感知变弱 ⇒ 用 `standard/` 作为唯一工程样例

3. **C8 全量探针**｜目标：预检覆盖全部 N 份，杜绝"闸绿量不动"
- 路径：`shape_checks.py:161-192`（现为单份）→ 支持 `--probe-all`；`shape_gate.sh:1-44` 透传；`run.sh:435` 传参
- 验收：全员不可量 ⇒ `SHAPE_VALID=no` 且 exit 5；部分不可量 ⇒ `SHAPE_VALID=yes` + `c8-summary.json.unmeasurable=[…]`
- 风险：N 份探针 = N 次本地执行器调用（零 LLM），必须计入耗时预算并串行

4. **固化与篡改防护**｜目标：量尺阶段不可能换尺子
- 路径：新增 `out/assignment/{checker.frozen.json,assignment-manifest.json}`（写盘点复用 `run.sh:251` 的 provenance 写法）
- 验收：measure 前用 `validate.py` 复算 id == manifest.`checker_id`；手工改 frozen 一字节 ⇒ exit 3 且无分数
- 风险：frozen 必须**字节复制**（不得重组 JSON，否则 id 语义漂移）

5. **作业级产物**｜目标：reconciliation / comparability / coverage / 投影数组
- 路径：新增 `scripts/dsh-grader/assignment_report.py`（复用 `coverage_report.py:1-149` 与 `run.sh:600-611` 汇合逻辑）
- 验收：`comparability.json` 单 checker_id、`ok+failed+unmeasurable == N`；矩阵计数与逐份结果可对齐
- 风险：MATRIX 拼合不要把 `unsupported` 与 `missing` 混算

6. **失败语义与 `--strict`**｜目标：整作业 vs 单份的边界可执行
- 路径：`assignment_run.sh` 的判定段（对齐 `run.sh:446-452` 的 exit 5 与 `:592-598` 的门控写法）
- 验收：§1.2 表逐行有对应测试（stub 路径即可，零 LLM）；默认 PARTIAL 不算失败
- 风险：默认宽松可能掩盖数据问题 ⇒ summary 必须显式打印 `FAILED/UNMEASURABLE` 计数

7. **模型调用预算断言**｜目标：把"一次造尺"钉成可验证事实
- 路径：`assignment_run.sh` 摘要（对齐 `run.sh:622-628` 的 `RUN_*` 字段风格）
- 验收：第一遍 `MODEL_CALLS=1`、第二遍 `MODEL_CALLS=0`；用 `stub-dsh.sh` 也能断言计数
- 风险：stub 路径与真实路径的计数口径必须一致

8. **证据与不自证**｜目标：C 可用同一命令复算
- 路径：`docs/dsh/evidence/agent-b/R3.5-*.{json,md}` + README 更新
- 验收：`README.md` 增加 `--checker/--max-rebuild/C1–C8/measure-only` 条目（现状 README 完全没写这些，属文档缺口）；报告单列模型调用数、N、逐份 canonical 列表
- 风险：不得声称"分数正确"；只能声明"可复现 + 覆盖率 + 失败语义"
