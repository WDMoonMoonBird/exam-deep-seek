## 二、产品目标

1. **补齐工程类考核短板**：现有题库仅支持单文件代码题，无法考核学生的完整工程能力（多文件组织、依赖管理、构建配置）。工程项目批改填补这一缺口，让教师可以发布包含完整工程结构的实训任务。

2. **三位一体评分体系**：融合机器校验（编译/运行/测试通过率）、AST 静态分析（代码结构合理性）和 AI 语义评审（代码质量/设计模式/最佳实践），让评分比纯 AI 更客观、比纯机器更智能。

3. **高效批改工作台**：教师在一个页面内完成"浏览文件树 → 查看代码 → 查看三方评分 → 确认/调整 → 写评语"全流程，无需切换页面，大幅提升批改效率。

4. **独立模块零侵入**：新功能作为独立菜单"实训任务"出现在教师端侧边栏，新建独立的数据库表，不修改现有 `questions`/`assignments`/`submissions` 任何字段或逻辑。

## 五、界面设计

### 5.1 菜单结构

**决策：独立菜单项，不复用"作业管理"**

理由：
- 实训任务的数据模型（工程包、文件树、三方评分）与现有作业（题库选题、小题评分）完全不同
- 放在同一个菜单会造成概念混淆，教师难以区分"编程作业"和"实训任务"
- 独立菜单可独立迭代，互不影响

教师端侧边栏菜单变更：

```
班级管理
学生管理
教学团队
题库管理
作业管理
评分审核
实训任务        ← 新增，位于"评分审核"下方
```

路由前缀：`/teacher/projects`，子路由：

| 路由 | 页面 | 说明 |
|---|---|---|
| `/teacher/projects` | 实训任务列表 | 默认页，展示全部任务 |
| `/teacher/projects/new` | 发布任务 | 创建新任务 |
| `/teacher/projects/:id/edit` | 编辑任务 | 修改已有任务 |
| `/teacher/projects/:id/submissions` | 提交列表 | 查看全班提交状态 |
| `/teacher/projects/:id/review/:submissionId` | 批改工作台 | 核心批改页 |

## 六、核心交互流程

### 6.1 教师发布任务完整流程

```
教师点击"新建任务"
  → 填写标题、描述、截止时间
  → 选择发布班级
  → 上传标准工程包（zip）
      → 前端调用 POST /api/projects/upload-package
      → 服务端用 adm-zip 解压到 /uploads/projects/{projectId}/standard/
      → 递归读取目录结构，存入 project_files 表
      → 回传文件树 JSON 给前端展示
  → 设置评分权重（三个滑块联动，合计 100%）
  → 保存并发布
      → POST /api/projects
      → 状态设为 published
      → 关联班级（project_classes 表）
```

### 6.2 学生提交 zip 包（P2 学生端，本期仅定义接口）

```
学生提交 zip 包
  → POST /api/projects/:id/submit (multipart/form-data)
  → 服务端用 adm-zip 解压到 /uploads/projects/{projectId}/submissions/{submissionId}/
  → 递归读取目录结构，存入 submission_files 表
  → 异步触发三方评分 Worker：
      1. 机器校验（编译/运行/测试）
      2. AST 静态分析
      3. AI 评审（DeepSeek）
  → 所有评分完成后汇总计算加权总分
  → WebSocket 推送通知教师（复用现有机制）
```

### 6.3 文件存储目录结构

服务端存储路径设计：

```
/uploads/projects/
  └── {projectId}/
      ├── standard/                  ← 标准工程解压目录
      │   ├── src/
      │   │   └── main/
      │   │       └── java/
      │   │           └── ...
      │   ├── pom.xml
      │   └── ...
      └── submissions/
          └── {submissionId}/        ← 每个学生提交解压目录
              ├── src/
              │   └── ...
              ├── pom.xml
              └── ...
```

数据库不存储文件内容本身，只存储文件树元数据（路径、大小、语言类型），文件内容按需从磁盘读取。

### 6.4 文件树前端递归渲染

数据模型（服务端回传）：

```json
{
  "tree": [
    {
      "name": "src",
      "type": "directory",
      "path": "src",
      "children": [
        {
          "name": "App.java",
          "type": "file",
          "path": "src/App.java",
          "language": "java",
          "size": 2048
        }
      ]
    }
  ]
}
```

前端使用 Ant Design Vue 的 `a-tree` 组件，`tree-data` 直接绑定上述 JSON。点击文件节点时：

1. 调用 `GET /api/projects/:id/submissions/:submissionId/file?path=src/App.java`
2. 获得文件内容字符串
3. 根据 `language` 字段设置 Monaco Editor 的 `language` 属性
4. 更新 `modelValue` 展示代码

递归渲染核心逻辑：

```vue
<!-- 文件树节点自定义渲染 -->
<a-tree
  :tree-data="fileTree"
  :field-names="{ children: 'children', title: 'name', key: 'path' }"
  @select="onFileSelect"
>
  <template #title="{ name, type }">
    <FileOutlined v-if="type === 'file'" />
    <FolderOutlined v-else />
    <span>{{ name }}</span>
  </template>
</a-tree>
```

### 6.5 Monaco Editor 只读展示多语言代码

复用现有 `CodeEditor.vue` 组件，新增 props：

```js
// 使用方式
<CodeEditor
  :modelValue="fileContent"
  :language="currentLanguage"  // 动态切换
  :readOnly="true"
  :height="editorHeight"       // 填满分栏高度
/>
```

语言自动映射：前端根据文件后缀设置 Monaco language ID，列表见 5.5 节。

## 九、待确认问题

| # | 问题 | 影响决策 | 建议方向 |
|---|---|---|---|
| Q1 | 学生 zip 包大小上限？ | 决定上传限制和存储规划 | 建议 50MB，覆盖大多数课程项目 |
| Q2 | 标准工程包中是否允许二进制文件（.class/.jar/.exe）？ | 影响解压安全策略 | 建议默认过滤 `node_modules/`、`.git/`、二进制文件 |
| Q3 | 机器校验在什么环境执行？ | 需要沙箱/容器支持 | 建议第一版仅做编译检查（比较轻量），运行测试用 Docker 沙箱（P1） |
| Q4 | AST 分析支持哪些语言？ | 决定 `acorn`/`@babel/parser` 等解析器选型 | 建议 P0 仅支持 Java（`java-parser`）和 Python（`ast` 模块），其他语言 P1 |
| Q5 | 三方评分是同步还是异步？ | 异步需要 Worker + 状态轮询，同步可能超时 | 建议复用现有 Worker 模式异步评分，提交后立即返回"评分中"状态 |
| Q6 | 教师调整分数后，是否保留三方原始分？ | 影响 `project_submissions` 表字段设计 | 建议保留（`machine_score`/`ast_score`/`ai_score` 存原始分，`final_score` 为教师调整分） |
| Q7 | 标准工程包修改后，已提交学生的评分如何处理？ | 影响评分一致性 | 建议任务发布后锁定标准包，如需修改走"升级版本"机制（P2） |
| Q8 | 是否需要支持小组提交？ | 影响提交模型设计 | 建议 P0 仅个人提交，小组留 P2 |
