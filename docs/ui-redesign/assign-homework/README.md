## 现状实测（问题清单，逐条有据）
1. **一次只能布置 1 道题**：步骤① 用 `type: 'radio'`；但接口 `POST /teacher/assignments` 收的是 `questionIds` **数组**，数据库有 `assignmentQuestions` 关联表且按 `sortOrder` 写入序号 —— **后端与数据模型早就支持多题，是前端把自己锁死了**。要出 3 题作业就得建 3 条作业、重复设 3 次时间与班级，评分审核/导出随之翻 3 倍。
2. **点行不选中**：实测点标题文字、点难度列 → `checked=0`；必须精确点到 15px 圆点 → `checked=1`。
3. **信息被步骤切碎**：标题/时间在最后一步，选题时看不到「交给谁、何时交」；步骤条**不可点击**（实测 `stepsClickable=0`）。
4. **无默认值**：起止时间默认空（实测 `rangeEmpty=true`），每次手点两次日历；无「一周后截止」快捷。
5. **校验晚且含糊**：只有第 3 步提交才校验，提示 `请填写完整`，不说缺哪个字段。
6. **开关 + 二次确认弹窗**：练习模式要弹带红按钮的确认框（4 条说明 + 不可逆警告）；解释性内容应长在选项旁。
7. **选班看不出工作量**：班级列表不显示人数（实测 `showsHeadcount=false`）。
8. **手机端走不通**：390 宽视口下弹窗仍 **820px**，实测「可选班级」左栏 `left=-406`（完全在屏幕外），屏幕只剩右栏「已选 0 个班 / 请从左侧选择」——不是"挤"，是**选不了班**。

保留的优点：班级点选（优于下拉多选）、题目搜索、开放性题目「无标准工程包」软警告流程。

## 提案要点
- **一页式两栏**（弹窗 820 → 1040，与项目既有第四档一致）：左 = ①基本信息 ②题目 ③班级 ④时间与规则；右 = 实时摘要（N 题 · M 个班 · K 人 · 截止 · 模式）+ 就绪提示 + 立即布置/存为草稿 + 「上次布置 · 套用设置」。
- **题目多选 + 已选排序区**（序号 ↔ 接口 `sortOrder`），提供上移/下移/移除（拖拽的键盘替代）。
- **班级点选保留**，补「N 人」与合计人数。
- **模式改两张卡片**：考试 / 练习，差异写在卡里；练习卡内标注「开启后不可切回」。`mode`/`allowResubmit`/`maxAttempts` 提交口径不变。
- **时间给快捷预设**（默认「今天 18:00 ~ 一周后 23:59」）。
- **字段级校验 + 主按钮禁用 + 摘要卡列缺项**，替代 toast「请填写完整」。
- **≤768 手机端**：全屏 sheet、单列、班级按钮 ≥44、底部常驻操作条（左摘要右主按钮）。
- 自评：现状 **58** → 提案 **88**。

## 交付方式（后端 0 改动）
改 `client/src/views/teacher/Assignments.vue` 一个文件：删 `step` 向导与 `a-steps`，模板换成分区表单 + 摘要栏；题目选择 `radio → checkbox` 并加已选排序；提交仍用现有 `questionIds` 数组。可选：localStorage 草稿 + 关闭前确认（现状 `destroyOnClose` 静默丢弃）。
验收：3 题 2 班一次布置成功（DB 里 `assignmentQuestions` 3 行、`sortOrder` 1/2/3）· 375 宽无横向溢出 · 键盘可完成全流程 · 浅深双主题 · 0 控制台报错。
