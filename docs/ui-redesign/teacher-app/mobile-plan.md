# 手机端适配计划（教师端优先）

> 依据已确认的 5 条决策 + 之前的平台策略（Android 优先）与交互设计（代码只读 / 批量四层）整理。
> 目标：**不动桌面端**，新增移动端；小屏自动切换，≥768 回退表格视图。

## 一、已确认的决策（不再讨论）

| # | 决策 | 对实现的约束 |
|---|---|---|
| 1 | 教师端**编辑标准答案暂时搁置**，但页面保留 | 该页改为「暂不支持在手机端编辑代码」说明页；不做接力编辑、不做本地编辑器 |
| 2 | **不新增批量接口**（批量能力取消） | 批量操作由前端**逐条提交**：并发 5 + 进度 + 成功/失败汇总 + 失败重试；不等后端 |
| 3 | **不做撤销机制** | 发布前用「影响范围摘要 + 二次确认」挡住误操作；文案明确「发布后不可撤销」 |
| 4 | **≥768 回退表格视图** | 平板/横屏用桌面式多列表格；手机上才是卡片 |
| 5 | 学生端单独设计 | 本计划只覆盖教师端；学生端另出稿与计划 |

## 二、范围

**做（阶段 1–4）**：教师端 /m 移动 Web（工作台、作业列表、作业详情、评分审核队列、布置作业、我的）、代码只读与 diff、批量逐条提交、小屏自动切换、PWA。
**不做**：手机端代码编辑、表单外的复杂配置（AI 配置/监控等管理员页）、学生端、iOS、推送。
**不动**：桌面端全部页面与路由（只新增，不改既有）。

| 阶段 | 内容 | 交付物 | 验收（可断言） | 依赖 | 人日 |

## 四、技术要点

**路由与切换**
- 新增 `/m/*` 路由区（独立 Layout），桌面 `/teacher/*`、`/student/*` 一行不改
- 判定：`matchMedia('(max-width: 767px)')` **且** `matchMedia('(pointer: coarse)')`
- **只在入口跳一次**，偏好写 `localStorage['ui:layout']`（auto/mobile/desktop），提供手动切换入口
- `/teacher/x` ⇄ `/m/x` 映射保留 query/hash；桌面访问 `/m/*` 显示「去桌面版」提示条

**组件与体积**
- Vant 4 **按需引入**，且只在 /m 路由 chunk（`defineAsyncComponent` + 路由懒加载）→ 桌面包不变大
- 卡片列表、SwipeCell（左滑）、PullRefresh、List（上拉加载）、ActionSheet、Toast 用小写组件封装，避免业务页各写一套

**表格回退（决策 4）**
- `useMobileLayout().isTablet = width>=768` → 同一路由渲染 `ReviewTable`（桌面式）或 `ReviewCards`
- 表格模式保留多列与批量勾选；手机模式卡片 + 多选

**批量（决策 2、3）**
- 多选 → 「审核通过 (N)」→ **影响范围摘要**（含 N 份中 <60 的 M 份）→ 二次确认
- 提交：**并发 5 逐条**调用既有单条接口；顶部进度 `正在发布 3/12`；结束后汇总 `成功 10 · 失败 2`，失败项可「重试这 2 份」
- **不提供撤销**；确认框文案明确「发布后学生立即可见，且不可撤销」
- 部分失败不阻塞成功项，结果按条记录（本地 Map）

**代码（决策 1）**
- 只读面板（行号 sticky、横滑、字号调节、长按选中 → 引用到评语/复制/搜索）
- 逐块折叠 diff + 「只看差异」开关
- 编辑入口 → **说明页**：「暂不支持在手机端编辑代码，请用电脑打开（可复制链接）」

**移动端硬指标**
- `viewport-fit=cover` + `env(safe-area-inset-*)`；高度用 `100dvh`
- 触控目标 ≥44×44；`touch-action: manipulation`（不禁缩放）
- 键盘弹起用 `visualViewport` 处理底部按钮遮挡
- 动效遵循 `prefers-reduced-motion`

## 六、测试与验收

- **双视口回归**（Playwright）：375 触摸 → 自动进 /m；1280 鼠标 → 不跳；手动切桌面版后刷新仍生效
- **真机**：Android Chrome + 微信内置浏览器各过一遍（开发期用 `vite --host` 局域网访问）
- **无障碍**：触控目标 ≥44px、焦点可见、颜色不是唯一标识、屏幕阅读器走一遍审核流程
- **性能**：首屏 < 2s（3G 模拟）、列表 200 条滚动不掉帧、代码面板 500 行不卡
- **失败路径**：断网、接口 401/403/500、批量部分失败

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 批量逐条提交部分失败 | 结果逐条反馈 + 失败重试；确认框显示影响范围 |
| 无撤销带来的误操作 | 二次确认 + 「分数 <60 建议复核」提示 + 可先看风险项 |
| Android 厂商杀后台（未来推送） | 上线推送时引导加白名单；当前不做推送规避 |
| WebView 版本碎片 | 只用成熟 CSS（dvh 有降级、容器查询不用） |
| Monaco 在移动端不可用 | 只读自研渲染（预着色 HTML），不加载 Monaco |
| 与桌面并行开发的冲突 | 只新增 /m 与 composable；桌面文件零改动；提交按目录隔离 |

## 八、待办与依赖

1. **产品**：确认「代码编辑说明页」是否需要「复制电脑端链接」按钮（默认加，成本≈0）
2. **后端**：本计划**不依赖后端改动**（批量改逐条、不做推送、不做 CORS）；若后续上架 iOS 再单独提 CORS
3. **运维**：PWA 的 `manifest.webmanifest` 与 `sw.js` 需要正确的 MIME 与不缓存策略（nginx 三行配置，届时提供）
4. **测试设备**：至少一台 Android 真机（Chrome + 微信浏览器各一）
