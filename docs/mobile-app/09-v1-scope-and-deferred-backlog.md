## 2. v1 范围（零后端）

### 2.1 范围口径

- **保留**：公共 6 屏 + 学生 11 屏 + 教师 14 屏 + 平台/状态 3 屏 = **34 屏**；核心闭环：学生登录→作业→作答/草稿/提交→回执→成绩（本人分数/反馈）；教师登录→工作台→作业→审核队列→审核详情→改分/评语/通过→按 ids 发布→批量逐条审核；题库/班级/学生/布置作业/我的。
- **降级**：成绩聚合、成绩构成、通用题 AI 分项、教师班均对比、作业均分、催交、打回、接力 token、批量含评语影响、题库使用次数、请求编号等（见 §4）。
- **后置（不算取消）**：管理端 3 屏（admin-home / admin-directory / admin-monitor）整体转入 v1.1+（其中 admin-monitor 的「系统监控」部分零后端，可在需要时先做简化版）。
- **不变**：完整 37 屏设计稿、Gallery、设计文档、SCREENS 契约全部保留；延期项在设计稿中仍是「未来状态」，只由实现开关控制是否出现。

### 2.2 v1 页面与功能清单（按组）

| 组 | 屏数 | v1 | 关键降级 |
|---|---|---|---|
| 公共与认证 | 6 | 全部实现 | 登录补多学校选择（前端状态，接口已有）；错误页不显示伪造 requestId |
| 学生端 | 11 | 全部实现 | 成绩页不显示均分/排名/等级分布；成绩详情不显示构成/班级均分/逐题分母；首页/我的不显示平均分/排名；编程题接力只保留「复制链接（需登录）」 |
| 教师端 | 14 | 全部实现 | 工作台 AI 待评文案；作业不显示均分/催交；审核队列不显示班均、队列卡不带 AI 分项；审核详情通用题无分项、无「打回」；批量只做逐条审核+按 ids 发布；题库不显示使用次数、题型仅前端过滤 |
| 管理端 | 3 | **后置** | 本阶段不注册 /m 管理端路由；桌面端继续承担 |
| 平台与状态 | 3 | 全部实现 | 无（安装/启动屏/四态） |

> 合计 **34 屏 v1** + **3 屏后置（未取消）**。37 屏设计稿和截图全部保留。

### 2.3 实现约束（必须写进代码评审清单）

1. **零后端改动**：不得修改 server/**、prisma/**、数据库迁移；移动端只新增/修改 client/** 与 docs/mobile-app/**。
2. **不调用未上线接口**：延期项不得 fetch 不存在的 URL；开关关闭时组件不渲染、不请求。CI/Playwright 断言无 404 请求。
3. **不伪造数据**：禁止用 mock 排名/均分/分项/在线人数填充 UI；没有数据就隐藏或显示「暂未开放」。
4. **默认关闭延期功能**：建议在 client 建一个 mobileFeatureFlags（见 §5），默认全部 false；只有 v1 需要的为 true。
5. **保留设计资产**：37 屏设计稿、SCREENS、08/09 文档不删除；延期项在文档/backlog 可追踪。
6. **桌面零回归**：/m 路由与组件不得影响桌面入口、路由、样式与构建产物（沿用 07 的 chunk 隔离与 verify 门禁）。

## 5. 建议的功能开关（实现用，不新增依赖）

在实现阶段建议加一个纯前端配置（名称可调整）：

~~~js
// client/src/features/mobileFeatures.js（M0 新增，示例）
export const mobileFeatures = {
  scoreAggregates: false,       // D1/D4
  scoreComposition: false,      // D2
  generalAiBreakdown: false,    // D3
  assignmentAverage: false,     // D5
  urgeAndNotification: false,   // D6
  rejectWorkflow: false,        // D7
  handoffToken: false,          // D8
  batchAtomicReview: false,     // D9
  assignmentEditDelete: false,  // D10
  questionUsage: false,         // D11
  adminArea: false,             // D12
  requestTraceId: false,        // D13
  multiSchoolLogin: true,       // D14（前端只有 UI 工作）
};
~~~

规则：
- 开关 false 时：组件不渲染、不发起请求、不出现空占位假数据；
- 开关 true 前：必须把 09/08 中对应「解除条件」逐条满足并更新本文件状态；
- 不为延期项预留**死 UI**（隐藏区块可以保留设计稿，但生产路由/组件不挂载）。
