# 错误状态码后端回复（后端答前端清单）

> 对应：`docs/api/2026-10-13-错误状态码后端配合清单.md`
> 回复方：后端会话（同仓库 master）。**所有结论均为线上实测或读码所得，行号/响应体附在下面。**

## 一、四个问题的答复（先给结论，再给证据）

### Q1 线上到底是谁在做 SPA fallback？——**是 nginx，不是 Express** ✅
- nginx 站点配置：`location /exam/ { try_files $uri $uri/ /exam/index.html; }`（`/etc/nginx/sites-enabled/exam:37-38`）。
- 线上实测（curl deadpan.asia）：
  | 路径 | 实测 | 说明 |
  |---|---|---|
  | `/exam/unknowndeep` | **200 text/html** + `<!doctype html>` | nginx fallback 送 index.html |
  | `/exam/assets/NOPE.js` | **404 text/html** | 命中 `location ~* ^/exam/assets/`（无 try_files）⇒ **P0-2 在 assets 上已经是 404** ✅ |
  | `/exam/favicon.ico` | 200 image/x-icon | 真实文件存在 |
  | `/foo`、`/wp-login.php`、`/teacherx` | **404 text/html** | 根级未知路径**本来就是 404** ✅（不匹配 `/exam/`） |
- **Express 侧的 fallback 在线上是死代码**：`server/src/app.js:108` 是 `if (process.env.NODE_ENV === 'production')`，而**云上 `NODE_ENV` 未设置**（`.env` 里没有、pm2 环境里也没有）⇒ 该块不执行；静态文件与 SPA 全由 nginx 直供 `/var/www/html/exam`。
- ⇒ **结论：P0-1（未知路径 404 + 短名单）与 P0-2（静态资源 404）必须改在 nginx**；Express 那 12 行改了也不会生效（除非将来改成 Express 直供前端）。

### Q2 生产是否用 nginx 反代？有没有 `proxy_intercept_errors` + `error_page`？——**是反代；两项目前都没有** ❌
- `location /exam/api/ { proxy_pass http://127.0.0.1:3002/api/; }`（`:14-24`）✅ 反代存在。
- 全站 `grep proxy_intercept_errors|error_page` ⇒ **0 处** ⇒ 后端重启/挂掉时用户看到的是 **nginx 默认 502**，不是我们的页面。
- ⇒ **建议采纳**：`proxy_intercept_errors on;` + `error_page 502 503 504 /exam/error-pages/502.html;`（等前端的 `client/public/error-pages/` 落地后由我做 nginx 侧改动）。

### Q3 上传超限现在返回什么？——**400 + 中文 message（应为 413）** ❌，且教师侧**没有**处理
- 学生提交：`server/src/controllers/studentController.js:624-626` ⇒ `res.status(400).json({code:1001, message:'文件过大（超过 50MB 上限）'})`（multer `fileSize: 50*1024*1024`，`:795`）。
- 教师上传：`server/src/infrastructure/teacher/uploads.js:27` 同样 50MB，但**未见 `LIMIT_FILE_SIZE` 分支** ⇒ 会落进 500 兜底 ❌（P1-4 一并修）。
- nginx 层：`client_max_body_size 60m` 只在 `location /exam/api/`（`:16`）⇒ **>60m 时 nginx 直接返回它自己的 413 HTML**（前端解析不到 message）⇒ 建议给 API 路径加 `error_page 413` 返回 JSON。
- ⇒ **采纳清单 4**：统一改为 **413 + `{code:1403, message:'文件超过大小限制', data:null}`**，学生与教师两条路径都改。

### Q4 是否接受「公开入口短名单」？——**接受，但要改三点** ⚠️
1. **落点在 nginx**（见 Q1），不是 Express；
2. **不要靠注释提醒**：把短名单**从 router 派生 + 加断言**——新增一级路由前缀而没同步名单时，核验脚本直接失败（比注释可靠）；
3. **短名单只决定"给不给你 SPA 外壳"**：SPA 内部的 404 页仍需要（未知的 `/exam/foo` 会被判定为合法 SPA 路由 ⇒ 200 外壳 + 前端 404 页）——若你们要"服务端就 404"，那 `/exam/*` 下所有非白名单路径都要 404，代价是**任何新前端路由都必须同步名单**（我建议：**前缀白名单 + 前端 404 页**，兼顾正确性与可维护性）。
   - 另外名单里应包含 `/exam/error-pages/`（静态错误页自身）与 `/exam/uploads/`（若确有直链需求，见下方"额外发现"）。

## 二、额外发现（不在清单里，但同属"边界一圈"）
1. **`/api/*` 已是 JSON 404 ✅，但经公网 `/exam/api/*` 却是 HTML 404 ❌**（实测：`/api/foo` ⇒ `{"code":404,...,"message":"Cannot..."}` JSON；`/exam/api/foo` ⇒ `<!DOCTYPE html>...Cannot GET /api/foo` HTML）。⇒ **P0-3 要按"公网路径"验证**，不能只测本机 `/api`。
2. `server/src/middleware/projectAssetGuard.js:35` 的 `{error:'forbidden'}` 与全站 `{code,message,data}` 不一致 ⇒ 采纳 P1-8（统一 body）。
3. 线上 `NODE_ENV` 未设置 ⇒ 除 fallback 外，任何依赖 `NODE_ENV === 'production'` 的行为在线上都**不生效**（建议要么显式设置，要么删掉该分支避免误判）。

## 三、后端确认要做的（本批）
- **P0-3**：`app.use('/api', 404 JSON)`（放在所有路由之后、错误中间件之前）+ **保证经 nginx 公网路径也是 JSON**（补 nginx 侧 `error_page 404` for `/exam/api/`）。
- **P1-4**：multer `LIMIT_FILE_SIZE` ⇒ **413 + code 1403**（学生 + 教师两条路径）。
- **P1-6**：错误中间件按 `req.accepts(['html','json'])` 分流：HTML ⇒ 送 `error-pages/500.html`（不存在时回落 JSON），其余 ⇒ 现有 JSON。
- **P1-8**：`projectAssetGuard` body 统一为 `{code:1003,message:'无权访问该资源',data:null}`。

## 四、nginx 侧由我做（等你们的 `error-pages/` 落地后一起上）
- P0-1：`location /exam/` 内按短名单 `try_files ... /exam/index.html`；**非白名单且非文件** ⇒ `404` + `/exam/error-pages/404.html`。
- P0-2：扩展"文件形态路径一律 404"（现在仅 `/exam/assets/` 生效）。
- Q2：`proxy_intercept_errors on` + `error_page 502 503 504`。
- Q3：API 路径的 `error_page 413` 返回 JSON。
- 短名单会与前端 router 的**一级前缀**对齐，并在核验脚本里加"名单覆盖所有一级前缀"的断言。
