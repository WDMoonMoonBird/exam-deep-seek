## 2. ★三处口径（C/后续轮次必须先读，否则会误判成缺陷）

### 2.1 国庆 2026 取 **7 天**（`2026-10-01 ~ 2026-10-07`）
- 依据与代价方向：**多登记一天 = 高峰照跑 = 白付一倍价钱；漏登记一天 = 多等一个窗口 = 不花钱**。
  ⇒ 拿不准时一律**取小**。官方口径待用户确认（A §5 R2 已登记）。
- 该取值同时**与 A 报告的两处口径自洽**：A1「`2026-10-08T01:30:00Z`（=北京 09:30）= 高峰」、
  A5「`2026-10-09` 09:00 = 高峰」都要求 **10-08 是工作日**（8 天版本会让 A1 得到 `false`）。
- 2026 春节区间（`02-15~02-22`）无论官方取 7 天还是 8 天，**落在工作日的放假日完全相同**（02-16~02-20），故无歧义。

### 2.2 `computeStartPlan().reason` 的取值语义（7 个枚举）
| reason | 何时出现 | canStartNow | startAt |
|---|---|---|---|
| `idle-now` | 普通工作日空闲（午休/夜间）且余量 > T | ✅ true | = now |
| `weekend` | 周六周日（**恒空闲，不识别调休**，§4.1.1 ③） | ✅ true | = now |
| `holiday` | 法定节假日（表内日期） | ✅ true | = now |
| `peak` | 工作日 9-12 / 14-18 高峰中 | ❌ false | = 下一个可启动窗口起点 |
| `too-close-to-window-end` | 空闲中但距窗口结束 **≤ T** | ❌ false | = 下一个可启动窗口起点 |
| `past-deadline` | 入参 `deadline`（**最晚启动时刻**）已过或 startAt 超过它 | ❌ false | **null** |
| `holiday-table-out-of-range` | 该年未收录（如 2027）且确实影响结论（工作日 + 高峰钟点） | ❌ false（保守） | = 下一个可启动窗口起点 |

- `startAt === null` 只有两种情形：`past-deadline`，或扫描上限（128 个窗口）内没有「整段时长 > T」的空闲窗口。
- **队首的 `past-deadline` 作业会被出队**（记 warn、释放去重位）：它永远等不到窗口，留在队首会堵死后面所有作业；这是调度器的活性要求，不是产品决策（真正的「过期作废」语义若要落库/通知，属 P2）。
- `expectedFinishAt`（= startAt + estimatedMs）**只用于显示**；`estimatedMs` **不参与准入判定**（准入只看 T，避免同一件事扣两次）。
- 逐日为「周末 / 放假日」时**全天无高峰区间**，因此空闲段是**连续段**：周五 18:00 起算的窗口结束于**周一 09:00**，
  国庆连休起算的窗口结束于**连休后第一个工作日 09:00**（`currentIdleWindow` 返回的是这个连续段，不是「当天 0-24 点」）。

### 2.3 节假日表超范围 = **显式降级 + 日志**，不是静默
`OUT_OF_RANGE_POLICY = 'peak'`（当前实现，保守）；策略本身**待用户拍板**（`'peak'` 保守多等 / `'idle'` 可能多花钱），
两种取值都会让 `holidayTableOutOfRange === true` + `notice` 非空，调度器**按日期键去重后打 warn 日志**，绝不静默。

## 5. 实现中修掉的 3 个真缺陷（自证记录）

| # | 缺陷 | 症状 | 修法 |
|---|---|---|---|
| 1 | **窗口推演方向搞反**（`peak-hours.js` 两处） | 10-09 08:30 距窗口结束 30min，应推到 12:00；实际 `startAt=2026-09-30 18:00`（**退到上一段空闲**，跨连休能退 8 天）。根因：用「往回找空闲段起点」的函数去算「越过高峰后的下一段空闲起点」 | 两处一律改为 `nextIdleStart(...)`（向前）；并在两处各留一行注释说明「★不得用 idleRunStartMs，那是往回找」 |
| 2 | **ENV 兜底依赖注入方实现**（`read-config.js`） | 注入的读取器返回空值时，`DSH_GRADING_*` / `FEATURE_IMMEDIATE_GRADE` **静默失效**（全落内置默认）。既有 `getConfig` 自带 `cfg[key] \|\| envFallback` 所以真实路径看不出来 | 兜底移到本层：读取器返回 `undefined/null/''` ⇒ 显式取 ENV；既有路径行为不变（幂等） |
| 3 | **队首死作业堵队列**（`grading-scheduler.js` 复读时发现，非探针报错） | 传了 `deadline` 的作业一旦过期，`computeStartPlan` 永远返回 `past-deadline`+`startAt=null`；原实现只记日志不出队 ⇒ 排在其后的作业**永远轮不到** | 迭代上限改为「队列长度 + 闸宽」，`past-deadline` 的队首**出队 + 释放去重位 + 继续试下一个**；新增探针（两个死作业 + 一个正常作业 ⇒ 正常作业照常启动） |
