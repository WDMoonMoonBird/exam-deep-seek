**F3（中 · 影响用户拍板）`OUT_OF_RANGE_POLICY='idle'` 的后果被文档低估（在当前实现下）。** 把常量翻成 `'idle'` 后（/tmp 副本实测）：`peakIntervalsOfDay` 对未收录年份直接返回 `[]` ⇒ `idleRunEndMs` 走退化分支 ⇒ **windowEnd = now + 60 天**（`2027-03-01 10:00 → end=2027-04-30 10:00`）。即 T 预留期**整体失效**，超范围年份**连真实高峰钟点也照开**（不是「只多花一点点」，而是整个未补表年份的费率保护被关闭）；另有 **823/4000 例**出现 `canStartNow=true` 与 `reason='holiday-table-out-of-range'` **并存**，与 B §2.2 的语义表（该 reason ⇒ canStartNow ❌ false）矛盾，教师端文案会误导。**拍板前应先修这两点**（或把 'idle' 明确标注为「不支持/未实现」）。

**F4（中 · A8 判据未完全满足）超时「状态记 failed」没有对外可见性。** 超时后 `tick()` 返回 `{started,queued,active,nextWakeAt}`、`status()` 返回 `{active,queued,nextStartAt,nextWakeAt,running,stopped}`，**均无失败作业字段**；结果只落在 error 日志与内部 `job.timedOut`（对象随后被丢弃）。闸释放 ✅、下一作业能起来 ✅、`abortJob` 1 次 ✅，但「状态」不可观测 ⇒ 教师端/DB 无法知道作业失败（P2 需要它）。建议：`status()` 增 `failed: [{projectId, at, reason}]` 或落 `grading.state`。

**F5（中 · P2 接线隐患）跨实例重复执行。** 实测：`inst1` 有作业在跑 → `inst1.stop()`（= `stopScheduler()` 语义，不打断）→ `inst2` 对**同 projectId** `enqueue` **accepted=true** 且真的跑起来 ⇒ `runs=["inst1:999","inst2:999"]`，**同一项目同时 2 个执行**，不变量②与闸=1 同时失效。P2 在 `stopScheduler()→startScheduler()`（含 PM2 reload）路径上必须先等运行中作业收敛，或把闸/去重集提到模块级共享。

**F6（低 · 与文档表述不符）「setTimeout 睡到窗口」实为封顶轮询。** `wake()` 把 delay 夹到 `≤ pollSeconds*1000`：实测高峰 10:00 入队（nextWakeAt=12:00，差 7200s）时 `setTimeoutFn` 收到的是 **60000ms** 而非 7200000ms（`定时器记录 = [1000,60000]`）。行为可接受（每 60s 醒一次重新判定），但 commit message/文档的说法不准确。

**F7（低 · 契约不一致）`timeoutMinutes` 的小数语义。** `read-config` 允许 `min=0.001`（`'2.5'` 合法 ⇒ 2.5 分钟），但调度器 `Math.max(1, v)*60000` 把 <1 分钟一律夹到 **1 分钟**：实测 `timeoutMinutes=0.5` 时 30s **不**超时、60s 才超时。二者取其一改齐（建议 read-config min 提到 1，或调度器不夹 1 分钟下限）。

**F8（低 · 文档不可复现）B §4 的命令逐字复算失败。** `cd server && node scripts/gates/arch-metrics.mjs` → `Error: Cannot find module '…/server/scripts/gates/arch-metrics.mjs'`（REAL-EXIT=1）；gates 在**仓库根** `scripts/gates/`（A10 写的 `node ../scripts/gates/cycle-check.mjs` 才对）。数字本身已复算无误，仅命令写法要改。

**F9（低 · 文档笔误）B §5 缺陷 1 的例子日期与数值不自洽**：写「10-09 08:30 … 实际 `startAt=2026-09-30 18:00`」，但 10-09 的向后值应为 `2026-10-08 18:00`；`09-30 18:00` 对应的是 **10-08 08:30**（C 实测两值均如此）。

**F10（低 · 注释引用错误）** `holidays-cn.js:18` 把 2025 年通知文号写成「国办发明电〔2024〕7 号」，实为**〔2024〕12号**（日期 2024-11-12 正确）。

**F11（观察 · FIFO 清理滞后）** 队首为 `too-close`（非过期）时按 FIFO 阻塞后续（实测 `queued` 不变、`nextWakeAt=18:00`）；且**过期作业只有到达队首才被清出**，长队列下清理滞后。语义自洽，但 P2 若关心「过期作业尽早作废」需要额外扫描或按 deadline 排序。

**F12（观察 · 计费近似）** 「按启动时刻的费率整段计费」是近似：跨 12:00/18:00 的运行中作业会产生混合计费（token 级计费），T 预留期是缓解而非消除；文档未写明该近似。

**F13（观察 · 测试网缺失）** `jest --testPathPatterns=scheduler` = **0 个文件**，B 的探针已不在 /tmp ⇒ 该模块当前**无任何自动化回归网**。按用户「测试代码不入库」约定，建议 P2 接线前把最小回归集固化（或明确接受无回归风险）。
