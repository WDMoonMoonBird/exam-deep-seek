## 1. 方法（自建样本，不复用对方脚本）

```text
/tmp/agentc-lint-verify/mini/                 ← 自建最小同构仓库根
  scripts/gates/lint-check.mjs                ← 仓库脚本逐字节副本（sha256 与仓库一致）
  package.json（{}）+ node_modules -> <repo>/client/node_modules
  client/src + server/src                     ← 我自己写的最小源码树
  docs/pipeline/lint-baseline.json            ← 由门禁自己的 --update-baseline 生成（迷你基线）
```

- 每个场景都是「重置树 → 写样本 → 生成迷你基线 → 施加变更 → 跑默认模式」，**退出码与完整输出原样留存**在 `/tmp/agentc-lint-verify/out/`、`out2/`。
- 被搬迁的缺陷与真实代码同形：`let count = 0;` 只写不读（声明与赋值都在、无读取），基线里就是一条 `no-unused-vars / count`。第一个场景实测确认：`server/src/controllers/reviewController.js:4 no-unused-vars count` 被精确检出。
- **样本副本一致性**：`27d563d6…`（repo）== `27d563d6…`（sample）。

### 5.2 我找到的「真违规漏过」构造 —— 1 个，且**已被改进方披露**

**攻击 S12（换位攻击）**：同一次运行里

1. 把原宿主的死变量**修掉**（`return { reviewedStudentIds, count };` —— `count` 被读取 ⇒ 该违规消失 = resolved 1）；
2. 在**另一个新文件**里**凭空新增**一处死变量，其声明行文本与基线指纹逐字相同（`let count = 0;` ⇒ fresh 1）。

实测：**exit 0**，报告写「已迁移 1 条：`reviewController.js:4 → services/newDup.js:4`」。

⇒ 一个**货真价实的新增缺陷**被记为「迁移」放行了。这正是改进报告 **§5.1 已披露的「固有等价类」**（也在 §3.9 复述）：在 `(rule, symbol, 规范化行文本)` 指纹下，「A 处被修掉」与「B 处新出现同指纹缺陷」不可区分。它**不是实现 bug**（实现严格按设计执行），也不需要猜测动机即可复现。

**它是否推翻本轮？** 不推翻，但**推翻了报告 §1 的绝对化表述**：原文写「对**真正新增的缺陷一点都不能放松**」——S12 证明存在一类真新增会被放行（改动前门禁因比对键含 file 会拦下它）。准确表述应是「**对无法与逐字搬迁区分的新增不放松；一旦可区分，一律阻断**」。记为 **D1（中，已披露的固有局限 + 口径过绝对）**。

### 5.3 我找到的**未披露**的口径放宽 —— 1 个（不足以漏放真新增，但违背「逐字搬迁」字面契约）

**攻击 S13（空白归一化跨越字符串字面量）**：

- 基线：`const UNUSED_MSG = 'hello  world';`（两个空格，死变量）；
- 变更：搬到新文件并**把字符串内容改成 `'hello world'`**（一个空格，真实内容变化），删原文件。

实测：**exit 0**，「已迁移 1 条 ｜ `const UNUSED_MSG = 'hello world';`」。原因：`normalizeSourceText` 用 `/\s+/g` 折叠**一切**空白，**包括字符串/模板字面量内部**。

- 影响评估：这条仍属**同一处缺陷换宿主**（死变量本身没变，变的是同一行里的消息文本），所以**不构成新的假阴性类别**；但它证明负向清单第 3 条「**改了代码再搬**（… `count = 0` → `count = 1` …）⇒ 规范化后不同 ⇒ 不配对」**过度概括** —— 行内**空白序列**的改动（含字面量内部）**不会**破坏配对。
- 记为 **D2（低）**：建议要么在文档里把口径写全（「同一行内任意空白序列的差异视为相同，含字面量内部」），要么把折叠限制在字面量之外（更严，且仍满足他们想支持的「缩进/排版变化不影响」）。
