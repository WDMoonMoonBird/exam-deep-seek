## 10 方法论沉淀（可复用）

1. **通用规范缺"项目约束"层**：规范只写角色与循环，不写度量口径 / 不改清单 / 冻结基线 → 必须先补，否则第一轮就产假结论。
2. **"销毁会话"映射为"每轮起独立 subagent"**；跨轮唯一记忆 = 一个 ≤30 行的状态文件。
3. **平台不会自己无限循环**：必须有显式驱动机制（本项目用定时提醒），且提醒要**可自终止**。
4. **变异测试是"测试有牙"的唯一证明**：禁用被测守卫，看测试是否精确变红。
5. **"谁能改"之外还要问"能改成什么"**：C6-1 就是前者修好了、后者漏了才被绕过。
6. **部分替身会放大安全改造的破坏面**；判定标准 = 断言改动后必须比改动前更强或等强。
7. **先冻结再测**；`git status` 对未跟踪目录没有证据力（必须用 mtime / 指纹）。
8. **命令链短路**：多段 `&&` 串联时前段失败会让后段静默不跑；判"全绿"前先数摘要条数。
