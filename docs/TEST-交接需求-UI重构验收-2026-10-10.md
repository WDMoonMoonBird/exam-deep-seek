## 6. 为什么要这些（背景，可跳过）

三条实测陷阱，任何一条都会让测试结论失真：

1. **5173 现在是旧 UI**：主 worktree 的 vite 占着 5173，而 `server/test/e2e/playwright.config.js` 的 `baseURL` 硬编码 5173、其 client `webServer` 又是 `reuseExistingServer: true` → 从 UI worktree 跑同一套 e2e 会**静默复用旧客户端**，产出假通过/假失败。
2. **UI worktree 无法独立起后端**：缺 `server/.env` 与 `server/node_modules`，而 e2e 必须从 `.env` 派生 `exam_system_test` 库。
3. **多个 UI 预览实例并存**：5174/5175 两份同分支实例，谁是"验收对象"无法判定；且两者都 `proxy → 3000`，会与测试后端互相干扰。
