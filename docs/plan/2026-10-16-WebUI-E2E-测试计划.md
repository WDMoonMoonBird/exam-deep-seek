## 1. 目标与非目标

### 目标

用**真实浏览器、真实鼠标点击**把 Deadpan 判题的 Web 界面走一遍，重点验证两条链路：

1. **界面功能与守卫**：登录与鉴权、路由守卫、学生作业与作答、教师建题与布置、评分审核、题库/班级/学生/团队管理、管理端。
2. **双班实训题实战闭环**：教师 `test_teacher` 在广西农业职业技术大学「测试 1 班」布置 Spring MVC 期末实践考试 → 40 名学生逐个登录、上传工程包并提交（**A、B、C 轮转均匀分布**）→ 考试截止后系统自动评分；「测试 2 班」以同样流程跑 **D、E、F**。

产出：机器可读结果 + Markdown/HTML 报告 + 双班评分对照表。

### 非目标

- 后端 API 契约、数据库断言、并发与性能压测。
- **清理/回滚**：测试写入的生产数据不自动删除，由人工处置。
- Chrome 69 / legacy 构建分支（另有专项）。
- 移动端 H5（本计划视口固定桌面 1440×900；仅 TC-REV-07 临时切 900×900 观察窄屏抽屉分支）。
- **AI 给分是否正确**：只验证页面呈现是否合理，不对「AI 分数是否符合参考答案」下结论。

## 2. 铁律与合规设计

| 铁律 | 落地手段 | 证据 |
|---|---|---|
| **驱动真实浏览器** | Playwright Chromium，headless，视口 1440×900（= 代码设计宽度），`zh-CN` / `Asia/Shanghai` | 每条用例的执行 trace + 截图；失败附加失败态截图 |
| **禁止调用后端接口** | ①动作词表**封闭白名单**（18 个动作，含 `use` 宏调用），不含任何 api/request 类型；②执行器硬禁 `page.request`、`APIRequestContext`、`page.route`、`route/mock`；③出现未登记动作 ⇒ fail-closed 判 BLOCKED | ①JSON 的 `actionVocabulary`；②执行器源码逐行审查；③白名单校验报告（**0 个越界动作**） |
| **只操作 DOM** | 定位只走 `role / label / placeholder / text / id / css`；不注入业务脚本、不打补丁 | 每个 `target` 都是可读的语义定位子；无 `addInitScript` |
| **不修改任何代码** | 执行器、夹具、产物**全部放在仓库之外**（`~/.workbuddy/workspace/e2e-exam-ui/`）；仓库内只新增本计划与动作 JSON 两个文档 | `git status` 复核 |
| **只出报告** | 产出 `test-results.json` + `test-report.md` + `test-report.html` | 不做修复、不提 PR、不建分支 |

> 边界说明：被测页面**自身**会向后端发请求（这是被验证的行为，必须发生）。约束的是**测试代码**——测试不直连 API、不构造请求、不绕过 UI 造数。上传走页面自带的 `input[type=file]`，属浏览器 DOM 行为。

由于这两场作业的截止时间在 4 天后、且作业管理列表的操作列只有「锁定/解锁」（未发现改期入口），要在本次跑完可验证的闭环，采用**新建两份短窗口作业 + 40 人全量提交**的路径（见 8.2）。

```

actionVocabulary   动作白名单 + 断言枚举 + 定位子规范 + 禁用清单
macros             login / logout 复用宏
cases              69 条用例，每条 = id / group / priority / steps[]
executionPolicy    执行顺序、隔离、命名归一化、超时、重试
gates              启动闸门、停止条件、费用警示
```

### 6.2 动作词表（封闭白名单）

`goto` `reload` `click` `fill` `clear` `press` `pickOption` `toggle` `hover` `scrollIntoView` `typeInEditor` `uploadFile` `poll` `waitFor` `expect` `screenshot` `annotate` `use`

**没有**任何 api / request / fetch 类型动作。其中：

- `use` —— 调用 `macros` 里的复用宏（`login` / `logout`）。**v1.2 漏登记**：宏在 69 条用例里共出现 60 次，按「未登记动作 ⇒ fail-closed 判 BLOCKED」的规则会让整份计划直接跑不起来，v1.3 已补入白名单。

- `uploadFile` —— 先 `click` 页面可见的上传圆按钮（`.kind-add-btn`），再向**页面自带的** `input[type=file][accept=".zip"]` 注入本地文件路径。原生文件选择器 Playwright 驱动不了，必须走这个 input；但它就是页面自己的 DOM 元素。
- `poll` —— 定时轮询 DOM 文本（如 `待评分 → 已评分`）。**禁止**用 `waitForResponse` 代替。
- `typeInEditor` —— Monaco 输入，click 聚焦 + 键盘输入，不调用 `setValue` API。

### 6.3 断言枚举

`visible` `hidden` `text` `containsText` `notContainsText` `value` `url` `urlContains` `count` `enabled` `disabled` `attr` `checked` `hasClass` `pageTextNotContains`

### 6.4 定位约定

本项目源码 **0 处 `data-testid`**，且不允许为此改代码，因此定位优先级为：

`role` → `label` → `placeholder` → `text` → `id` → `css`（仅无语义锚点时兜底）

**命名归一化（已实测的坑）**：ant-design-vue 的 `autoInsertSpaceInButton` 会给**恰好 2 个中文字**的按钮中间插空格：

```
getByRole('button', { name: '登录'  })  →  0   ✗
getByRole('button', { name: '登 录' })  →  1   ✓

DOM: <button class="ant-btn ant-btn-primary"><span>登 录</span></button>
```

执行器对 `role ∈ {button, link, menuitem, tab, radio}` 且 name 恰为 2 个 CJK 字符的定位子，**自动**按忽略内部空白匹配（全局规则，非逐条标注）。

受影响：登录 / 保存 / 取消 / 删除 / 审核 / 重置 / 刷新 / 编辑 / 返回 / 关闭 / 锁定 / 展开 / 收起。
不受影响（≥3 字）：布置作业 / 新增题目 / 立即布置 / 保存审核 / 发布成绩 / 提交全部 / 提交答案 / 重新评分 / 清空筛选 / 保存描述 / 保存评分标准。

**其他定位注意**：

- antd 把 `aria-label` 落到外层 `div` 而非 `role=combobox` 的 input ⇒ 下拉用 label 关联或 placeholder 定位。
- `StatusTag` / 表格单元格 / 空态文案 / toast 无 role ⇒ 用 `text` 定位。
- 语义锚点质量总体很好：大量 `role=alert/status/note`、`aria-label="评分面板"`、视觉隐藏 `label for=...`、静态 id（`assign-title`、`tch-students-class-filter`、`review-class-filter`）。
- 唯一无语义锚点：审核页**改分输入框**（无 label/placeholder/id）⇒ 只能 `.wb-final-score` 兜底。

- **antd 下拉一律点容器**：`#id` 落在外层 div，`#id .ant-select-selector` 才是可点区域（`pickOption` 的 trigger 均照此写法）。
- **严格模式**：同一 target 命中多个元素时，未给 `nth` 则取第一个并记 warning；弹窗按钮与侧栏菜单同名（如「新增班级」「退出登录」）必须用 `.ant-modal-footer`/`.ant-modal` 收窄或显式 `nth`。
- **草稿串味**：布置作业草稿在 `localStorage[assign-draft-v1]`；断言「还差：」形态的用例（G5）必须用全新 context 或先清 localStorage。

### 8.3 素材均匀分布

```
测试 1 班：学生序号 i（0-based，按学生管理页列表顺序）→ [A, B, C][i % 3]
测试 2 班：学生序号 i                                  → [D, E, F][i % 3]
```

两班各 40 人 ⇒ `A`/`B` 各出现 13 次、`C` 出现 14 次（`D`/`E` 各 13 次、`F` 14 次），分布均匀且可复现。两班人数不等时各自独立轮转，无歧义。

### 8.4 截止时间

控件是 `a-range-picker` + `show-time`，**可精确输入到秒**（格式 `YYYY-MM-DD HH:mm:ss`），截止完全可控。不使用快捷项「今天 18:00 ~ 一周后 23:59」——当前时刻 18:00 已成过去，而「一周后截止」太久。

窗口由人数推算：

```
窗口 = max(10 分钟, ceil(N / 8) × 90 秒 + 120 秒)    封顶 25 分钟
开始 = 布置成功时刻 + 60 秒
截止 = 开始 + 窗口
```

| N | 窗口 |
|---|---|
| **≤ 40（本次实况：两班各 40 人）** | **10 分钟** |
| 56 | 约 12 分钟 |
| 80 | 约 17 分钟 |
| ≥ 96 | 封顶 25 分钟 |

**举例**：19:40 布置成功 → 开始 `19:41:00`，截止 `19:51:00`。

### 8.5 评分触发时机（v1.4 按云端实测更正）

**先说结论**：提交**不会**自动出分；**也不存在**「等到某个时间点（峰谷/截止）再评分」的调度器。评分是否开始，取决于云端评分链路（worker / 装置 / 判据）是否就绪。

#### 实测证据（2026-10-16，只读浏览，未点审核/未改分/未提交）

| 作业 | 班级 | 进度 | 截止 | AI 状态 | 审核状态 |
|---|---|---|---|---|---|
| 【实验2·测试1班 A/B/C】期末实践考试 | 测试 1 班 | 40/40 | 2026-10-20 23:59 | **待评分 40 人** | 待审核 0 人 |
| 【实验2·测试2班 D/E/F】期末实践考试 | 测试 2 班 | 40/40 | 2026-10-20 23:59 | **待评分 40 人** | 待审核 0 人 |
| Python 测试 / C++测试 / 500 压力测试 | 远端500人测试班 | 2/500、1/500、500/500 | 2026-06 | 已评分 | 待审核 2 / 1 / 500 人 |

- 作业管理页 KPI：`AI 评分中：无异常`（＝此刻没有任何评分任务在跑）。
- 两场作业的提交发生在 **10-13**，距实测已 **3 天**，一份都没评 ⇒ **提交不触发评分**。
- 远端班那三场是 **2026-06** 的提交、状态「已评分」⇒ 评分能力本身存在，靠的是**作业级批改触发**（`POST /teacher/assignments/:id/grade`，`server/src/routes/teacher.js:76`），而非提交或截止事件。

#### 与代码/需求文档的差异（开跑前需二选一确认）

| 来源 | 说法 |
|---|---|
| 仓库代码 | `project-submit.js:167` 提交成功后调 `enqueueProjectGrade`（`projectGrading.js` 铁律 R5） |
| 需求文档 | `docs/PRD-实训题流程定义.md` R5：「提交即触发评分……不依赖教师手动点击（手动触发保留为兜底能力）」 |
| **云端实测** | 80 份提交 3 天未评、无进行中任务 ⇒ 该路径在云端**未生效**（旧部署 / 评分 worker 未运行 / 判据未就绪） |
| 全仓检索 | `grep -rn "cron" server/src` = 0；无 deadline 调度器；**不存在**「峰谷/错峰/低峰排队」机制 |

#### 对执行的影响（本计划据此调整）

1. **开跑前先做 1 人探针**：1 名学生 + 1 份小包提交 → 观察 30 分钟。AI 状态若始终「待评分」，则评分类断言（`TC-CLD-05/06/09/10`）只能**记录现状并判 BLOCKED**，不能判 FAIL（缺的是前置条件，不是被测对象出错）。
2. **不要等截止**：截止只决定「还能不能交」。窗口仍设 10 分钟（够 40 人提交），但**收工条件是提交完成 + 状态观察记录**，不是「等评分跑完」。
3. **学生端看不到分数**另有独立原因（与评分是否跑完无关）：`server/src/domain/services/project-view.js` 的 `canStudentSeeScore(status)` 只在 `published` 放行，未发布一律 `score=null`。这条断言（`TC-CONS-02`）不受本更正影响，仍然有效。

> 更正留痕：v1.3 曾据代码写「提交即触发评分」，v1.4 按上述实测数据改回「提交不触发评分」，并删去原「截止前不得出分」的反向断言。

## 9. 执行方式与产物

```
① G0 定位校准（命中率须 ≥ 90%）→ locator-report.json
② G1→G9 只读与校验组
③ TC-CLD-00 → 现勘（含翻页取全量名单）→ cloud-fixtures.json
④ TC-CLD-01 → 02 → 03 → 04 → 05 → 06      （测试 1 班全流程）
⑤ TC-CLD-07 → 08 → 09 → 10                  （测试 2 班全流程）
⑥ 汇总报告
```

- 每 case 独立 browser context；三角色各登录一次可复用 storageState；**G10 每个学生必须独立 context**。
- 失败即截图 + trace；**重试 0 次**（即 `retries=0`，避免用重试掩盖 flaky 定位）。
- 超时：case 15 分钟，expect 8 秒，导航 30 秒，上传 180 秒，AI 评分轮询 50 分钟。
- 异步等待一律用 `poll` 轮询 DOM 文本，不用网络等待。

**产物**

| 文件 | 内容 |
|---|---|
| `test-results.json` | 机器可读结果（用例/步骤/断言/耗时） |
| `test-report.md` | 人读报告（失败归类 + 修复建议） |
| `test-report.html` | 单文件 HTML（失败截图 base64 内嵌） |
| `locator-report.json` | 定位子命中情况 |
| `cloud-fixtures.json` | 云端现勘结果 |
| 双班评分对照表 | 学生 → 素材 → AI 总分 → 分项 |

**启动闸门**：题库该实训题缺失、素材文件不可读、两个班在云端不存在、G0 校准命中率 < 90%、**用例所需夹具为空**（如无「已发布成绩」可绑）—— 任一命中即 BLOCKED 并回报，**不降级为假红、不静默跳过**。

**停止条件**：出现计划外的数据写入、页面 500 或 Prisma/SQL 内部文本上屏、学生端在未发布状态下看到分数或 AI 评语、出现「确认按开放性题目布置」软警告（说明标准包未生效）。
