## 2. Windows 是否需要额外改代码

**不需要。** 安全策略与下载放行逻辑是平台无关的同一份主进程代码；Windows 与 macOS 共用 `blob:http://127.0.0.1:47821/<uuid>` 形式的下载 URL。核对后 Windows 侧没有单独的下载分支/白名单，因此拉取即生效，未做平台分叉。

### 验证环境的一个坑（非产品问题）

本机是被 DSH 代理进程拉起的，默认 `%TEMP%` / 下载目录对子进程不可写：下载会立刻 `interrupted`（0 字节），把 `TMP/TEMP` 指到工作区、并给测试钩子指定工作区保存路径后即 `completed`。这是**代理沙箱**的限制，不是 Windows 用户环境的问题；正常双击安装包运行时 TEMP/下载目录可写，保存对话框会正常弹出。

因此「保存对话框 → 落盘」这一段需要在真实安装环境里做最后确认（见 §5）。

1. 安装/运行 `Deadpan-0.2.1-x64.exe`，登录后进入「评分审核」；

> 补充：测试中还观察到，给 `setSavePath` 传**含中文的长文件名**时下载会 `interrupted`，而 ASCII 文件名可完成。生产链路走系统保存对话框、由用户确认文件名，理论上不受影响；若真机仍失败，优先怀疑文件名/路径，可按日志里的 `item.getFilename()` 进一步处理。
