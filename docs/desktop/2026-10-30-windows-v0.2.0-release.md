## 构建环境

- Windows 11 26H2（10.0.26300）、200% 缩放
- Electron 44.10.0（`electronDist=node_modules/electron/dist`，未重新下载）
- electron-builder 26.18.0，NSIS
- 依赖经淘宝镜像 `registry.npmmirror.com` 安装；Electron 二进制经 `npmmirror.com/mirrors/electron/`
- 本机没有 `npm`（只有 pnpm），electron-builder 的 `npm list` 依赖收集需要一个 npm shim（`C:\Users\Public\dsh-tools\npm.cmd`，ASCII 路径），否则打包在 “searching for node modules” 阶段失败

## 构建命令（本机）

```powershell
cd desktop
$env:CSC_IDENTITY_AUTO_DISCOVERY = 'false'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
node node_modules/electron-builder/out/cli/cli.js --win nsis --x64
```

前置：`dist-desktop` 已生成（`node desktop/scripts/build-dist.mjs`），`desktop/node_modules/electron/dist` 存在。

## 服务端

- 默认 `serverUrl`：`https://deadpan.asia`（`config.mjs` 的 `DEFAULT_SERVER_URL`，首次启动生成 `%APPDATA%\Deadpan-Exam-Desktop\config.json`）。
- 实测：`POST https://deadpan.asia/api/auth/login` 返回真实后端 `400 {"code":400,"message":"usernameOrEmail must be a string"}`；壳内登录页提交错误口令返回「用户名或密码错误」，说明本地内容服务 → 反代 → 生产后端的链路通。
- 真实数据需要用户用自己的工号/学号登录；本机没有生产账号，未做登录后页面验收。

## 本次包的已知差异

1. **前端产物是“现代浏览器构建”**：为了绕开 legacy 插件 + terser 在本机的超长构建（约 11 分钟且第一次因 pnpm 严格依赖解析失败），本次用临时配置关闭了 legacy 与压缩后再打包。
   - 对 Electron 44 无影响（本身就是现代 Chromium，不需要 Chrome 69 兼容 chunk）；
   - 与 Web 端正式产物的差异：包体更大、无 legacy chunk/压缩；
   - 若要严格对齐 Web 产物，需要按标准 `vite.config.js` 重新构建（约 15 分钟）后重打 NSIS。
2. **未做 Windows 10 真机验收**：Win10 分支只通过 build 号注入验证了参数/CSS 路径；本次在 Win11 上完成窗口/亚克力/WCO/最大化验证。
3. **无代码签名**：内部试用可接受；正式分发建议采购证书并接入 electron-builder 的 Windows 签名配置。
