# 桌面端 v0.2.1 —— Excel 导出无响应修复（D25）

日期：2026-10-30
分支：`feat/desktop-shell`
产物：`Deadpan-0.2.1-arm64.dmg`

## 1. 现象

桌面端（v0.2.0）点击「导出 Excel」没有任何反应：没有保存对话框、`~/Downloads` 也没有文件。
浏览器里同样的操作正常。

## 2. 根因

前端导出用的是 SheetJS 的 `XLSX.writeFile(wb, filename)`，它在浏览器环境下的实现是
**造一个 Blob，再 `<a download>` 触发**，下载项 URL 形如：

```
blob:http://127.0.0.1:47821/<uuid>
```

而桌面壳的安全策略 `evaluateDownload` 只认 http(s)：

```js
const url = parseHttpUrl(rawUrl);
if (!url) return { allow: false, reason: '非 http(s) 下载地址' };   // ← blob 在这里被拒
```

被拒后 `will-download` 里直接 `event.preventDefault()`，Chromium 不会弹保存对话框、
也不报错 —— 表现就是「点了没反应」。受影响的三个入口：

- `client/src/infrastructure/export.js`（评分审核导出 xlsx）
- `client/src/views/teacher/Students.vue`（学生导入模板）
- `client/src/composables/admin/gradingRuns/useGradingRunsDetail.js`（评分日志下载）

## 3. 修复

`desktop/src/main/security-policy.mjs`：`evaluateDownload` 增加 blob 分支，
**只放行「内层 origin === 本地内容服务 origin」的 blob**：

```
blob:http://127.0.0.1:47821/<uuid>   → allow（本站页面生成）
blob:https://evil.example.com/<uuid> → deny
blob:null/<uuid>                     → deny（opaque origin）
data:...                             → deny（不放开）
```

blob URL 的 origin 前缀由浏览器在创建时写入，页面无法伪造，因此这个判断等价于
「下载由本站页面发起」，安全边界不变。

`desktop/src/main/security.mjs`：放行时输出 `[download] 放行（原因）：URL`，
并在 `done` 事件里记录 `completed/failed`，以后再出「点了没反应」可直接看日志定位。

`redactUrl` 同步支持 blob（日志里显示为 `blob:<origin>`，不泄露 uuid）。

## 4. 验证

**单测**（`desktop/test/security-policy.test.mjs`、`security.test.mjs`）：18/18 通过，新增 3 条：

- `evaluateDownload`：本站 blob allow / 站外 blob deny / opaque blob deny / data: deny
- `will-download`：本站 blob 不 preventDefault 且留痕；站外 blob 拦截并留痕
- `redactUrl`：blob URL 脱敏成 `blob:<origin>`

**真 Electron 端到端**（独立脚本，起一个 http 页面 → 触发 blob 下载 → 走真实 session 策略）：

```
INFO [download] 放行（本站页面生成的 blob 下载）：blob:http://127.0.0.1:47899
INFO [download] completed：e2e.bin
DONE completed exists=true body=hello-blob-download
RESULT OK
```
